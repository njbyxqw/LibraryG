# 元素牌开发任务

> 跨 TileScape / TileMatch 的持续任务主档案。这里记录新元素的需求、共同机制、设计取舍、实现对位和验证；Daily 只保存当日摘要与本任务入口。

## 初步需求背景

需要让策划快速搭建局内实验，验证新 Tile / 障碍牌 / Effect 的逻辑与表现。当前不另建实验运行时：在实验分支中使用现有关卡编辑器自由摆放元素，复用真实 TileV2 棋盘、选中、消除、ECA 与局内 View，以 `Trial` 试跑。

TileScape 是当前实现和运行时验证目标；TileMatch 用于查找历史元素机制、编辑器能力、火箭牌 / 连胜闪电球和局内道具的设计基线。历史实现不能直接迁用，每次落地前必须与当前 TileScape 代码对位。

## 任务定位

- 目标：形成新元素“可设计、可配置、可摆放、可试跑、可验证”的最小开发闭环。
- 范围：Tile / Effect 载体选择、ECA 复用或最小扩展、逻辑和 View 接入、资源配置、关卡编辑器数据表达、Trial 验证。
- 当前实验分支：`level_trial`。
- 不在本次范围：复制 TileV2 主链路或新建独立实验环境；预先建设通用试跑调试功能；未被具体元素触发的发布、DLC/网络、回放/重连、DDA 改造。
- 当前状态：已完成初步路线和资料路由；等待第一个元素需求。

## 每个元素的需求卡

| 维度 | 需明确内容 |
| --- | --- |
| 载体 | 独立 Tile / 障碍牌，还是挂载于普通牌 / 棋盘的 Effect |
| 编辑器数据 | 坐标、层级、朝向、尺寸、Pile、序列、专有参数与 ECA 绑定 |
| 初始状态 | 可点性、遮挡/显示、耐久或次数、关联对象、随机性 |
| 触发 | 点击、匹配、受击、显露、回合 / 事件，或已有 ECA Event |
| 逻辑结果 | 修改的棋盘状态；对 Bar、OverBar、可见性、目标或胜负的影响 |
| 表现 | View、动画、粒子、音效、输入锁定及完成时机 |
| 验证 | 编辑器摆放 / 参数、Trial 触发、局内表现、正式局外副作用隔离 |

## 当前实现基础（TileScape，静态确认）

- 编辑器：`Assets/Game/TileV2/Editor/LevelEditor/`，已有 Tile / Effect 选择、棋盘摆放、图层、参数面板、Undo/Redo 和校验。
- Trial 入口：`Editor/LevelEditor/Script/Views/TestControlView/TestControlView.cs` 创建 `GameMode.Trial` 的 `CustomData`。
- Trial 宿主：`EditorTrialLauncher.cs` 与 `EditorTrialController.cs`；运行真实 `TileMatchGame`、`TileMatchGameLogic`、`TileMatchLevelLogic`、`TileMatchApplication` 与局内 View。
- 局外隔离：`EditorTrialGameUIService.cs` 将奖励、购买、广告、埋点等非局内服务转为默认值、无操作或返回编辑器。
- ECA：配置在 `Scripts/Config/Behaviours/`，运行时 Event / Condition / Action 在 `Scripts/GameCore/Logic/GameLogic/Behaviours/`。

## 推进顺序

1. 收到具体元素需求后，填写“每个元素的需求卡”，选择当前最相近的 Tile / Effect 模板。
2. 对位 TileMatch 历史参考与 TileScape 当前配置、ECA、实体逻辑、View、资源和编辑器参数路径，写清可复用与不可迁用项。
3. 确认编辑器能表达所需数据；只为真实缺口补最小编辑器能力。
4. 在实验分支实现并通过 Trial 验证局内完整链路。
5. 决定是否进入正式开发范围；届时单独评估发布、回放/重连、DDA、资源投递和兼容性。

### 2026-09-04 — 磁铁牌（Magnet）初步实现

- 需求（已更正）：点击磁铁牌 → 点击牌随即进入手牌区（Bar），并随即触发一次磁铁效果，把另外 2 张磁铁牌吸至 Bar，3 张随即匹配消除（`BarChanged → BarMatch`）；每关可配置组数。
  - 注：原描述中"被点牌飞往弃牌区（OverBar）"为笔误；"随机触发一次"为笔误，应为"随即触发一次"。
- 关联设计稿：`[[03-KNOWLEDGE/Game-Logic/设计-磁铁牌元素-v1|设计-磁铁牌元素-v1]]`（已同步更正）。
- 分支：`level_trial`。
- 改动清单（TileScape）：

| 模块 | 文件 | 改动 |
| --- | --- | --- |
| TileType | `TileType.cs` | 新增 `Magnet = 5210`（Blocker 段） |
| 可点性 | `TileInteractable.cs` | `InteractableBlocker` 加入 `TileType.Magnet` |
| ECA Action | `ActionType.cs` | 新增 `MagnetPull` |
| ECA Action | `ActionConfig.cs` | 新增 `MagnetPullActionConfig`（无参数） |
| ECA Action | `MagnetPullAction.cs`（新增） | 点牌 + 其余磁铁牌吸至 Bar，复用 `AddTilesToBar/MultiTilesAdd` 视图流程 |
| 配置 | `Magnet.json`（新增） | `TileType 5210 / Blocker / MatchCount 3 / Life{0:1}`；`TileClicked→MagnetPull`、`BarChanged→BarMatch`、`TileDestroyed→DestroyTile` |
| Level | `LevelConfig.cs` | 新增 `MagnetGroupCount` + `SetMagnetGroupCount` |
| Level | `LevelMagnetTilesInit.cs`（新增） | 按关卡组数改牌（仿 Rocket/Gold 模板） |
| 接入 | `Board.cs` | 初始化流程在 rocket 之后接入 `ModifyTilesToMagnet` |

- 关键技术取舍：
  - **一个动作复用整条链路**：`MagnetPull` 移除牌 → `Bar.AddTile(ignoreFull:true)` → enqueue `ActionResult(AddTilesToBar, SourceType=MultiTilesAdd)`；让既有 `MultiTilesAdd` 视图控制器播放多牌入栏动画并广播 `BarChanged`，从而触发 `BarMatch`，避免新写专用视图控制器。
  - **初步版不区分"同组"**：仅按"棋盘/OverBar 上的其余磁铁牌"吸入（上限 3 张），组绑定延后。
  - **Trial 默认 1 组**：`LevelMagnetTilesInit` 在 Trial 且 `MagnetGroupCount ≤ 0` 时默认 1 组，方便直接验证。
- 编译修复（同日）：`MagnetPullAction.cs` 缺少 `using Game.TileV2.Scripts.GameCore.Logic.GameLogic.Behaviours.Event;`，导致 `EventData` 未解析（CS0246），并级联触发 `IAction.Execute` 未实现（CS0535 ×2）。补上 using 后两处错误均消除。
- 验证边界：纯静态实现与本地编译确认；Unity 实机 Trial 试跑、行为对齐、组绑定细化、OverBar 语义、随机范围回放/DDA、道具交互表、LevelEditor 配置 UI 均延后到下一轮。
- 下一步：Trial 试跑磁铁牌局内表现；按"需求卡"维度回填"载体/触发/逻辑结果/表现"四列；决定是否进入组绑定细改。

### 2026-09-07 — 磁铁牌接入编辑器右侧障碍栏（直接放置）

- 决策：在「关卡配置加磁铁组数字段」与「放障碍栏直接放置」之间，用户选择后者。
- 语义区别：障碍栏直接放置 = 固定位置、无「组」绑定；设计稿「每关可配置组数」对应的是 `MagnetGroupCount` + `LevelMagnetTilesInit`（开局随机改牌），本次未走该路径。
- 改动（TileScape，5 份文件，三份配置必须同步否则导表回退）：
  - `Editor/LevelEditor/Res/ExcelConfig/LevelEditorConfig.xlsx`：EffectTypeConfig 表新增 Id=3201 / BlockType=5210 / Type=1 / Name=磁铁；TileSelectionGroupConfig 表 Element 组 GroupTypes 末尾追加 `,3201`。
  - `Editor/LevelEditor/Res/Config/LevelEditorConfig/effecttypeconfig.json~` + `.bytes`：新增磁铁行。
  - `Editor/LevelEditor/Res/Config/LevelEditorConfig/tileselectiongroupconfig.json~` + `.bytes`：Element 组追加 3201。
- 配置链路：右侧障碍栏 `TileSelectionView` 全数据驱动，取数自 `BlockTypeData`（effecttypeconfig）与 `TileSelectionGroupData`（tileselectiongroupconfig）；`BlockType=5210` 经 `Enum.IsDefined` 转回 `TileType.Magnet`，点选后 `SetCurrentTileType` 放置。
- 关键坑（已解决）：运行时 `ConfigRuntimeConst.RuntimeFormat = ProtobufNet`，编辑器加载 `.bytes` 而非 `.json~`；用 Python 手写 protobuf-net 兼容编解码器做 decode→encode round-trip 校验后写入。字段取值 Id=3201（糖果瓶 3101 / 行李箱 3301 间空闲号）、BindTileType=-2、Version=1.9.1。
