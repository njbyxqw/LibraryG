## Rocket 火箭牌模块

### 核心机制

| 维度 | V1 (旧版) | V2 (重构版) |
|------|----------|------------|
| 生成策略 | `RocketNormalStrategy` (浅层优先) | `RocketDepthStrategy` (深度分桶 + 连胜调节) |
| Action | `PrepareAttackAction` | `PrepareChainedAttackAction` (预计算所有波次) |
| Lucky实现 | 独立牌型 `LuckyRocket` | 概率强化效果 (非独立牌型) |
| 连锁逻辑 | `ChainController` (运行时逐层) | 逻辑层一次性预计算 |
| 事件抑制 | 无 | `DirectTileDestroyedAttackNotSuppressed` Condition |

### 生成规则

**火箭组数计算**:
```
rocketGroupCount = 3 + max(0, (normalGroupCount - 25) / 5)
```

**深度分桶算法**:
- 前 30% → 浅层区 (优先分配)
- 30%-60% → 中层区
- > 60% → 深层区 (不主动分配)

**连胜动态调节**:

| 连胜次数 | 浅层组数 | 说明 |
|---------|---------|------|
| ≤ 2 | 2 组 | 正常分布 |
| > 2 | 1 组 | 降低浅层密度 |

### Lucky Rocket

Lucky **不是独立牌型**，而是匹配时的概率强化效果。

**概率映射表** (基于累计胜场):

| 累计胜场 | Lucky 概率 |
|---------|-----------|
| ≤ 10 | 0% |
| 11 | 15% |
| 12 | 30% |
| 13 | 50% |
| 14 | 70% |
| ≥ 15 | 100% |

**效果**: Lucky 成功 → 主波攻击 9 个目标 (6+3)，失败 → 6 个目标

### Chain Rocket

- 主波命中 ≥3 张火箭 → 触发链式波
- 最多 2 层链式 (MaxChainWave=2)
- 链式波优先选普通 Tile，不足时允许选 Rocket
- 链式命中 Rocket 时抑制邻居 Side Attack

## DDA (动态难度调整)

### 花色分配策略

**入口**: `InitLevelConfigTileType()`

| 策略 | 触发条件 | 说明 |
|------|---------|------|
| `ReconnectStrategy` | 录像回放/断线重连 | 直接恢复记录的花色 |
| `AssignTileTypeByDepthStrategy` | DDA V2 | 按可达深度排序分配 |
| `AssignTileTypeStrategy` | DDA V1 (默认) | 按难度步频打乱 |

### AssignTileTypeStrategy (默认策略)

1. 统计目标数量: `GetRandomTileCount() + GetSequenceRandomTileCount()`
2. 生成均匀分布的花色队列 `GetColors()`
3. 按难度步频打乱分配

### 障碍 Tile 生成

- 障碍 Tile 通过 `TileConfig` 配置生成
- 序列容器 (`SequenceSource`) 处理父子关系
- 批次绑定 (`ApplyBatchBindingStrategy`) 控制障碍出现时机

## 死局检测 (Deadlock)

### 判定函数

**文件**: `InevitableDeathJudge.cs` → `IsDeadlock(gameContext)`

**入口过滤**: `UnmatchedCount <= CurrentCapacity - 2` → 跳过判定

**判定逻辑**:
- 剩 ≥2 格: 藤蔓/双张并发消除检查
- 剩 ==1 格: 仅检查单张消除
- 剩 ==0 格: 直接返回 true (死局)

### 触发时机

`UpdateDeadlockState()` 在以下事件后触发:
- 点击牌加入手牌区后 (`AddingToToBarByClick`)
- 手牌区消除后 (`BarMatched`)
- 战前道具完成 (`LevelPrePropFinished`)
- 关卡失败/复活/洗牌/道具使用后

### 已知问题

1. **`remainingCapacity >= 2` 分支是死代码** — 入口条件保证 remainingCapacity 只能是 1 或 0
2. **两步/三步死局判定缺失** — 剩 2 格时完全不判
3. **缺 `deadlock_duration` 打点** — 无法分析玩家在死局压力下停留时长

## 关卡连胜与闪电球

### 核心概念

| 概念 | 说明 |
|------|------|
| 连胜计数 (WinStreak) | 连续通关关卡数，最大 4。胜则 +1，败则归零 |
| 闪电球 (Lighting Prop) | 根据连胜次数决定可消除牌组数 (1~4 组) |

### 数据存储

| 存储位置 | 说明 |
|---------|------|
| `LevelBaseData._LevelContinueWinTimes` | 总连胜次数 (始终累加) |
| `LevelBaseData._LevelWinStreakTimes` | 连胜活动连胜次数 (受功能解锁控制) |
| `DataBridge.WinStreakTimes` | 局内连胜次数 (闪电球使用此值) |

### 闪电球效果

- 选中牌面最多的花色
- 消除 3 张同花色牌
- 可消除组数 = 连胜次数 (1~4)

## 跑关机器人（LevelBot）

### 系统定位

Unity Editor 中以自动化方式模拟玩家跑关的关卡测试框架，供关卡策划测试难度、验证平衡性。

**运行环境**: Unity Editor / Batch Mode（非运行时）

### 核心架构

```
入口层: LevelBotCommandLine / LevelBotJenkins / LevelBotView
公共层: LevelBotCommon（加载场景、读取参数、创建 Runner）
核心引擎: BotRunner（关卡遍历 + 重复执行 + 动作决策 + 统计收集）
策略接口: ILevelBotActionStrategy / ILevelBotGameInstance / ILevelBotStatsCollector
决策引擎: BotNStepProbabilityBlockerEngine（共享引擎，在 GameLogic 层）
游戏实例: TileLevelBotGameInstance（接管 Tick、动画、DDA）
统计分析: TileLevelBotStatsCollector（CSV 持久化）
```

### 执行流程（三层循环）

| 层级 | 内容 | 说明 |
|------|------|------|
| 第一层 | 关卡遍历 | `for level in levelNames[]` |
| 第二层 | 重复执行 | 每关 `repeatTimesPerLevel` 次（默认 10） |
| 第三层 | 局内游戏循环 | `while steps < maxStepsPerRepeat`（默认 200） |

**游戏状态流转**:
```
Entered → Start → Playing ──→ Succeeded（通关）
                           └─→ Failed → Revive → Playing（循环）
                                    └─→ maxDeathCount → 跳过（OverHard）
                                    └─→ maxSteps → 跳过（Timeout）
```

### 动作决策策略（核心 AI）

**策略入口**: `NStepOptimumSolutionWithProbabilityBlocker` → `BotNStepProbabilityBlockerEngine`

**决策流程**:
1. 处理多步缓存（`TryHandlePreviousMultiStepDecision`）
2. 确定动态步长（`GetDynamicEvaluationStep`）
3. 阶段一：贪婪分层搜索（`GreedyLayerByLayerSearch`）
4. 阶段二：单步评估（`CollectSingleStepEvaluations`）

**动态步长**:

| 剩余容量 | 搜索步数 |
|---------|---------|
| ≥7 | 1 |
| 5-6 | 2 |
| 3-4 | 3（最佳规划窗口）|
| 2 | 2 |
| ≤1 | 1 |

**排序体系（5 个比较方法）**:

| 场景 | 第1优先 | 策略倾向 |
|------|---------|---------|
| 贪婪搜索 | HasMatch > TotalBlockerHPDelta | 通用 |
| 有消除 | CapacityChange > BarTypeChange | 释放空间优先 |
| 无消除+容量≤3 | **IsFirstActionInPile(true)** | 🔺 求生模式：暗牌优先抢空间 |
| 无消除+容量≥4 | **TotalBlockerHPDelta** | 🔺 求胜模式：优先打障碍揭布局 |
| 多步缓存替换 | 路由到上述方法 | 概率替换（p2Probability）|

### 参数配置（param.json 关键字段）

| 字段 | 说明 |
|------|------|
| `repeatTimesPerLevel` | 每关重复次数（默认 10）|
| `maxStepsPerRepeat` | 单次最大步数（默认 200）|
| `deathCountDisplayThreshold` | 过难阈值（默认 10）|
| `ddaVersion` | DDA 版本（V1/V2）|
| `randomStep` / `randomTimes` | 花色随机步长/次数 |

### 统计数据（三套 CSV）

| 文件 | 粒度 | 关键指标 |
|------|------|---------|
| `repeat_*.csv` | 每次重复 | Total, Succeeded, Failed, FT_0~FT_GT5 |
| `level_*.csv` | 每关汇总 | 通关率, 平均步数, 复活分布 |
| `error_*.csv` | 异常记录 | 超步, 超死亡, 异常错误 |

## Tile 打点

> TileMatch 打点体系基于 `Tile打点.xlsx`，共 13 个 Sheet，覆盖用户属性、投放事件、公共参数、各功能模块打点。

### 事件体系总览

| Sheet | 内容 | 行数 |
|-------|------|------|
| 用户属性 | 用户维度属性（关卡进度、连胜、付费能力等）| 130 行 |
| 投放相关事件 | 启动、loading、商店、在线时长、付费等 | 116 行 |
| 用户ID体系 | account_id / distinct_id 配置 | 5 行 |
| 公共参数 | 全事件公共属性（level, diamond_count, gold_count 等）| 120 行 |
| 基础模块 | loading、启动游戏流程 | 70 行 |
| 基础功能 | ui_open, ui_close, unlock_illustration 等 | 106 行 |
| 广告 | ad_entrance, ad_play, ad_result 等 | 34 行 |
| 支付 | gift_show, gift_click, gold_pass_level 等 | 64 行 |
| 物品产销 | report_item, report_merge | 135 行 |
| 活动 | act_horse（5人赛马）等 | 43 行 |
| 活动（框架重构后）| 新活动框架打点 | 143 行 |
| 新手引导 | start_guide, end_guide, skip_dialog | 16 行 |
| 关卡 | lv_start, lv_end, lv_revive, add_moves_show 等 | 324 行 |

### 核心关卡打点事件

| 事件名 | 触发时机 | 关键属性 |
|----------|---------|---------|
| `lv_start` | 进入关卡 | `lv_id`, `level_type`, `level_enter_num`, `exp_hard`, `consecutivewin` |
| `lv_end` | 关卡结束 | `lv_id`, `result`（成功/失败）, `use_step`, `revive_count` |
| `lv_revive` | 关卡复活 | `revive_reason`（TileShow/GoldCollect/Power/Rocket/Archery）|
| `add_moves_show` | 复活弹窗展示 | `lv_id`, `level_type`, `card_left` |
| `booster_use` | 使用战前道具 | `booster_type`, `booster_from` |

### 公共参数（全事件附带）

| 属性名 | 含义 | 类型 |
|----------|------|------|
| `level` | 玩家当前最高关卡进度 | 数值 |
| `diamond_count` | 当前钻石存量 | 数值 |
| `gold_count` | 当前金币存量 | 数值 |
| `box_count` | 当前宝箱数量 | 数值 |
| `energyvalue` | 当前体力数量 | 数值 |
| `ul_stratification_id` | 用户基础分层 ID | 数值 |
| `system_language` | 用户当前语言 | 文本 |

### 已知打点问题

| 问题 | 说明 |
|------|------|
| 属性类型错误 | `land_count`, `energyvalue` 上报为 String，应为数值 |
| 上报时机缺失 | `booster` 字段在 `lv_start` 中有定义但实际未上报 |
| `deadlock_duration` 缺失 | 死局压力下停留时长无以分析（需新增打点）|

## Effect 牌系统

> Effect 是挂载在 Tile/Board 上的装饰层，不占格子，通过 ECA（Event-Condition-Action）引擎驱动行为。

### Effect 分类

| 分类 | Effect | 说明 |
|------|--------|------|
| 受击护盾 | Golden/Crate/Ice/Stone/Pig/Ice2x2/Cookie | 受击时扣 HP，HP 归零后消失 |
| 可见消除 | Cloud/GiftBox/Grass/Jelly | 消除时或条件满足时移除 |
| 点击交互 | Cirrus/Mystery | 需要玩家点击交互 |
| 状态切换 | Curtain | 状态切换机制 |
| 链接传递 | Chain | 伤害/效果在 Tile 间传递 |

### ECA 行为引擎

Effect 的行为通过 JSON 配置定义，由 ECA 引擎解析执行：
- **Event**: 触发时机（如 `OnTileDestroyed`）
- **Condition**: 触发条件（如 `HP > 0`）
- **Action**: 执行动作（如 `ReduceHP(1)`）
