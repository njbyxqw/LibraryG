# 底层框架总览（Betta 三包）

> TileScape 与 TileMatch 共用的底层能力层，由 **BettaInterface（契约）/ BettaSDK（能力实现）/ BettaFramework（UI 与通用运行时）** 三包构成。
> 三者是**同一批 GitLab 仓库的 submodule**，两项目只是挂载路径与检出 commit 不同；分册见 [[03-KNOWLEDGE/底层框架/BettaSDK/SDK总览|BettaSDK]]、[[03-KNOWLEDGE/底层框架/BettaFramework/框架总览|BettaFramework]]（已细化到核心机制）、[[03-KNOWLEDGE/底层框架/BettaInterface/契约总览|BettaInterface 契约]]（已细化到逐接口签名）。

## 一、适用范围与来源

| 项 | 说明 |

| 来源项目 | TileScape（`D:\TileScape`）、TileMatch（`D:\meatloaf_client01`） |
| 适用范围 | 两项目共用的底层能力层；不含任何玩法层代码（TileV2 / TileMatch 业务） |
| 验证状态 | 目录结构、依赖声明、启动链路为**源码静态扫描**；版本号与挂载路径为 **git 实测**（2026-09-18）；**未做运行时验证** |

> [!note] 版本基准（2026-09-18 定）
> 本文档**以 TileScape（TS）为基准**：接口签名、类职责、配置 schema 均取自 TS 工作区当前实际编译版本。
> TileMatch 侧检出 commit 与 TS 不一致，仅作跨项目参考，不作为本文档基准。详见第五节。

## 二、三包一览

| 包 | 定位 | 上游仓库 | 命名空间根 |
|---|---|---|---|
| **Betta.Interface** | 纯契约层，只定义接口，**不含任何实现** | `Sparkwoods/BettaInterface` | `Interface.*` |
| **BettaSDK** | 运行时基础能力实现：账号、支付、资源、广告、音频、触觉、第三方服务 | `PhantomFish/BettaFrameWork_Client/BettaSDK` | 全局 |
| **BettaFramework** | 通用运行时基础设施：UIManager、消息总线、本地化、场景状态、屏幕适配 | `PhantomFish/BettaFrameWork_Client/BettaFramework` | `Betta.Framework` |

三者关系一句话：**Interface 定标准 → SDK / Framework 提供实现 → 业务只面向接口消费**。

## 三、分层与依赖方向

```
Betta.Interface        （零依赖，auto referenced）
      ↑                         ↑
BettaSDK   ────────────  BettaFramework
（capability 实现）       （UI / 通用运行时）
      ↑                              ↑
   ────────────────────────────────────────
              Game.Interface  →  业务模块 / 玩法层
```

`BettaFramework.asmdef` 的 `references` 为 4 条 **GUID**，2026-09-18 实测已全部解析：

| 关系 | 声明位置（GUID） | 说明 |
|---|---|---|
| Interface ← SDK | `BettaSDK.asmdef` `references` 含 `Betta.Interface` | 硬引用 |
| Interface ← Framework | `BettaFramework.asmdef` 引 `Betta.Interface`（`1d4cfa00889414c7c88dcca6bdf2b416`） | 硬引用 |
| Framework ← SDK | `BettaFramework.asmdef` 引 `BettaSDK`（`f6687d67c0a238a448760fe7e664af13`）+ `package.json` 声明 `com.betta.unity.sdk` | **双声明** |
| Framework ← uGUI/TMP | `BettaFramework.asmdef` 引 `UnityEngine.UI`（`2bafac87e7f4b9b418d9448d219b01ab`）、`Unity.TextMeshPro`（`6055be8ebefd69e48b49212b09b47b2f`） | 硬引用 |
| 三包 → 业务 | `autoReferenced: true` | 业务程序集无需显式引用即可用 |

> [!note] 依赖判定修正（2026-09-18）
> 早前记录「Framework → SDK 仅 `package.json` 声明、asmdef 层看不到这条边」是**误判**。实测 asmdef 层明确引用了 `BettaSDK`（GUID `f6687d67...`），依赖图以上表为准。

**BettaSDK 的外部依赖**（asmdef `references` 节选）：`Unity.TextMeshPro`、`MaxSdk.Scripts`、`com.Tivadar.Best.HTTP`、`xasset` / `xasset.pad`、`HybridCLR.Runtime`、`ThinkingAnalytics`、`AIHelp`、`AppsFlyer`、`AppleAuth`、`Google.Play.{Core,Common,Games,Review}`、`GoogleSignin`、`StompyRobot.SRDebugger`、`Unity.SharpZipLib.Utils`、`Unity.Notifications.{iOS,Android}`、`Unity.Purchasing`、`Obfuz.Runtime`。

## 四、启动与生命周期链路

底层框架由**两个常驻 Prefab** 驱动，各自挂在启动场景：

| 入口 | 位置 | 职责 |
|---|---|---|
| `BettaSDKRoot.prefab` | SDK 包根 | SDK 能力初始化与每帧驱动 |
| `BettaFrameworkRoot.prefab` | Framework 包根 | 初始化本地化（Locale） |

**BettaSDKRoot 生命周期**

| 阶段 | 动作 |
|---|---|
| `Awake` | `DontDestroyOnLoad`；初始化核心工具与性能监控；挂 `ProfileLifecycleSaveBehaviour` 做暂停/退出落盘 |
| `Start` | 触发 `XAssetVersionManager.Initialize()`（热更资源版本检查） |
| `Update` | 驱动 `ProfileHub` / `PassportHub` / `UserHub` / `PerformanceMonitor` / `ResourceHub.AutoRecycleUpdate` |
| `OnApplicationPause` | 派发全局暂停/恢复事件 |
| `OnGameReady()` | 游戏可见可交互后统一上报重装、性能、运行时保护埋点 |

> `Hubs.Instance.Init()` 负责补齐广告、触觉等轻量能力的初始化。

**能力获取方式**（最重要的一条约定）

```csharp
// 业务侧：面向接口，不 new 具体类
implementManager.Get<IUIManager>()
implementManager.Get<IResourceSystem>()
implementManager.Get<IAdSystem>()
```

- 实现侧只在初始化阶段注册：`BettaFramework` 注册 UI 相关，`BettaSDK` 注册资源/登录/支付/广告/音频。
- 业务侧**不承担平台分支**，只消费接口。

## 五、跨项目现状（重点）

### 5.1 挂载路径不同

| 包 | TileScape 路径 | TileMatch 路径 |
|---|---|---|
| BettaSDK | `Packages/BettaSDK` | `client/Assets/BettaSDK` |
| BettaFramework | `Packages/BettaFramework` | `client/Assets/BettaFramework` |
| BettaInterface | `Packages/BettaInterface` | `client/Packages/BettaInterface` |

TS 三包全在 `Packages/` 下；MT 是 `Assets/` 与 `Packages/` 混挂。

### 5.2 分支策略不同

| 项目 | `.gitmodules` 分支声明 |
|---|---|
| TileScape | 显式声明：SDK / Framework → `dev_frame`，Interface → `dev` |
| TileMatch | **未声明分支**，跟随 submodule 默认检出 |

### 5.3 两项目版本对照（以 TS 为基准）

| 包 | 基准（TS） | TileMatch（参考） |
|---|---|---|
| BettaSDK | `10f609de` · 2026-08-07 · `v0.1.0-31` | `1d6f5667` · 2026-09-11 · `v0.1.0-35`（较新，参考） |
| BettaFramework | `7357350` · 2026-08-07 · `v0.1.0-81` | `548df6f` · 2026-08-18 · `v0.1.0-3`（不同演进线，参考） |
| BettaInterface | `7096cfd` · 2026-08-07 · `v0.1.0-78` | `0b034da` · 2026-07-10 · `v0.1.0-1`（较旧，参考） |

> 本文档及三份分册均以 **TS 列**为权威基准；MT 列仅作跨项目参考。MT 侧检出位置：SDK / Framework 属 `origin/mergetile/dev`，Interface 属 `origin/feat-item`，六处均为 detached HEAD。

### 5.4 TS 侧工作区与 HEAD 的关系（已定基准）

| 包 | 未提交改动文件数 | diff 规模 |
|---|---|---|
| BettaSDK | 10 | +85 / −335 |
| BettaFramework | 4 | +7 / −7 |
| BettaInterface | 14 | +70 / −226 |

抽样看改动性质是**回退到旧 API 命名**：`Dispose()` → `Release()`、`Unregister` → `UnRegister`、删除接口重载与 XML 注释。

> [!note] 基准决策（2026-09-18 定）
> 工作区内容（`Release` / `UnRegister` 等命名）是 TS **实际编译生效**的版本，本文档及三份分册均以此为基准。
> 与各自 HEAD 的旧命名差异**已确认不追回**：不做 `git submodule update` / `checkout` 切回 HEAD，避免 API 命名跳变引发上层编译错误。
> 若后续需要升级 submodule，须先以本文档为基线比对 API 变更，再决定是否同步。
