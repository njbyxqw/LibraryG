## 2026-07-14 — V2 对比框架搭建

### 架构设计
- 从 V1 替换工具派生，去掉候选匹配和替换逻辑
- 两组独立 6 维评分 → Level ID 匹配 → 逐关双列对比
- 数据流：`scoreDataset(ds)` → `map0/map1` → `levels[]` → `renderT()`
- 扩展性：`datasets[]` 数组，scoreDataset 循环调用，核心引擎天然支持 N 组

### 对比列设计
- Level / 质量分V1 / 质量分V2 / Δ / 流失→ / 难度→ / 变异→ / 改善指标
- 5 种排序：Δ绝对值 / 改善最大 / 质量分V1 / 质量分V2 / Level

### 标签体系重构
- 初版误删了基础/进阶标准面板（认为对比不需要标注）
- 讨论后恢复：需要 V1/V2 标签来判断"两个都烂即使改善也没意义"
- 标注列改为双版本显示：`V1:⚠流失 ⚠偏难 → V2:—`
- 分类从 Δ 驱动改标签驱动：
  - 已修复：V1 有标签 → V2 无
  - 改善未修复：V1 V2 均有标签
  - 新问题：V1 无标签 → V2 有
  - 全部正常：两边均无标签

### 对比指标逐项评估
- 流失率：最可靠，无歧义
- 难度/变异：阈值外两个都标，需看 Δ 辅助判断
- 人均消耗：方向反转——替换工具"低=问题"，对比里消耗↑是改善
- 复活转化：弱信号——转化低可能是关太简单不需要复活
- 失败剩余率(首次)：越小越好，改用首次失败剩余率列
- 变异系数 (CV=σ/μ) 而非方差，消除关卡难度差异

### Bug 修复
**renderT 挂死**
- 现象：点"加载并对比"一直⏳分析中
- 原因：`r0/r1` ReferenceError，summary 面板引了 map 回调内的局部变量
- 修复：改直接用数组 `.length`

**bs.forEach ReferenceError**
- 现象：同上的分析挂死
- 原因：`bs` 声明在 381 行但 372 行引用，var 提升后值为 undefined
- 修复：挪声明到使用前

**try/catch 兜底**
- 加 try/catch 包裹分析回调，出错弹 alert 显示具体错误而非静默挂死

## 2026-07-14 — V3 自定义指标 + 持久化

### 自定义对比指标
- 参考 V3 分析工具 dropdown 模式
- `scanColumns()` 上传后扫描 Excel 列名，过滤 `_r_` 前缀（解析内部副本）
- `autoDir()` 自动方向判断：含流失/变异/难度/死局/退出/剩余 → ↓越低越好

**下拉无反应**
- 现象：点下拉列名无反应
- 原因：`addCustom()` 里调了 `renderWeightConfig()`，该函数不存在，ReferenceError 静默
- 修复：去掉调用

**数据显示为 —**
- 现象：选中自定义列后表格显示 —（无数据）
- 原因：`getVal()` 从评分对象 `{lv, tu, va, ...}` 查找 `_cm_` 前缀 key，不存在
- 修复 1：改从 `datasets` 按 Level ID 查找 → 性能差（每行 O(n)）
- 修复 2：分析时把自定义列值嵌入 `level._cm0/_cm1`，渲染直接读

**恢复后下拉无效**
- 现象：刷新恢复后点添加列显示"所有指标已添加"
- 原因：`availCols` 未存入 localStorage
- 修复：`saveState` 加 `ac:availCols`

**按钮位置**
- 从权重面板移到筛选栏独立一行，宽按钮，下拉 `min-width:220px`

### localStorage 持久化
- `saveState()`：存 levels / weights / thresholds / customMetrics / availCols / filenames
- `restoreState()`：页面加载自动恢复，有数据直接渲染
- 性能优化：不存原始 datasets（57列×500行×2≈几MB），只存分析结果 ~50KB
- 清除缓存按钮：`localStorage.removeItem + location.reload()`

### 列宽优化
- `table-layout:fixed`
- Level 56px / 质量分 64px / Δ 40px / 标注 150px(可换行) / 其余自适应
- 对比指标 checkbox 独立一行

### CSV 导出修复
- 自定义列导出从 `datasets.find()` 改为读 `_cm0/_cm1`

## 关键决策

### 三工具不合并
V3 分析 → V1 替换 → V2 对比 是串行使用流程，语义不重叠。数据集含义不同（分析对象 vs 候选池 vs 对照版本），合并会导致 Tab 切换时状态混乱。

### 基础/进阶标准用途
对比工具中不用于筛选，仅用于给 V1/V2 打标签做定性参考。

## 2026-07-14 晚间 — 逻辑纠正

### 归一化：独立 → 统一
- 背景：A组1000关(老) vs B组1000关(新)，同关不同配置
- 问题：独立归一化导致数值变差但得分反升（如 Lv.65 流失 4.17→4.60，分 65→70）
- 修复：两组数据合并计算 min/max，再分别套公式
- 效果：Δ 反映绝对值变化，直觉一致

### Δ：绝对值 → 有符号
- `Math.abs(...)` → `r1.score - r0.score`
- 正=改善，负=恶化

### V1/V2 基准定义
- 上传区：`V1 基准版本` / `V2 对比版本`
- 表头：`V1(基准) vs V2(对比)`
- Δ=V2-V1

### 行色：标签×Δ 综合
- 标签清零+Δ≥0 → 绿行（真改善）
- 标签清零+Δ<0 → 无色（标签好了但分值降了）
- V2 新增标签 → 红行
- 无标签+Δ<0 → 红行（需关注）

### 权重 UI 恢复
- 数组已存但 DOM 滑块未刷新 → `renW()` 调用补上

### 排序标签
- "按 Δ 绝对值降序" → "按 Δ 降序(改善→恶化)"

## 2026-07-16 — V4 双因子评分重构

### 背景与动机

前夜（07-14）完成了对比工具 V3 的逻辑纠正（统一归一化、Δ 有符号、行色综合判定）。但次日实测发现核心问题：
- **Lv.130 流失 0.00→0.15，仅涨 0.15pp，质量分却降 40 分**
- 根因：归一化是"排名逻辑"——0.00 在分布底端得满分，0.15 排在 P25 附近，排名差被放大
- 用户判断偏好：0→0.15 是数据波动，不扣；1→2 才是问题。需要看 Δ 绝对值而非排名

### 策略探索过程

1. **纯 P5/P95 + Log 变换**（初始方案）→ 废弃
   - 假设流失/剩余率严重右偏，用 Log 压缩右尾
   - 问题：Log(0.0001)=-4 人为制造虚假满分，0→0.15 被放大 3.2 个数量级
2. **纯分桶法** → 部分合理，但丢失连续分布信息
3. **双因子：基础分×60% + Δ分×40%** → 方向正确，但初始实现把两个 Δ 混在一起
   - 第一版错误：Δ 列 = baseDelta×0.6 + deltaScore×0.4，质量分和桶罚揉在一个数里，核对不上
   - 第二版错误：Δ 列改纯减法，桶罚只影响排序，双因子没嵌入指标得分
   - 最终版：双因子嵌在 `scoreDataset` 的指标层——每个指标的归一化同时考虑排名和变化

### 最终评分公式

```javascript
指标得分 = (P5/P95归一化 × 0.6 + Δ调整 × 0.4) × 权重
Δ调整 = 查4档桶:
  |Δ|≤波动阈值 → 1.0   (不调整)
  |Δ|≤轻扣阈值 → 0.75  (恶化扣25%) / 1.25 (改善加25%)
  |Δ|≤中扣阈值 → 0.5   (恶化扣50%) / 1.5  (改善加50%)
  |Δ|>重扣阈值 → 0      (恶化清零) / 2.0  (改善双倍)

V1 Δ调整恒=1.0（无对比对象）
V2 Δ调整=查桶（恶化扣改善加）
Δ = V2质量分 - V1质量分（纯减法，可核对）
质量分可>100（V2改善多时破满分）
```

### 数据验证：Log 为什么不该用

用 A 组（无主题A.xlsx）和 C 组（有主题C.xlsx）各 1000 关实测：

| 指标 | A组右尾比 | C组右尾比 | 需 Log？ |
|------|:--:|:--:|:--:|
| 流失率 | 2.6 | 3.6 | ❌ 最高才3.6，远低于5的阈值 |
| 难度 | 3.0 | 3.3 | ❌ |
| 变异系数 | 0.8 | 0.8 | ❌ |
| 人均消耗 | 1.2 | 1.3 | ❌ |
| 复活转化率 | 2.7 | 2.6 | ❌ |
| 失败剩余率 | 1.4 | 1.6 | ❌ CV=0.20，分布极窄 |

结论：**全部 6 个指标都不需要 Log 变换。之前加 Log 是经验假设，没看数据。**

### 桶阈值确定

基于 A vs C 配对的 |Δ| 分布实测（n=1000）：

| 指标 | |Δ| P50 | IQR | 波动阈值 | 波动占比 | 阈值最终版 |
|------|-----:|-----:|:--:|:--:|------|
| 流失率 | 1.05 | 2.50 | 0.25 | 16% | **0.20**/1.0/2.5（用户指定 0.20）|
| 难度 | 0.10 | 0.87 | 0.10 | 50% | 0.10/0.35/0.85 ✅ 不变 |
| 变异系数 | 0.09 | 0.42 | 0.05→**0.08** | 31%→45% | 0.08/0.2/0.4 |
| 消耗 | 54 | 285 | 30 | 34% | 30/120/300 ✅ 不变 |
| 复活转化率 | 0.04 | 0.13 | 0.02→**0.03** | 28%→45% | 0.03/0.05/0.15 |
| 剩余率 | 0.03 | 0.11 | 0.02 | 37% | 0.02/0.05/0.12 ✅ 不变 |

### Bug 修复记录

**deltaPenalty is not defined**
- 原因：函数定义在 `scoreDataset` 内部，`run()` 的 `levels.map` 调用时不在作用域
- 修复：`deltaBuckets` + `deltaPenalty` 挪到全局

**V1/V2 口径不一致**
- 原因：V1 用纯 `scoreDataset` 排名，V2 在 `levels.map` 里二次重算双因子
- 修复：`dualScore(r, other)` 统一处理——V1 传 null（Δ调整=1.0），V2 传对方数据

**质量分Δ 对不上**
- 原因：第一版 Δ = baseDelta×0.6 + 桶罚×0.4，和第二版 Δ = V2重算 - V1原始 都对不上
- 修复：V1/V2 都用 `dualScore()` 同公式，Δ = 纯减法

**上传第二个文件卡顿/无响应**
- 原因：`setTimeout(fn, 10)` 延迟解析导致 UI 看起来无响应
- 修复：去掉 setTimeout，上传即刻显示 ⏳，解析完变 ✅

**无标签关卡被误标红**
- 原因：`!v1flags && !v2flags && ds<0 → 红` 规则太严，双因子下小波动常见
- 修复：去掉该规则，仅保留标签驱动的两个条件

## 2026-07-20 — V5.0 稳定性修复 + 性能优化 + 默认值调整

### 背景

V4 上线后在实际使用中暴露三个问题：
1. 单文件模式下点击上传区无反应
2. 上传/加载时严重卡顿
3. 部分模块宽度不一致，布局不协调

### Bug 修复：文件上传无反应

**根因**：`tab-single` 面板内存在重复的 HTML 块（`#group-selects` 和 `#single-warn` 各出现两次），更严重的是有一行孤立的 `</div>`，导致 DOM 嵌套被破坏，`tab-single` 被提前关闭。

- **修复**：删除第164-171行的重复块（8行），恢复正确 div 嵌套
- **影响**：单文件模式上传区点击事件链路（`onclick → click() → change → loadSingleFile()`）恢复通畅

### Bug 修复：sortBy 显示 undefined

- **现象**：排序标签显示"按 undefined"
- **原因**：`sortLabels[sortBy]` 引用在 `sortBy` 赋值前
- **修复**：`sortBy` 赋值移到使用前

### 性能优化（6 项）

#### 瓶颈分析与修复

| # | 瓶颈 | 位置 | 量级 | 修复 |
|---|------|------|------|------|
| 1 | 重复 `levels.filter` ×5 | `renderT` | 5次全量遍历 + 1次完全重复 | 合并为 1次 forEach 分类（5x 提速）|
| 2 | `datasets.find()` 嵌套循环 | `run()` levels.map | O(n²×m)，500关×5指标×500行=125万次扫描 | 建 Level→row 索引 Map，循环外只建1次 → O(1) 查找 |
| 3 | `indexOf` 去重 | `run()` allLvs | O(n²)，500关≈12.5万次比较 | `allLvsSet{}` 对象 O(1) 去重 |
| 4 | `indexOf` 搜索 | `renderT` 筛选 | O(n×m)，每次筛选遍历 | `nsSet{}` 对象替代 → O(1) 查找 |
| 5 | `innerHTML+=` 重排 | `loadSingleFile` finishParse | 每次循环触发 reflow | 字符串拼接后一次性赋值 |
| 6 | `sortBy` 未赋值使用 | `renderT` | 显示 undefined | 赋值前置 |
