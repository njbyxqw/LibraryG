# 关卡文件追踪工具

> Python 脚本 + SQLite 增量存储，追踪 Git 历史中关卡文件的变更记录，生成 Markdown/HTML 报告。

---

## 一、需求背景

在 TileMatch 项目中，关卡文件分布在两个路径：
- `client/Assets/Game/TileV2/Config/LevelConfig/` — 源文件
- `client/Assets/Game/TileV2/Editor/LevelConfig/Levels/线上关卡组/` — AB 变体

需要工具追踪这些文件在 Git 历史中的新增、修改、删除记录，按时间区间查询，并生成可视化报告。

---

## 二、技术方案

### 2.1 技术栈

| 组件 | 说明 |
|------|------|
| `level_tracker.py` | 主脚本，解析 Git log 并写入数据库 |
| `level_tracker.db` | SQLite 数据库，增量存储 commit 和文件变更记录 |
| `report_final.html` | HTML 格式报告输出 |
| Markdown 报告 | 源文件和 AB 变体分开显示的 .md 报告 |

### 2.2 追踪分支

```python
TRACK_BRANCHES = ["tile/tile_dev_level", "dev"]
```

按 `TRACK_BRANCHES` 顺序依次处理每个分支的 commit 历史。

### 2.3 增量更新机制

- 数据库记录 `last_processed_commit`，避免重复处理已解析的 commit
- `update_database()` 按 `TRACK_BRANCHES` 顺序处理
- commit 已存在时**不更新** `source_branch` 字段（保留首次遇到的分支信息）

---

## 三、数据库设计

### 3.1 commits 表

| 字段 | 类型 | 说明 |
|------|------|------|
| `hash` | TEXT PRIMARY KEY | Commit SHA |
| `author` | TEXT | 提交者 |
| `date` | TIMESTAMP | 提交时间 |
| `message` | TEXT | 提交信息 |
| `source_branch` | TEXT | 来源分支 |

### 3.2 file_changes 表

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PRIMARY KEY | 自增 ID |
| `commit_hash` | TEXT | 关联 commit（外键） |
| `file_path` | TEXT | 文件完整路径 |
| `file_name` | TEXT | 文件名 |
| `file_type` | TEXT | `source`（源文件）或 `ab_variant`（AB 变体） |
| `change_type` | TEXT | `added` / `modified` / `deleted` |

### 3.3 分支逻辑修复

**早期设计**：使用独立的 `commit_branches` 表记录 commit 与分支的多对多关系。

**问题**：同一 commit 出现在多个分支时，`source_branch` 归属不确定，导致报告统计混乱。

**修复方案**：去掉 `commit_branches` 表，在 `commits` 表中直接加 `source_branch` 字段。commit 已存在时不更新该字段，确保每个 commit 只归属到第一个处理的分支。

---

## 四、文件类型区分

### 4.1 过滤规则

- **过滤 .meta 文件**：Unity 生成的 `.meta` 文件不纳入追踪
- **源文件**（`file_type = "source"`）：路径匹配 `LevelConfig/` 下的 `.json` 文件
- **AB 变体**（`file_type = "ab_variant"`）：路径匹配 `线上关卡组/` 下的 `.json` 文件

### 4.2 文件名识别

AB 变体文件名格式：`{level_id}_ab{variant}.json`，如 `417_ab70C.json`。

---

## 五、查询与报告

### 5.1 日期过滤器

支持两种格式：

| 格式 | 示例 | 精度 |
|------|------|------|
| 日期 | `2026-06-01` | 精确到天 |
| 日期时间 | `2026-06-01T10:30:00` | 精确到分钟 |

### 5.2 Markdown 报告

报告结构：
1. **头部**：生成时间、追踪路径
2. **按 commit 分组**：每个 commit 显示作者、时间、SHA
3. **源文件变化**和 **AB 变体变化**分开显示
4. 每个文件标注 `[新增]` / `[修改]` / `[删除]`

### 5.3 HTML 报告

`report_final.html` 提供更丰富的可视化：
- 按日期分组的折叠视图
- 文件变更统计图表
- 侧边栏导航

## 七、脚本调用方式

### 7.1 命令行

```bash
# 全量更新数据库
python level_tracker.py --update

# 按时间区间生成报告
python level_tracker.py --report --since 2026-06-01 --until 2026-06-26

# 精确到分钟
python level_tracker.py --report --since 2026-06-01T10:30:00 --until 2026-06-26T19:00:00
```

### 7.2 参数说明

| 参数 | 说明 |
|------|------|
| `--update` | 增量更新数据库（从 last_processed_commit 继续） |
| `--report` | 生成报告 |
| `--since` | 起始时间（包含） |
| `--until` | 截止时间（包含） |
| `--format` | 输出格式：`markdown` 或 `html`（默认 `markdown`） |

## 八、关键设计决策

| 决策 | 原因 |
|------|------|
| SQLite 而非纯文件 | 支持增量更新，避免每次全量解析 Git log |
| source_branch 不更新 | 避免 commit 归属歧义，第一个处理的分支即为来源 |
| 过滤 .meta 文件 | .meta 是 Unity 自动生成，不反映人工关卡变更 |
| 源文件/AB 变体分开显示 | 两类文件的变更含义不同，混合显示会造成混淆 |
| 精确到分钟查询 | 大规模批量提交时，需要精确到时间点过滤 |
