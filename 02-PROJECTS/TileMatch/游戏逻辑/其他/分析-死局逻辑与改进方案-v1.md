# 死局（Deadlock）逻辑与改进方案

> **背景**：TileMatch 关卡中，当玩家无法继续消除时触发死局判定，关卡失败或触发复活。本文梳理当前死局判定逻辑，并提出两步/三步死局的改进方案。

---

## 一、当前逻辑确认

### 1.1 判定条件

**核心文件**：`InevitableDeathJudge.cs`

```csharp
public static bool IsDeadlock()
{
    var bar = Bar.Instance;
    int unmatchedCount = bar.UnmatchedCount;
    int currentCapacity = bar.CurrentCapacity;
    
    // 关键条件：手牌区剩 1 格（remainingCapacity <= 1）时才判死局
    if (unmatchedCount <= currentCapacity - 2)
        return false;  // 手牌区还有 >= 2 格空位，不判死局
    
    // 遍历所有可点击牌，检查单张/双张消除可能性
    // ...
}
```

**结论**：
- 判定条件：**`UnmatchedCount > CurrentCapacity - 2`**（即 `remainingCapacity <= 1`）
- 然后遍历所有可点击牌检查单张/双张消除可能性

### 1.2 上报路径

| 事件 | 字段 | 触发点 |
|------|------|---------|
| `prop_used` | `deadlock_times` + `is_deadlock` | 道具使用时 |
| `lv_end` / `lv_revive` | `deadlock_times` | 关卡结束/复活 |
| `add_moves_show` | — | 复活弹窗显示 |

### 1.3 状态更新触发点

- `AddingToBarByClick` — 放牌到手牌区
- `BarMatched` — 手牌区消除
- `LevelPrePropFinished` — 道具使用前
- `LevelFailed` — 关卡失败
- `LevelRevived` — 关卡复活
- `AfterShuffle` — 洗牌后
- `UseProp()` 成功后

## 二、待改进项

### 2.1 两步/三步死局缺失

**当前**：只判定 `remainingCapacity <= 1`（一步死局）

**改进方向**：
- **两步死局**：`remainingCapacity == 2` 时，递归检查下一步所有可能的放牌位置，是否都会导致一步死局
- **三步死局**：`remainingCapacity == 3` 时，递归检查两步死局

### 2.2 双口径

**问题**：`InevitableDeathJudge.cs` 和 `Bar.cs` 中都有死局相关逻辑，口径可能不一致。

**建议**：统一到 `InevitableDeathJudge.cs`，`Bar.cs` 只负责数据。

### 2.3 duration 缺失

**问题**：当前没有记录死局持续时长（`deadlock_duration`）

**建议**：新增字段，附在现有事件上（不需要独立事件）

## 三、两步死局扩展详细方案

### 3.1 入口放宽

```csharp
// 原入口：只处理 remainingCapacity <= 1
if (unmatchedCount <= currentCapacity - 2)
    return false;

// 新入口：额外处理 remainingCapacity == 2 和 == 3
if (unmatchedCount <= currentCapacity - 4)
    return false;  // remainingCapacity >= 4，不判死局
```

### 3.2 新增 remainingCapacity == 2 递归分支

```csharp
private static bool IsTwoStepDeadlock()
{
    // 1. 获取当前所有可点击牌
    var clickableTiles = GetAllClickableTiles();
    
    // 2. 对每张牌，模拟放到手牌区的所有可能位置
    foreach (var tile in clickableTiles)
    {
        // 模拟放牌
        Bar.Instance.SimulateAddTile(tile);
        
        // 3. 检查放牌后是否一步死局
        if (!IsDeadlock())  // 放牌后不是一步死局，说明两步不死
            return false;
            
        // 回退模拟
        Bar.Instance.SimulateRemoveTile(tile);
    }
    
    // 所有可点击牌都导致一步死局，判定为两步死局
    return true;
}
```

### 3.3 新增 remainingCapacity == 3 递归分支

```csharp
private static bool IsThreeStepDeadlock()
{
    // 类似两步死局，但递归深度 +1
    // ...
}
```

### 3.4 O(n²) 复杂度

**问题**：两步死局需要遍历所有可点击牌（n），每张牌模拟后检查一步死局（n）→ O(n²)

**优化**：
- 缓存可点击牌列表（只在牌状态变更时更新）
- 剪枝：只要找到一张牌不放导致死局，立即返回 `false`
