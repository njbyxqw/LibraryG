### 参数与数量边界

定义：`Scripts/GameCore/Logic/GameLogic/Module/DyeingBomb/DyeingBombConfig.cs`。

| 参数 | 当前默认值 | 含义 |
|---|---:|---|
| MaxEnergy | 3 | 每轮触发消费 3 点能量；2026-10-15 当前工作区调整 |
| DyeCount | 6 | 默认染色上限 6 张 |
| BarTypeThreshold | 5 | 合格普通手牌达到 5 种花色，启用手牌优先 |
| PriorityBarTypeCount | 2 | 优先处理其中 2 种花色 |
| EnergyTileCount | 9 | 能量牌总目标3组；2026-10-15 当前工作区调整 |

`DyeCount > 0` 时按 `DyeCount / 3` 向下取整规划组数；非正数时选择器默认 3 组。常规分支只保留完整三张，手牌优先分支可保留不足三张的必选手牌，因此实际数量不保证达到上限或为 3 的倍数。`Assets/Module/GM/Scripts/Category/GmCommon.cs` 可调整 MaxEnergy / DyeCount；默认值不等于所有运行实例的实时值。

### 染牌优先级（当前分支）

入口：`DyeingBombSystem.TriggerDyeing()` → `DyeingBombTargetFilter.FilterTiles()`；文件为 `Scripts/GameCore/Logic/GameLogic/Filter/DyeingBombTargetFilter.cs`。

**第一优先：手牌特殊分支。**

- 合格且 InBar 的普通手牌达到5种不同花色时触发。
- 对这些花色统计棋盘 Highlight / Visible / NotVisible 中 State=InBoard 的存量，按存量降序，同量随机，取前2色。存量统计使用原池，不重新过滤锁定与 eligible；Bar / OverBar 不计入存量。
- 先保留前2色的全部合格手牌，直到本轮上限。再按 Highlight → OverBar → Visible → NotVisible 补成同色三张；补不齐仍保留必选手牌，不加入失败的部分补牌。
- 该分支的必选手牌及补牌不参与深度和排序。其他手牌从后续候选池排除；剩余额度按下述常规流程选完整组三张。

**常规花色来源顺序：Highlight → Bar → OverBar → Visible → NotVisible。**

每种花色归入它当前仍有候选的最高优先级来源池；排序先比较来源，来源相同再应用下列规则。

| 花色类别 | 花色间排名 | 实际选三张 |
|---|---|---|
| 有合格高亮候选的花色 | 最浅三张深度和档位升序 → 高亮数量降序 → 随机 | 跨全部候选池找该花色最浅三张，直接返回评分组三张 |
| 最高来源为 Bar / OverBar / Visible / NotVisible | 来源优先级 → 该来源同色数量降序 → 随机 | 按五池顺序收集同花色三张，不按深度排序 |

**高亮花色深度档位。**

1. 从该花色全部合格候选中取剩余最浅三张，不限三张都高亮；少于三张则该花色不能成组，跳过。
2. 档位为 `max(3, 三张深度之和)`，因此按 **≤3 → 4 → 5 → …** 排序。同档先比较高亮同色数量，数量相同再随机。
3. 同深度牌按候选池遍历顺序保留：Highlight → Bar → OverBar → Visible → NotVisible，池内沿原列表顺序，不额外按 Id 排序。
4. 深度来自 `TileDepthComputer.ComputeTileDepths` 对当前 Board 的批量计算；深度表找不到的牌默认 **1**，手牌/弃牌没有被专门设置为0。
5. `SelectGroups()` 开始时计算一次深度表；每选完一组仅排除已选牌、重新组成最浅三张并排名，不模拟移除棋盘遮挡后重算几何深度。

**降级范围与讨论口径的差异。**

- A、B 都属于高亮花色时，B 即使高亮数量少，只要深度和更低，就能越过 A。
- 代码先比较 RegionIndex，再比较高亮深度档位。因此高亮花色 A 的深度和即使为6，仍先于仅有手牌的花色 B（B 即使三张深度和为3）。这不是“所有来源花色统一按深度和排序”。
- 前序讨论曾使用“深度和优先，同分沿用原来源优先级”的全局表述；当前实现只在高亮花色内部降级。这里保留为实现范围差异，未擅自修改代码或认定已满足全局排序。
- 现有代码没有将“牌堆高亮”和“其他高亮”拆成两个池；对应的实现是同一 Highlight 池内先深度档位、再同色数量。

每次成功选完完整组后重新排名，可重复选同一花色。所有花色均无法凑齐三张则停止；常规结果为3的倍数，手牌特殊分支可保留不足三张的结果。

### 共同资格与候选池处理

- 排除 null、Blocker、有效 LockState=Locked，以及 **Golden、DyedSuit、Joker**。当前过滤器不再显式排除 Candy；是否入选仍取决于其分组、状态和其他条件。
- 只允许 InBoard / InBar / InOverBar，传入 eligible 时也必须满足；不单独排除 SequenceId。
- 来自 Highlight 但 `Clickable()` 为 false 的合格牌不会直接丢弃，而是依据 `IsVisibleToPlayer()` 降到 Visible 或 NotVisible 池。
- 跨池按 Tile 去重；后续最浅组三张及来源数量均基于归池后的候选。
- Rocket=5000、CandyBottle=5170、Energy=5250 仍被 Blocker 分组排除；能量牌收集和普通牌染为 DyedSuit 是不同链路。

## 运行时主链路

```text
Energy.json → LevelCollect(CollectKey=DyeingBomb)
  → LevelCollectAction → DyeingBombSystem.TryReserveEnergy(tileId, count)
  → 收集表现完成 → LevelCollectActionInvoker 发布 DyeingBombEnergyCollected
  → CompleteEnergyCollection → TryTriggerDyeing
  → TriggerDyeing → DyeingBombTargetFilter.FilterTiles
  → TileService.ModifyTile(target, DyedSuit=1002)
  → DyeingBombActionData → DyeingBombViewAction
  → 动画完成 → OnDyeingComplete → 检查剩余能量
```

- **预留与入账**：预留阶段按 tileId 去重并累计 pending；完成事件需 SessionId、CollectionId、Count 匹配后才将 pending 转入 current。
- **输入锁**：染色进行中，或允许触发且 current+pending 达到门槛时禁用输入；不必等能量飞行结束才锁定。
- **触发消费**：先发布满额状态，再扣除 MaxEnergy（当前默认3点）并选牌。无目标也消费本轮能量；已入账的剩余能量满足条件时继续检查。
- **染色结果**：目标统一修改为 DyedSuit；InBar 牌延迟通知 BarChanged，其他牌立即通知。没有独立创建 DyedSuit Prefab 的过程。
- **结束收口**：完成事件校验 SessionId / RoundId，解除处理锁，并根据 CanContinue 决定是否继续。
- **定位**：`Scripts/GameCore/Logic/GameLogic/Behaviours/Action/Implementation/LevelCollectAction.cs`、`Scripts/GameCore/Application/ActionInvoker/Implementation/LevelCollectActionInvoker.cs`、`Scripts/GameCore/Logic/GameLogic/Module/DyeingBomb/DyeingBombSystem.cs`。

## 能量牌生成位置（2026-10-15 调整）

- **当前依据**：`dev_dyeingtest` 工作区，基于 `11fbe0b9e7` 的本次未提交修改。文件为 `Scripts/GameCore/Logic/GameLogic/Module/LevelEnergyTile/Strategy/EnergyTileNormalStrategy.cs` 与 `Module/DyeingBomb/DyeingBombConfig.cs`。
- **确认后的参数**：收3染6，能量牌总目标9张（3组）。若9张全部收集，理论触发3次，累计染色上限18张；实际依生成数量及可染目标而定。
- **候选资格**：FromRandom 普通牌，排除 Energy、Golden、CandyBottle 及 Blocker / Collectable；不额外判断锁定、SequenceId、高亮。
- **位置与配额**：按 Depth → z → Id 升序排列候选，前50%为统一优先池、后50%为兜底池；分界向上取整。取消原浅区前30%固定优先2组的安排，不设置15%下界。
- **选组顺序**：先在前50%选择所有可用完整组，达到所需组数即停止；不足再从后50%补。池内随机选一种数量至少3张的原花色，再随机取该花色三张；不按最浅三张深度和选花色，也不跨池拼三张。
- **不足与已有能量**：同色整组不足可少于9张；已有能量计入总目标，超量不主动删除，已有数量非3倍数则沿用原逻辑跳过。分区规则仅约束本次自动转换，不搬移关卡中既有能量牌。
- **表层保护**：若全部高亮牌都为能量牌，尝试将本次一组含高亮的转换还原，优先从前50%未选中的非高亮候选找同色三张替换，前半无组再到后50%；均无组则不替换。该保护不保证初始表面能量牌的具体数量上限。
- **目的与边界**：降低总量并取消浅区6张配额，预期减少开局表面能量牌；前50%仍含高亮牌，不能据静态代码保证每个关卡的高亮数量都减少。
- **历史口径**：此前30%～50%中区划分已被本次两池方案替代。15%～50%严格范围曾讨论但未实施。更早 dev 工作区的生成深度和试做不在当前策略中；染色目标的高亮花色深度分档仍是另一条链路。
- **验证**：提取实际选组方法进行独立 C# 校验，通过前半足量、后半补组、同色完整组三张、去重、不足不拆组、零剩余组、表层替换优先/兜底/排除已选，以及候选数0～100的分界检查；diff 检查通过。模块构建仍因缺少 project.assets.json 报 NETSDK1004，未进入完整模块编译；未做 Unity / 真机验证。

## 能量牌资源与暗态表现

### 能量牌资源链

```text
TileType.Energy=5250
  → tileblockercfg.bytes / tileblockercfg.json~ 的 id=5250
```

- `tileblockercfg.bytes` 是运行时 Protobuf；`tileblockercfg.json~` 是可读备份，二者当前将 `5250` 映射至 `TileEnergy.prefab`。
- 普通能量牌图标与 HUD 飞行图标使用 `Energy/Texture/block_9999.png`（能量喷罐）；普通高亮牌底使用 `Energy/Texture/block_db_bg.png`。
- `TileEnergy.prefab`、`DyeingBombCollectViewUGUI.prefab`、飞行拖尾/粒子共同组成当前点击收集表现。不要将能量牌图标指向目标花色 `Texture/Tiles/block_1002.png`。
- `block_9999.png` 是 512×512、透明背景；其 `.meta` 以 `block_305.png.meta` 为基准，保持 Sprite Single、PPU 450、中心 Pivot、MipMap Off、Bilinear、Clamp、iOS/Android Max Size 128、Format 48。
- 染色目标牌使用 `Texture/Tiles/block_1002.png`；破碎配置 `tilebreakeffectcfg*.json~` 指向独立 `Particle/block_1002_Particle.prefab`，不再与 `block_305` 共用同一 Prefab 引用。

### Pile 不可见态牌底

- `EnergyTileView` 在 `Data.InPile && EntityVisibility.NotVisible` 时关闭专用背景并显示 `plainBackground`。
- `plainBackground` 是 `TileEnergy.prefab` 的 `PileBackground`，当前引用 `Texture/Tiles/block_bg2.png`，因此与普通暗牌使用的全局 `BlockBgConfig=block_bg2` 一致。
- 此处不能用喷罐 Sprite 或目标花色 Sprite；它是不可见状态的牌底，尺寸为 118×132、PPU 100。
