# 局内道具逻辑梳理

## 概述

本文档对 TileMatch 局内道具（Hint / Shuffle / Remove / Revert / SolutionHint）的完整架构与核心逻辑进行分析梳理。道具系统采用清晰的三层架构，各层职责分离，便于扩展与维护。

## 三层架构

```
UI 层 → Entry 层 → Logic 层
```

| 层级 | 职责 | 说明 |
|------|------|------|
| **UI 层** | 用户交互、按钮点击反馈 | 显示道具图标、数量、可用状态 |
| **Entry 层** | 道具入口调度 | 接收 UI 请求，路由到对应 Logic 实现 |
| **Logic 层** | 核心选牌/执行逻辑 | 每种道具有独立的选牌算法与执行策略 |

## PropType 枚举

```csharp
public enum PropType
{
    AutoMatch,        // 自动消除（DDA 触发）
    Hint,             // 提示
    Shuffle,          // 洗牌
    MoveToOverBar,    // 移至 OverBar
    Remove,           // 移除
    RevertLastAdd,    // 撤销上一次放入（已标记弃用）
    SolutionHint      // 死局自动提示
}
```

| 枚举值 | 说明 | 触发方式 |
|--------|------|----------|
| `AutoMatch` | DDA 自动匹配消除 | 系统自动触发 |
| `Hint` | 高亮提示可消除的牌对 | 玩家点击 |
| `Shuffle` | 重新排列 Bar 中的牌 | 玩家点击 |
| `MoveToOverBar` | 将选中牌移至 OverBar 槽位 | 玩家点击 |
| `Remove` | 直接移除选中牌 | 玩家点击 |
| `RevertLastAdd` | 撤回最后一次放入 Bar 的牌 | 已弃用 |
| `SolutionHint` | 死局时自动给出提示 | 系统检测死局后触发 |

## IProp 接口体系

所有道具逻辑均实现 `IProp` 接口，保证统一的调用契约：

```csharp
public interface IProp
{
    PropType Type { get; }
    bool CanExecute();
    void Execute();
}
```

每种 PropType 对应一个 `IProp` 实现，由 Entry 层根据 `PropType` 路由调度。

## 选牌算法

### AutoMatch / Hint 选牌算法

**核心策略**：优先在 Bar 中寻找同类型、同花色的牌对进行消除。

1. 遍历 Bar 中所有牌，按类型 + 花色分组
2. 优先返回 Bar 中已存在的同类型花色牌对
3. 若 Bar 中无匹配，则从棋盘上寻找可消除组合
4. `AutoMatch` 直接执行消除，`Hint` 仅高亮不消除

### Shuffle 选牌算法

**核心策略**：优先凑 `LastUnmatched` 消除，即尽量让洗牌后能解决当前无法消除的局面。

1. 计算当前 Bar 中无法配对消除的牌集合（`LastUnmatched`）
2. 以 `LastUnmatched` 为目标，尝试重排使这些牌能被消除
3. 评估重排后局面的可解性
4. 输出最终洗牌结果

详见 [[Shuffle改造AB测试方案]]。

## 移牌逻辑

### MoveToOverBar

- 将玩家选中的牌从棋盘移至 OverBar 额外槽位
- OverBar 有容量限制，满时不可使用
- 用于腾出 Bar 空间或临时存放关键牌

### Remove

- 直接将选中牌从棋盘移除（不放入 Bar）
- 相当于"丢弃"该牌，不触发消除
- 适用于移除干扰牌或无法配对的牌

## RevertLastAdd（已弃用）

- 撤回最后一次放入 Bar 的牌，将其退回棋盘原位
- 已标记 `@Deprecated`，不再推荐使用
- 历史遗留功能，后续版本可能移除

## SolutionHint 死局自动提示

当系统检测到死局时，自动触发 `SolutionHint` 给出提示。

### DeadlockHint / DeathHint 缓存预计算

- **DeadlockHint**：在关卡加载时预计算可能的死局提示路径
- **DeathHint**：运行时死局检测确认后，从缓存中取出对应提示
- 采用缓存预计算策略，避免运行时实时计算的性能开销

### 死局检测流程

```
玩家操作 → 触发死局检测 → 查询 DeadlockHint 缓存
  → 若命中：直接返回提示
  → 若未命中：实时计算 → 存入缓存 → 返回提示
```

## DDA 钻石等值换算

DDA（Dynamic Difficulty Adjustment）系统中，钻石作为虚拟货币用于等值换算道具价值：

| 道具 | 钻石等值 | 说明 |
|------|----------|------|
| Hint | 低 | 仅提示不执行 |
| Shuffle | 中 | 重排 Bar |
| MoveToOverBar | 中 | 额外槽位 |
| Remove | 高 | 直接移除牌 |
| AutoMatch | 变动 | DDA 根据难度动态调整 |

DDA 会根据玩家当前关卡进度、失败次数等动态调整道具的触发频率与价值。

## PreGame 链式执行

PreGame 阶段支持链式执行多个预处理步骤：

```
PreGame Step 1 → Step 2 → Step 3 → ... → 游戏开始
```

- 每个 Step 可插入道具预计算、死局检测初始化等逻辑
- 链式执行保证顺序性，前一步完成后才进入下一步
- 支持条件跳过（如某 Step 不满足条件则跳过）

## CustomTargetFilter 选牌算法

部分道具支持自定义目标过滤（`CustomTargetFilter`），用于在选牌时施加额外约束：

- 按关卡配置的目标类型过滤候选牌
- 可与基础选牌算法组合使用
- 常用于特殊关卡（如限定花色、限定层级）

## Bot 模拟支持

道具系统支持 Bot 自动模拟操作：

- Bot 可调用所有 `IProp` 实现，模拟玩家使用道具
- 用于自动化测试、DDA 数据采集、关卡平衡性验证
- Bot 模拟与真实玩家共享同一 Logic 层，保证行为一致性
