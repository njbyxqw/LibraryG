# 关卡连胜与闪电球逻辑

> **背景**：TileMatch 关卡中，玩家连续消除会触发"连胜"计数，达到一定条件后可能触发闪电球（RocketVL）等特殊效果。本文梳理连胜计数逻辑、闪电球触发条件、与相关打点事件的关联。

---

## 一、连胜计数逻辑

### 1.1 计数触发点

| 触发点 | 文件 | 说明 |
|--------|------|------|
| `BarMatched` | `TileMatchGameLogic.Bar.cs` | 手牌区消除成功，连胜 +1 |
| `AddingToBarByClick` | `TileMatchGameLogic.Entity.cs` | 放牌到手牌区（未消除） |
| `LevelFailed` | `TileMatchGameLogic.Deadlock.cs` | 关卡失败，连胜清零 |
| `LevelRevived` | `TileMatchGameLogic.Deadlock.cs` | 关卡复活，连胜重置 |

### 1.2 连胜与死局的关系

- **死局判定**：`InevitableDeathJudge.cs` 中，连胜计数影响死局判定
- **关键逻辑**：连胜计数高时，死局判定更宽松（给玩家更多机会）
- **打点字段**：`prop_used` 事件含 `is_streak`（是否连胜）、`streak_count`（连胜次数）

## 二、闪电球（RocketVL）逻辑

### 2.1 触发条件

```csharp
// RocketVL 闪电球触发条件（推测）
if (streakCount >= 5)  // 连胜 5 次
{
    TriggerRocketVL();
}
```

### 2.2 视觉替换方案

- **文档**：`报告-RocketVL闪电球视觉替换.md`
- **实施**：`workbuddy_archives/RocketVL-闪电球视觉替换.md`
- **关键改动**：
  - 球体动画移除，仅保留闪电打牌
  - `DataBridge` 为 `internal` → 改为 `public`
  - `EventType` 歧义（`UnityEngine.EventType` vs `Config.Behaviours.Event.EventType`）→ 加 using alias

## 三、与死局逻辑的关联

### 3.1 死局触发条件

- **核心**：`InevitableDeathJudge.IsDeadlock()` 中，当 `UnmatchedCount > CurrentCapacity - 2`（即 `remainingCapacity <= 1`）时判死局
- **连胜影响**：连胜计数高时，死局判定更宽松（具体逻辑需查代码）

### 3.2 打点上报

| 事件 | 字段 | 说明 |
|------|------|------|
| `prop_used` | `deadlock_times` + `is_deadlock` + `is_streak` + `streak_count` | 道具使用（含死局和连胜信息） |
| `lv_end` / `lv_revive` | `deadlock_times` + `streak_count` | 关卡结束/复活 |
| `add_moves_show` | — | 复活弹窗显示 |
