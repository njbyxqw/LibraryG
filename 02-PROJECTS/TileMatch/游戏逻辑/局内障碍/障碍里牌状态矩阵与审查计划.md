# 障碍里牌状态矩阵与审查计划

> [!abstract] 目标
> 二次整理障碍系统，统一描述障碍自身与“里牌”在不同事件下的状态变化，并核对逻辑、表现、点击、DDA、死局、Bot、回放/重连等模块是否使用了正确的状态。本阶段只梳理现状与提出建议，不新增运行时逻辑。

## 一、范围与边界

### 本轮包含

- Effect 覆盖普通 Tile：Curtain、Cirrus、Mystery、Cloud、GiftBox、Cookie、Pig、Stone、Crate 等。
- 障碍 Tile 持有序列子牌：Switch、CardBox、SuitCase、SlotMachine、Flip、JokerFlip、MagicBox、ShellBox、Thief。
- 状态变化关联模块：配置/ECA、核心数据、棋盘可见性、点击、DDA、死局保底、GameView、Headless/Bot、回放/重连、编辑器配置。

### 本轮不做

- 不修改 C#、JSON、Prefab 或二进制配置。
- 不把“建议新增”当成已确认需求。
- 不顺带重构现有可见性、序列或事件框架。

## 二、证据标记

| 标记 | 含义 |
|---|---|
| **已确认** | 当前 `dev` 源码/配置可直接证明 |
| **推断** | 根据静态调用链推导，仍需 Unity 运行验证 |
| **待验证** | 静态代码不足，需要关卡、录屏、日志或断点 |
| **建议新增** | 可能需要的新状态、刷新入口、测试或文档；尚未决定实施 |

## 三、统一状态字典

| 状态维度 | 当前载体 | 含义 | 审查注意点 |
|---|---|---|---|
| 棋盘归属 | `TileState` / `EffectState` | InBoard、InBar、InOverBar、销毁中等生命周期 | 与显示状态分开，不应由 View 猜测 |
| 层级可见性 | `EntityVisibility` | `NotVisible(1)` / `Visible(2)` / `Highlight(4)` | 表达层级/序列显示窗口，不等于完整的“玩家当前可见” |
| 历史看见 | `TileData.HasSeen` | 该牌是否曾经对玩家可见 | 用于 DDA/Shuffle/表现；不是当前可见性的反向开关 |
| 玩家当前可见 | `TileData.IsVisibleToPlayer()` | 综合 `EntityVisibility` 与可隐藏 Effect 后的派生结果 | 当前缺少统一的表现刷新/事件语义 |
| 点击遮挡 | `EffectData.IsClickOccluder` | Effect 是否拦截底牌点击 | Curtain 同时借它表达开/关，需避免等同于 `EntityVisibility` |
| 高亮/可交互 | `TileData.Highlight` + `Tile.Clickable()` | 是否为当前可点击牌 | 还会受 LockState、TileType、Effect click mask 影响 |
| 序列激活位 | `ActiveIndex` / `SequenceDisplayConfig` | Switch 等容器当前激活子牌 | 当前在 SharedBag 与显示服务之间同步 |
| DDA 资格 | `HasSeen`、可见性变化标记、Sequence regulation 配置 | 是否可参与调控/交换 | 要区分首次揭示、重新显示、Shuffle 重建 |
| 表现缓存 | TileView 的 `_visibility` / `_highlight` / `_seen` | View 对逻辑数据的本地镜像 | 必须核对 GameView 与 Headless 是否一致 |

> [!warning] 统一口径
> “Visible”至少可能指 `EntityVisibility.Visible`、Effect 自身进入 Highlight、玩家肉眼能看到、牌面 Renderer 开启、或牌可点击。后续文档必须写明具体维度，禁止只写“可见/不可见”。

## 四、功能模块使用矩阵

| 模块 | 主要输入状态 | 主要输出/消费 | 本轮验收点 |
|---|---|---|---|
| 配置 / ECA | Event、Condition、Action、Blackboard | 状态切换与 ActionResult | 事件先后、Target/Source、StopPolicy 是否明确 |
| 核心数据 | TileData、EffectData、SharedBag | 当前状态与派生判断 | 状态所有权唯一；历史状态不替代当前状态 |
| Board / Visibility | Index、Effect 覆盖、SequenceDisplay | EntityVisibility、可见性缓存 | 增删/切换 Effect 后是否刷新覆盖区域 |
| 点击 | Highlight、LockState、Effect click mask | `Tile.Clickable()` | 玩家、转发点击、能量牌、Bot 语义一致 |
| DDA / Shuffle | HasSeen、visibility change、sequence window | 交换、预调控、重建 HasSeen | 打开/关闭、激活位切换不能重复或漏调控 |
| 死局保底 | 可交互牌计数、锁定牌、障碍候选 | 注册/选择保底动作 | 保底动作后的里牌状态必须闭环 |
| GameView | EntityVisibility、HasSeen、ActionResult | 图标、颜色、动画、排序 | 动画状态与逻辑当前状态一致 |
| Headless / Bot | 模拟可见性、点击遮挡、序列状态 | 可执行动作与搜索状态 | 不依赖 GameView 动画补齐逻辑 |
| 回放 / 重连 | 点击记录、初始化配置、运行时重演 | 状态重建 | 中途打开/关闭、激活位、HasSeen 能否复现 |
| 编辑器 / 关卡数据 | TileType、EffectType、DefaultActiveIndex、序列 | 初始局面 | 初始状态与运行时初始化行为一致 |

## 七、Curtain 基线矩阵（Codex 重点处理）

| 场景 | 事件/入口 | Curtain 状态 | 里牌状态 | 模块使用情况 | 当前判断 |
|---|---|---|---|---|---|
| 尚未进入 Highlight | Effect 尚不可触发 `VisibilityStateEquals(4)` | 配置初始为关闭：`IsClickOccluder=true` | `IsVisibleToPlayer()` 会将可隐藏且关闭的 Curtain 计为不可见来源 | ECA 不切换；点击由 Effect 阻挡 | **已确认** |
| 首次进入 Highlight | `EffectVisibilityChanged` / `LevelEnterAnimationStepOneFinished` → 50001 | 打开：ClickOccluder=false，TransmitAttack=false | `HandleCoveredTileReveal` 将满足条件的底牌 `MarkSeen()` | View 播 `up`；DDA 本次关闭 | **已确认** |
| 下一次普通牌被接收 | `BeforeAddingToBarByClick` → 50004 | 关闭：ClickOccluder=true，TransmitAttack=true | 没有反向隐藏动作；`HasSeen` 保持 true | View 播 `down`；当前依赖帷幕动画覆盖牌面 | **已确认；肉眼结果待运行时验证** |
| 再下一次普通牌被接收 | `BeforeAddingToBarByClick` → 50003；随后 `AddingToBarByClick` → 50009 | 先打开并标 Pending，后清 Pending | `HandleCoveredTileReveal(TryDdaRegulation=true)`；底牌保持 HasSeen | 打开动画 + 揭示/DDA | **已确认** |
| 能量牌被接收 | `BeforeEnergyTileClickAccepted` / `EnergyTileClickAccepted` | 与普通点击相同切换 | 与普通点击相同 | 能量牌是后补链路 | **已确认** |
| 死局且关闭 | Candidate → `BlockerGuaranteeSelected` → 50007 | 仅打开，不销毁 | 揭示底牌，不执行 DDA | 保底仲裁消费当前 ClickOccluder | **已确认** |

### Curtain 当前缺口

- **已确认**：`IsClickOccluder` 表达当前开/关；`HasSeen` 表达历史看见，两者语义不同。
- **已确认**：关闭路径没有与 `HandleCoveredTileReveal` 对称的“当前隐藏/刷新覆盖牌”动作。
- **已确认**：TileView 的牌面显示条件使用 `EntityVisibility`、Highlight、HasSeen，没有直接消费 `IsVisibleToPlayer()`。
- **推断**：关闭后逻辑判断可认为底牌当前不可见，但牌面 Renderer 仍可能保持开启；最终肉眼效果依赖 Curtain Spine 遮盖。
- **建议新增**：提供统一的“当前玩家可见性变化”刷新入口或事件，保留 `HasSeen` 作为历史状态；不建议用改写 `EntityVisibility` 的方式覆盖层级/序列语义。

### 8.6 第一批问题登记

#### 已确认的代码不一致或结构事实

1. **Switch Headless 激活索引反转**：Logic 与 GameView 按原始 `ActiveIndex` 选择子牌；Headless 按 `0↔1` 后的索引选择。
2. **Curtain 当前可见与牌面表现分离**：逻辑有 `IsVisibleToPlayer()`，GameView 图标没有消费它。
3. **SequenceCountChange 首次观察不算变化**：首次只记录当前 Count 并返回 false，所有依赖该 Condition 的旁路都应验证基线建立时机。
4. **SlotMachine 解锁依赖 ViewAction 完成**：逻辑 Action 上锁，GameView/Headless ViewAction 在 `finally` 解锁。
5. **Curtain Bot 专属模拟可达性疑点**：模拟器包含 Curtain 分支，但入口集合只收集 `IsOccluder=true` 的 Effect；Curtain 当前默认 false。

#### 待验证风险，不作为 Bug 结论

- CardBox 的 global `CardBox_OpenPending` 是否在多实例同时受击时串扰。
- CardBox / SlotMachine 在首次事件即发生直接销毁、AutoMatch、Energy 或重连恢复时，SequenceCount 基线是否导致漏刷新。
- SlotMachine 在非 Highlight 状态下直接销毁 index0 后，剩余序列是否全部落入 NotVisible。
- SuitCase 未来若允许超过3张，真实窗口与 Bot 推进是否分歧。
- Curtain 回放/重连能否稳定重建开/关、SharedBag 与牌面表现，且无一帧泄露。

#### 建议新增但未决定实施

- 增加 Logic/GameView/Headless/Bot 同输入快照对比测试。
- 增加 `DefaultActiveIndex=0/1` 的 Switch Headless 一致性测试。
- 为序列容器记录“SequenceCount 基线是否已建立”的验收观察项。
- 为 Curtain 增加“当前玩家可见”与“牌面实际呈现”断言，保留 HasSeen 的历史语义。
- 对逻辑上锁、ViewAction 解锁的流程增加取消、异常、缺失 View 时的锁释放用例。

#### 已确认的代码差异，不直接判定为 Bug

1. `SequenceConstraintHelper` 只对 Flip 启用序列牌型去重，JokerFlip 不启用。
2. `FlipSimulator` 与 `JokerFlipSimulator` 的剩余数量分支和 responded 标记时机不对称。
3. `BlockerTileMatchSimulator` 对 JokerFlip 跳过通用 Match 伤害，对 Flip 没有同样例外。
4. GameView 有重连立即收敛与 `OnShuffleChange`；Headless 没有完全对称的处理。
5. Headless 的不同刷新路径分别从序列牌和容器读取 Highlight，数据来源不一致；`SetClickEnable` 为空，点击主要依赖 `LockState`。

#### 待验证风险

- Flip Bot 在序列剩余 1 张时访问 `sequence[1]` 的实际可达性与影响。
- 普通点击与 Energy 点击共用 Behaviour 时的优先级和事件顺序。
- `SequenceCountChange` 首次只建基线是否会漏掉首个旁路变化。
- GameView / Headless 在 Shuffle、重连和 Highlight 恢复上的最终状态是否一致。
- `CustomTileController`、`CoveredTileIgnoreVisible` 未找到 C# 消费者，但不能排除外部工具或配置管线使用。
