# 编辑器统计功能分析

## 概述

本文档对 TileMatch 关卡编辑器的统计功能进行分析，涵盖单关卡统计面板与批量 CSV 导出功能，并评估新增 `LevelFileName` 列的可行性。

## StatisticView 单关卡面板

单关卡统计面板（`StatisticView`）展示当前编辑关卡的 6 项核心指标：

| 序号 | 指标名称 | 说明 |
|------|----------|------|
| 1 | 关卡 ID | `LevelID`，顺序编号 |
| 2 | 牌总数 | 该关卡中所有牌的总数量 |
| 3 | 层级数 | 牌堆的层数 |
| 4 | 类型数 | 不同牌类型的种类数量 |
| 5 | 障碍数 | 关卡中包含的障碍数量 |
| 6 | 难度评估 | 系统自动评估的难度等级 |

### 面板特点

- 实时刷新：编辑器内牌局变化后自动重新统计
- 只读展示：面板仅用于查看，不支持直接编辑

## ExportCSV 批量导出

`ExportCSV` 功能支持批量导出多个关卡的统计数据为 CSV 文件。

### CSV 列结构

| 列名 | 数据类型 | 说明 |
|------|----------|------|
| `LevelID` | int | 顺序编号（非文件名） |
| `TotalTiles` | int | 牌总数 |
| `LayerCount` | int | 层级数 |
| `TypeCount` | int | 类型数 |
| `ObstacleCount` | int | 障碍数 |
| `Difficulty` | string | 难度评估 |

### 导出流程

```
选择导出范围 → 遍历关卡列表 → 逐关卡计算统计指标 → 写入 CSV → 保存文件
```

## LevelID 说明

**重要**：`LevelID` 是顺序编号，并非文件名。

- `LevelID` 由系统按顺序分配，用于内部索引和排序
- 关卡文件名存储在 `LevelConfigData.LevelName` 字段中
- 当前 CSV 导出仅包含 `LevelID`，不包含文件名信息

这导致导出 CSV 后难以直接定位到对应的关卡文件，给批量管理带来不便。

## 新增 LevelFileName 列可行性评估

### 背景

在 CSV 导出中新增 `LevelFileName` 列，使导出数据能直接对应到关卡文件。

### 可行性结论

**结论：可行，改动量极小（约 3 行代码）。**

### 改动分析

| 改动点 | 位置 | 说明 |
|--------|------|------|
| 数据模型 | `LevelConfigData` | 已有 `LevelName` 字段，**无需新增** |
| CSV 表头 | `ExportCSV` 方法 | 新增 `LevelFileName` 列名 |
| CSV 数据行 | `ExportCSV` 方法 | 读取 `LevelConfigData.LevelName` 写入对应单元格 |

### 改动示例

```csharp
// 表头新增
csvBuilder.Append("LevelID,LevelFileName,TotalTiles,LayerCount,TypeCount,ObstacleCount,Difficulty\n");

// 数据行新增 LevelName
csvBuilder.Append($"{level.LevelID},{level.LevelConfigData.LevelName},{level.TotalTiles},{level.LayerCount},{level.TypeCount},{level.ObstacleCount},{level.Difficulty}\n");
```

### 风险评估

| 风险项 | 评估 | 说明 |
|--------|------|------|
| 数据兼容性 | 无风险 | `LevelName` 字段已存在，仅读取 |
| CSV 解析兼容性 | 低风险 | 新增列在末尾，旧解析器可忽略 |
| 性能影响 | 无影响 | 仅多读一个字段 |
