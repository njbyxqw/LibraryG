# 关卡文件管理工具

> Unity 编辑器扩展，提供关卡文件的复制、迁移、冲突检测、Dry Run 预演等功能。从 v3 迭代到 v3.3，持续优化交互体验与性能。

---

## 一、功能概述

关卡文件管理工具（`LevelFileMigrationWindow`）用于在 Unity 编辑器中批量管理关卡 JSON 文件：
- **复制（Copy）**：将关卡文件从源路径复制到目标路径，支持自动重命名
- **迁移（Move）**：移动关卡文件到新路径
- **冲突检测（DetectConflicts）**：递归扫描目标路径，检测同名文件冲突
- **Dry Run 预演**：不实际执行操作，预览将要发生的变更

## 二、架构设计

### 2.1 文件结构

| 文件 | 位置 | 职责 |
|------|------|------|
| `LevelFileMigrationService.cs` | `Core/` | 业务逻辑层（复制、迁移、冲突检测、自动重命名） |
| `LevelFileMigrationWindow.cs` | `Views/` | UI 交互层（窗口绘制、用户交互） |

### 2.2 Service 层职责

```csharp
// 核心服务接口
public class LevelFileMigrationService
{
    // 自动重命名：源文件名已存在时，递增编号
    public string AutoRename(string targetPath);

    // 冲突检测：递归扫描目标目录
    public List<ConflictInfo> DetectConflicts(string sourceDir, string targetDir);

    // 执行复制/迁移
    public MigrationResult Execute(MigrationConfig config);
}
```

### 2.3 Window 层职责

```csharp
// 编辑器窗口
public class LevelFileMigrationWindow : EditorWindow
{
    // 绘制 UI、处理用户交互
    // 调用 Service 层执行实际操作
}
```

## 三、版本迭代记录

### 3.1 v3 — 核心重构

#### Service 层修复

| 问题 | 修复方案 |
|------|---------|
| **AutoRename 计数器 bug** | 重命名时计数器未正确递增，导致文件名冲突。修复为每次检测目标路径是否已存在，存在则递增编号直到可用 |
| **DetectConflicts 非递归** | 仅扫描目标目录顶层，遗漏子目录冲突。修复为递归扫描所有子目录 |

#### Window 体验优化

| 优化项 | 说明 |
|--------|------|
| 去除双层 ScrollView | 原有嵌套 ScrollView 导致滚动行为混乱，改为单层 |
| 范围选择改为数字区间 | 原有拖拽选择关卡范围操作不便，改为输入起始/结束编号 |
| 操作后保留选中状态 | 复制/迁移完成后，保持关卡列表选中状态不丢失 |
| Dry Run 预演按钮 | 新增预演功能，不实际执行，仅显示将要发生的变更 |
| Move 模式重命名状态修复 | Move 模式下重命名状态显示不正确，修复为正确显示目标文件名 |

### 3.2 v3.1 — 细节修复

| 修复项 | 说明 |
|--------|------|
| 初始不全选 | 窗口打开时默认全选所有关卡，改为默认不选 |
| 搜索框失焦修复 | 搜索框在输入后焦点丢失，修复为保持焦点 |
| 去掉 meta 文件复制 | Copy/Move 时不再复制 `.meta` 文件 |
| 去掉 GUID 重生成逻辑 | 原有 GUID 重生成逻辑不必要且可能引入问题，直接删除 |

### 3.3 v3.3 — 体验完善

| 新增/优化项 | 说明 |
|-------------|------|
| 菜单合并 | 将分散的菜单项合并到统一的菜单入口 |
| RootGroup 新增"本地关卡文件" | 在根分组中新增"本地关卡文件"选项，指向 `Assets/Game/TileV2/Config/LevelConfig` |
| 默认路径逻辑 | 首次打开取第 1 个 RootGroup 的第 1 个 LevelGroup 作为默认路径 |
| 关卡列表字号调大 | 关卡列表字体过小，调大以提升可读性 |

## 四、性能优化

### 4.1 QueryLevels 性能优化

**问题**：`QueryLevels` 使用 `StreamReader` 读取每个关卡 JSON 文件内容，再用 `Regex` 解析关卡信息，导致大量文件 I/O。

**优化方案**：删除 `StreamReader + Regex` 逻辑，改为仅通过文件名和目录结构推断关卡信息，**零文件内容读取**。

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 文件读取 | 逐个读取 JSON 内容 | 不读取文件内容 |
| 解析方式 | Regex 正则匹配 | 文件名解析 |
| 性能 | O(n) 文件 I/O | O(n) 字符串操作 |

## 五、交互流程

### 5.1 典型使用流程

```
1. 打开窗口：Tools/TileV2/关卡文件管理/关卡文件管理...
2. 选择源路径（RootGroup → LevelGroup）
3. 选择目标路径
4. 搜索/筛选关卡（可选）
5. 选择关卡（数字区间或手动勾选）
6. 选择操作模式（Copy / Move）
7. 点击 Dry Run 预演 → 查看变更列表
8. 确认无误 → 执行操作
9. 查看结果（选中状态保留）
```

### 5.2 冲突检测流程

```
执行操作前
  → DetectConflicts(sourceDir, targetDir)
    → 递归扫描目标目录
    → 对比源文件名与目标已有文件
    → 返回冲突列表
  → 有冲突：显示冲突信息，提供 AutoRename 选项
  → 无冲突：直接执行
```

## 六、关键设计决策

| 决策 | 原因 |
|------|------|
| Service/Window 分层 | 逻辑与 UI 解耦，便于测试和复用 |
| Dry Run 预演 | 批量操作前预览变更，防止误操作 |
| 去掉 .meta 复制 | Unity 会自动生成 .meta，复制反而可能导致 GUID 冲突 |
| 零文件内容读取 | 关卡信息可从文件名推断，无需读取文件内容 |
| 操作后保留选中 | 连续操作时不需要重新选择关卡 |
