## 一、打点系统架构

项目使用 **ThinkingAnalytics (数数科技)** 作为核心打点 SDK，同时集成 **AppsFlyer**、**Firebase**、**Facebook** 作为辅助分析服务。

### 架构分层

```
应用层         BI (静态门面类)
              ├── TrackEvent()          → 业务打点
              ├── TrackEventMarket()    → 市场/归因打点
              └── SetSuperProperty()    → 公共属性
                  │
路由层         ServiceHub
              ├── TrackEvent()          → Firebase + TA
              ├── TrackEventMarket()    → AF + FB + Firebase
              ├── TrackAdRevenue()      → 广告收入
              └── TrackPurchase()       → 购买行为
                  │
服务层         IServiceTrack 接口实现
              ├── ServiceThinkingAnalytics  (TA/数数)
              ├── ServiceAppsFlyer          (AF)
              ├── ServiceFacebook           (FB)
              └── ServiceFirebase           (Firebase)
```

### 核心文件

| 文件 | 说明 |
|------|------|
| `Framework/Runtime/BI/BI.cs` | 应用层入口，注册自动事件和公共属性 |
| `BettaSDK/Service/ServiceHub.TrackBase.cs` | 路由层，分发到各服务 |
| `BettaSDK/Service/Base/ServiceBase.cs` | `IServiceTrack` 接口定义 |
| `BettaSDK/Service/Services/ServiceThinkingAnalytics/` | TA 服务实现 |
| `Game/TileV2/Scripts/UILogic/Data/TaDataManager.cs` | 关卡打点管理器 |

## 五、总览

- **事件总数**：约 **70+** 个不同事件名
- **涉及文件**：约 **50+** 个 C# 文件
- **上报通道**：
  - 业务事件 → Firebase + ThinkingAnalytics
  - 市场归因事件 → AppsFlyer + Facebook + Firebase
  - 广告收入 → 全部通道
  - 购买行为 → 全部通道
- **Editor 限制**：`TA.Track()` 被 `#if !UNITY_EDITOR` 包裹，仅真机/包体上报
- **DEBUG 日志**：`ad_entrance` 事件在 DEBUG 模式下会打日志检查 `enter_id` 参数
