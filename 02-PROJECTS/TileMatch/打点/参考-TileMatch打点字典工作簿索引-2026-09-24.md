## 关卡 SQL / 逻辑常用入口

核心 Sheet 为 `关卡-1`，已登记 `lv_start`、`lv_end`、`lv_revive`、`add_moves_show`、`prop_used`、`lv_start_reconnect`、`level_loading`。开始写 SQL 前，先在同一事件块内确认：

1. 事件的上报时机与是否含公共参数；
2. `lv_id`、`lv_name`、关卡类型、进关/尝试次数等字段的数据类型和枚举；
3. 结局、复活、加步、道具字段是否属于同一局次；
4. 表内是否留下“缺失 / 类型不一致 / 待确认”等测试备注。

`关卡` Sheet 使用 `Lv_Start`、`Lv_End`、`Lv_Revive` 等命名，内容与 `关卡-1` 不可默认拼接；需先按目标版本和事件实际名称验证。

## 读表规则

工作簿采用层级行而非一行一个完整事件：事件通常在事件名列起始行，紧随的多行在属性列继续列出参数。查一个事件时，应连同该事件起始行至下一个事件起始行之间的所有属性、类型、说明和测试备注一起读取。

建议的证据顺序：**工作簿定义 → 当前代码上报位置 → TA/数数字段抽样 → SQL 结果**。其中工作簿适合说明“应该上报什么”；不替代当前运行环境的事实核验。
