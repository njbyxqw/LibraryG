# 自动化任务设计规范（v1 · 终版）

> 本文档记录「知识库同步与维护」自动化任务的完整设计逻辑与决策过程。
> 后续修改自动化或新增任务时，先检索本文档了解既有设计和约束。

---

## 一、演进过程

| 阶段 | 状态 | 说明 |
|------|------|------|
| v0 | 已废弃 | 两个独立任务：周度维护（automation-1783324340942）+ 产出同步（automation-1782901406382） |
| v1（当前） | ✅ 终版 | 合并为 `automation-1783910244457`「知识库同步与维护」，四步综合 |

**合并原因**：同步与维护是前后工序——同步搬文件进 vault，维护检查 vault 健康。分开跑导致"同步了新文件但一周后才发现缺 frontmatter"。

---

## 二、最终方案

### 基本信息

- **ID**: `automation-1783910244457`
- **名称**: 知识库同步与维护（周度）
- **频率**: 每周一 09:00
- **CWD**: `D:\LibraryG`

### 四步流水线

#### 第一步：同步产出

| 子步骤 | 逻辑 |
|--------|------|
| 去重 | 同名跳过 + vault 内容相似检测（标题+大小相近），疑似重复标记不复制 |
| 聚类 | 读文件标题/摘要/关键词 → 同一任务产物归一组（而非逐个散判） |
| 归位 | 场景一（vault 有同类→并排） / 场景二（全新任务→判定大类+建文件夹） / 场景三（遗漏→同场景一） |
| 自动 FM | 无 FM 文件自动填 type/tags/date/status/title，cat_order 留人工 |
| 周报 | 基于最近 7 天日志 + 扫描文件生成一句话摘要 |

#### 第二步：导航可用性检查（60%）

| # | 检查项 | 权重 |
|---|--------|------|
| 1 | 断链扫描 | 30% |
| 2 | MOC 导航闭环（前向可达 + 反向 `## 关联` 含 `[[_MOC]]`）| 20% |
| 3 | 链接风格（禁路径链接，只用基名）| 10% |

#### 第三步：规范合规检查（40%）

| # | 检查项 | 权重 |
|---|--------|------|
| 4 | Frontmatter（分 type 分级，自动填的不扣分）| 10% |
| 5 | cat_order（非 index 文档，三位补零+连续）| 10% |
| 6 | 命名 + 去重 | 10% |
| 7 | 零污染 | 10% |

#### 第四步：报告

- 总分 + 趋势（对比上周）+ 工作摘要 + 同步详情 + 得分表 + 待完善 + git 状态提醒 + 待办页联动

---

## 三、关键决策记录

| 决策 | 结论 | 理由 |
|------|------|------|
| 同步目标路径策略 | **AI 智能归位**，非暂存区 | AI 可读内容判断类别，参考 vault 已有同类，不应举手投降 |
| 归位判断依据 | 文件内容 + vault 结构（不查 daily logs） | 任务上下文从文件名/标题/摘要即可判定 |
| 新文件 frontmatter | **自动填可确认字段** | type/tags/date/status/title 在同步时就能确定，不必等人工 |
| 权重分配 | 导航 60% + 规范 40% | 核心目标是"链接可达"，规范是辅助 |
| 断链扫描范围 | 全 vault（`D:\LibraryG\`） | 跨项目链接（如 `03-KNOWLEDGE/`）只在全 vault 扫描时可见 |
| reference 型文档 FM 要求 | 仅需 type/tags/cat_order | reference 是速查表，title 可选 |
| index 型文档 cat_order | 豁免 | 索引页是元文件，不需要编号 |
| 同步频率 | 每周一 09:00（一次） | 原先单独同步 Wed+Fri 两次太频繁，合并后一周一次足够 |

## 四、配套规则

自动化在报告末尾联动以下系统：

| 联动对象 | 方式 |
|---------|------|
| git 状态 | 提醒上次 commit 时间 + 未追踪/未提交文件数 |
| `待办-后续事项.md` | 提示查看是否有本周可推进项 |
| `规范-知识库健康检查.md` | 检查标准（权重/验收标准/分级规则） |
| `规范-知识库文档分类标准.md` | type 判定依据（6 种类型定义） |

---

## 五、禁止事项

- ❌ 同步时替换已有文件
- ❌ 不确认就移动源文件（仅复制）
- ❌ 健康检查时修改 vault 文件
- ❌ 自动 git commit/push
- ❌ 强行归位不确定文件（放 `00-INBOX/sync/`）
