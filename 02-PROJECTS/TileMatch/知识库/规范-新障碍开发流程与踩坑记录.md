## 零、核心方法论：拼装，不是开发

> **最重要的教训**：做新障碍是在已有框架上**拼装**，不是开发新功能框架。

### 正确流程（四步法）

```
1. 找模板 → 找到最相似的已有效果（Golden/Mystery/Curtain 等）
2. 拆解它 → 读懂它的 JSON 配置 + 代码，理解它用了哪些现成的 Action/Filter/Condition
3. 拼装     → 优先用已有零件组合出目标行为
4. 补漏     → 仅当已有零件确实不够时，才写最小量的新代码
```

### 本项目的错误示范

| 步骤 | 实际做的 | 应该做的 |
|------|---------|---------|
| 1. 找模板 | 看了 Rocket 文档（攻击型，不相关） | 看 Mystery/Curtain（点击触发型 Effect） |
| 2. 拆解 | 没做 | 读懂 Mystery 的 HandleClick + HandleForwardTileClick 全链路 |
| 3. 拼装 | 全量新建 Action/Filter/Invoker/ViewAction | 先问：AddTilesToBar + 自定义 Filter 够不够？ |
| 4. 补漏 | 新建了 10 个文件 | 最多 2-3 个文件（一个 TargetFilter + JSON 配置） |

### 每次动手前的强制检查

- [ ] 已找到最相似的效果（读它的 JSON + 代码）
- [ ] 列出需要的行为 → 逐一确认框架是否已有对应 Action/Filter/Condition
- [ ] 只在确认"框架确实没有"之后才新建代码
- [ ] 新建代码时照搬最近似文件的 import / 命名空间 / using 模式

## 一、设计阶段：概念对齐

在写任何代码之前，必须明确以下核心决策：

### 1.1 载体选型：TileType vs Effect

| | TileType 障碍牌（Rocket/Volcano） | Effect 效果（Golden/Magnet） |
|---|---|---|
| 触发方式 | 本身是一张牌，点击走 AddToBar | 附加在普通牌上，点击走 EffectClick |
| 适用场景 | 需要占用棋盘格子的独立牌 | 贴在其他牌上的 Buff/效果 |
| 枚举 | `TileType = 5xxx` | `EffectType = 2xx` |
| 配置文件 | `TileConfig/Rocket.json` | `EffectConfig/Magnet.json` |

**踩坑**：Magnet 最初选了 Effect 路线——因为它的表现是"点击牌触发效果后消失"，不占格子。如果选了 TileType，就会变成一张独立牌，与设计意图不符。

### 1.2 触发机制确认

| 问题 | 选项 | Magnet 最终选择 |
|------|------|----------------|
| 触发条件 | 点击触发 / 匹配触发 / 伤害触发 | **点击触发** |
| 一次性/永久 | 触发后消失 / 可反复使用 | **一次性（Effect 销毁）** |
| Bar 容量 | 需要预留空间 / 可溢出 | **3 张同花色必消除，不占格子** |
| 不足时行为 | 不触发 / 部分触发 | **不触发（不足 2 张同花色时走正常 AddToBar）** |

### 1.3 飞行表现对齐

**踩坑**：飞行轨迹方案变更了三次：
1. ❌ 初版：BC 瞬移到 A 位置 → 被纠正"也要飞过去"
2. ❌ 第二版：BC 飞到 A 位置→依次入栏 → 用户提出"为什么要瞬移到 A 位置"
3. ✅ 最终版：A 沿贝塞尔飞向 Bar，B/C 用**弧线实时追赶** A 的移动位置，追上后锁定跟随

**关键共识**：B/C 的排序不由逻辑层预先指定，而是**谁先追上 A 谁就是 B**，动画层动态决定。

### 2.2 每层的关键注意事项

**枚举层**：
- `EffectType.cs` 注释写"只能添加, 不能修改"——必须遵守，只在末尾追加
- `ActionType.cs` 同样追加

**逻辑层（MagnetCollectAction）**：
- 实现 `IAction` 接口，不继承任何基类
- `Execute()` 通过 `enqueue(ActionResult)` 产出数据给 View 层
- **踩坑**：`TileGroup` 不在 `Tile` 实体上，要用 `tile.TileType.GetTileGroup()`
- **踩坑**：`Visibility` 不在 `Tile` 上，要用 `ctx.Board.GetAllTileListByVisibility()` 构建查找表

**桥接层（ActionInvoker）**：
- 继承 `BaseActionInvoker`，实现 `ProcessAsync(ActionResult, CancellationToken)`
- **踩坑**：`ActionResult` 在 `Game.TileV2.Scripts.GameCore.Logic.GameLogic.Behaviours.Action`，不是在 `Implementation` 子命名空间
- **踩坑**：必须加上 `[Preserve]` 特性防止代码裁剪

**视图层（ViewAction）**：
- 继承 `BaseViewAction`，实现 `DoAction(object data)`
- 用 DOTween + UniTask 做异步动画
- `EventArguments` 在 `Game.TileV2.Scripts.GameCore.Logic.GameLogic.Behaviours.Event`
- **踩坑**：`BezierUtil.NOrderBezierInterp` 接收 `List<Vector2>`，不是 `List<Vector3>`

## 三、ECA 接入：事件触发链路

### 3.1 核心理解

Effect 不会直接收到 `TileClicked` 事件！必须走框架已有的 `EffectClick` 机制：

```
TileMatchGameLogic 点击处理
  → 检查 effectData.ShouldHandleClick()  
  → 返回 true 的条件: HandleClick=true && effect 处于 Highlight 状态
  → 发布 EffectClick(effect.Id)  → 跳过正常 AddToBar 流程
  → Effect 的 ECA 行为接收 EffectClick → 执行 MagnetCollect Action
```

### 3.2 Magnet.json 关键字段

```json
{
  "Name": "Magnet",
  "Type": 202,
  "HandleClick": true,          // ← 必须！否则点牌不会触发 EffectClick
  "IsClickOccluder": false,     // 不拦截底层牌的点击
  "InitialState": 0,
  "Behaviours": [
    {
      "BehaviourId": "20201",
      "Events": [{ "EventType": "EffectClick" }],  // ← 不是 TileClicked！
      "Actions": [{ "ActionType": "MagnetCollect" }]
    },
    {
      "BehaviourId": "20202",
      "Events": [{ "EventType": "EffectDestroyed", "TargetSelector": "Self" }],
      "Actions": [{ "ActionType": "DestroyEffect", "TargetSelector": "Self" }]
    }
  ],
  "Life": { "0": 1 }            // ← 必须！否则初始化时 config.Life[effect.Form] 崩溃
}
```

### 3.3 踩坑汇总

| 问题 | 原因 | 解决 |
|------|------|------|
| 点击没反应 | ECA 订阅了 TileClicked 而非 EffectClick | Effect 收不到 TileClicked，改用 EffectClick |
| 初始化崩溃 KeyNotFound '0' | 缺少 `Life` 字段 | 所有 Effect 必须有 `"Life": { "0": N }` |
| prefab 找不到 | tileblockercfg.bytes 没更新 | 临时在 ResourceLoadService 硬编码兜底 |
| 编辑器没显示 | effecttypeconfig.bytes 没更新 | 需要在 Unity 中重新生成 .bytes 文件 |

## 四、编辑器适配：面板配置

### 4.1 三层配置体系

```
.json~ 源文件（JSON，人类可编辑）
    ↓  需要编译工具/脚本
.bytes 二进制文件（Protobuf，运行时加载）
    ↓  编辑器读取
面板显示
```

**踩坑**：这个项目中配置文件是**二元制**：
- `.json~` 是源文件（JSON 格式），人类可编辑
- `.bytes` 是编译产物（Protobuf 二进制），运行/编辑器加载

修改 `.json~` 后**必须重新编译为 `.bytes`** 才能生效。如果不知道编译工具在哪，这个步骤会成为瓶颈。

### 4.2 需要更新的配置文件

| 文件 | 作用 | 示例条目 |
|------|------|---------|
| `effecttypeconfig.json~` | 注册 Effect 基本信息和图标 | `{ "Id":3501, "BlockType":202, "Type":2, "Name":"磁铁", ... }` |
| `tileselectiongroupconfig.json~` | 将 Id 加入编��器分组 | Element 组的 GroupTypes 追加 `,3501` |
| `tileblockercfg.json~` | prefab 路径映射 | `{ "id":202, "type":2, "prefabPath":"...", "effectName":"Magnet" }` |

### 4.3 prefab 资源链路

```
编辑器放置 Effect
  → 运行时 Board.AddEffects() 创建 Effect 实体
  → TileMatchViewController.CreateEffectViewGameObject()
  → EffectViewService.CreateEffectViewFromData()
  → ResourceLoadService.LoadEffectPrefab(effectType)
  → TileAssetConfigProvider.TryGetEffectPrefabPath()
  → tileblockercfg.bytes 查询 prefabPath
  → 加载 Prefab 实例化
```

## 六、关联

## 七、v2 重写实录

> 2026-07-27: 用户 discard 了第一版全部改动，从零重写。

### 改进
- 模板从 Rocket（攻击型）换为 Mystery（点击触发型 Effect），HandleClick + EffectClick 链路一上来就对了
- 减少文件数：10+→7 新建 + 7 修改
- 不再折腾 .json~ / .bytes 编译器配置，专注逻辑+表现
- 所有 Usings 照抄最近似现有文件，避免命名空间错误

### 仍无法完全拼装的部分
- 核心逻辑（找同花色+Board→Bar）必须自定义 Action，框架没有现成的"按花色选牌入栏"
- 贝塞尔追及动画必须自定义 ViewAction，框架没有分批延时飞行动画
- 即使用拼装思路，新障碍的核心业务逻辑通常仍需要 1-2 个自定义文件

### 正确心态
做新障碍不是"不用写代码"，而是"先查框架有什么，缺什么补什么，每写一个新文件都是在必须要时才写"。
