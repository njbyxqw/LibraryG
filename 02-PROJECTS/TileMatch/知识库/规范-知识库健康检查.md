# 知识库健康检查规范

> TileMatch 知识库（Obsidian vault `02-PROJECTS/TileMatch/`）的健康检查标准与操作流程。
> 自动化：每周一 09:00 自动执行。手动触发：用户说"检查知识库""健康检查""vault 状态"时执行。

---

## 一、检查项与评分

> 检查分两组：**导航可用性（60%）**确保 AI 可通过链接层层找到文档；**规范合规（40%）**确保文档结构一致。

### 🔗 导航可用性（核心，60%）

| # | 检查项 | 权重 | 合格标准 | 检查方法 |
|---|--------|------|---------|---------|
| 1 | **断链扫描** | 30% | 全 vault wikilink 指向的文件存在（排除代码块和模板占位符） | 全 vault Grep wikilink → 逐条验证 |
| 2 | **MOC 导航闭环** | 20% | HOME.md → _MOC.md → 每篇文档可达；零孤篇；每篇文档末尾 `## 关联` 含 `[[02-PROJECTS/TileMatch/_MOC]]` | 逐级遍历 MOC 链接树 + Grep 反向关联 |
| 3 | **链接风格** | 10% | TileMatch 内禁用路径链接（`[[游戏逻辑/...]]`），只用基名 | Grep 路径模式 |

### 📋 规范合规（辅助，40%）

| # | 检查项 | 权重 | 合格标准 | 检查方法 |
|---|--------|------|---------|---------|
| 4 | **Frontmatter 合规** | 10% | 按 type 分级（见下方规则） | Grep + 值域 + 分级匹配 |
| 5 | **cat_order 合规** | 10% | 三位补零 + 文件夹内唯一 + 连续（index 豁免） | Grep cat_order → 按文件夹分组 |
| 6 | **文件命名** | 10% | 文件名符合前缀规范 | Glob → 正则 |
| 7 | **零污染** | 10% | 无内容被错误覆盖 | Grep 污染特征 |

### Frontmatter 分级规则

| type | 必填字段 | 可选字段 | 得分规则 |
|------|---------|---------|---------|
| `spec`、`analysis`、`report`、`note` | title、date、type、status、tags、cat_order | aliases | 缺 1 必填扣 1 分/文件 |
| `reference` | type、tags、cat_order | title、date、status | 缺 1 必填扣 1 分/文件 |
| `index` | title、type、tags | date、status、cat_order | 缺 1 必填扣 1 分/文件 |

### 扫描范围

| 检查项 | 范围 | 原因 |
|--------|------|------|
| 断链扫描 | **全 vault**（`D:\LibraryG\`） | 跨项目路径链接（如 `03-KNOWLEDGE/`）不在 TileMatch 目录内 |
| MOC 覆盖率 | TileMatch 目录 | 只关心 TileMatch 内部文档 |
| 其余检查项 | TileMatch 目录 | Frontmatter / cat_order / 命名 / 污染 |

### 评分等级

| 总分 | 等级 | 说明 |
|------|------|------|
| 95-100 | 🟢 优秀 | 知识库健康，无需操作 |
| 80-94 | 🟡 良好 | 少量问题，建议修复 |
| 60-79 | 🟠 警告 | 多项问题，需要修复 |
| <60 | 🔴 危险 | 严重问题，立即修复 |

## 二、操作流程

### 自动化检查（每周一 09:00）

1. Automation 触发，执行以下扫描：
   - `Grep` 扫描所有 `[[` wikilink，提取目标文件名
   - `Glob` 列出 vault 全部 .md 文件
   - `Grep` 检查每个文件的 frontmatter 字段
   - `Grep` 扫描污染特征字符串
2. 对比分析，计算各项得分
3. 输出报告到 `D:\meatloaf_client01\.workbuddy\memory\YYYY-MM-DD.md`（标记为健康检查日志）
4. 如有 🔴/🟠 级问题，在报告中列出具体文件和修复建议

### 手动检查

用户说"检查知识库""健康检查""vault 状态"时：
1. 执行与自动化相同的扫描流程
2. 输出结构化报告（表格形式）
3. 如发现问题，询问用户是否修复

## 三、修复指南

| 问题类型 | 修复方法 |
|----------|---------|
| 断链 | 确认目标文件是否存在 → 如存在则修正链接路径 → 如不存在则创建占位笔记或删除链接 |
| Frontmatter 缺失 | 补充 title/date/type/status/tags/cat_order。type 和 status 值参照 `规范-知识库文档分类标准` |
| type/status 值不合规 | 修正为合法值。中文 status→`finalized`；type 从命名前缀判断 |
| MOC 索引不同步 | 新增文件 → 在 MOC 对应章节加链接；删除文件 → 从 MOC 移除链接 |
| cat_order 不合规 | 补零修正 → 同文件夹内去重重排 → 补充顺序索引 |
| 链接路径风格违规 | 将 `[[游戏逻辑/xxx]]` 改为基名 `[[xxx]]` |
| 命名不合规 | 用 `mcp__obsidian-mcp__move_note` 重命名 → 更新所有引用该文件的 wikilink |
| 文件 misplaced | 用 `mcp__obsidian-mcp__move_note` 移动到正确目录 → 更新 MOC |
| 污染 | 从 `.workbuddy/` 产物或 `workbuddy_archives/` 恢复原始内容 |

## 四、MCP 工具使用优先级

| 操作 | 首选工具 | 降级方案 |
|------|---------|---------|
| 读取笔记 | `mcp__obsidian-mcp__read_note` | `Read` 工具 |
| 搜索 vault | `mcp__obsidian-mcp__search_vault` | `Grep` 工具 |
| 列出笔记 | `mcp__obsidian-mcp__list_notes` | `Glob` 工具 |
| 创建笔记 | `mcp__obsidian-mcp__create_note` | `Write` 工具 |
| 编辑笔记 | `mcp__obsidian-mcp__update_note` | `Edit` 工具 |
| 移动/重命名 | `mcp__obsidian-mcp__move_note` | `Bash mv` 命令 |
| 批量扫描 | `Grep` + `Glob` | MCP 不适合批量操作 |
| 行数统计 | `Bash wc -l` | 无替代 |
