# Chuzzle 关卡配置加载与生成静态审计

## 结论

运行时按关卡 ID 优先读取 authored JSON；只有找不到对应文件且 ID 不为 `1` 时，才加载程序化生成参数并按逻辑种子生成 `LevelConfig`。元素目录则随 `ConfigRuntimeConst.RuntimeFormat` 选择 JSON 或 Protobuf `.bytes`，因此仓库内 `*.json~` 只可作静态阅读参考，不能等同于运行时数据。

```text
ChuzzleModule.TryResolveLevelConfig(levelId, seed)
├─ Config/LevelConfig/{levelId}.json 存在 → Load → JSON 反序列化 LevelConfig
├─ levelId == 1 且文件缺失 → 返回错误
└─ 其他缺失 ID → 加载 ProceduralLevelGenerationConfig
                 → ProceduralLevelGenerator.TryGenerate(..., seed, ...)
```

## 文件与加载职责

| 范围 | 当前路径 / 类型 | 静态职责 |
|---|---|---|
| authored 关卡 | `Config/LevelConfig/{id}.json` | `ChuzzleLevelConfigLoader.Load` 读取，且要求 JSON 内 `LevelId` 与请求 ID 一致 |
| 最低关卡兜底 | `LevelId == 1` | authored 文件缺失即报错，不会改走程序化生成 |
| 程序化参数 | `Config/ProceduralLevelGeneration/ProceduralLevelGenerationConfig.json` | Loader 反序列化后先 `Validate()`；当前样例范围为 4–8 格、15–30 步、最多 100 次候选 |
| 元素目录 | `Config/ElementCatalog/basic|booster|obstacle.(json|bytes)` | `ChuzzleElementConfigCatalog` 按运行时格式加载、清缓存并取得 override 后的最终行，再校验全量枚举覆盖 |
| Booster 规则 | `Config/BoosterGeneration/BoosterGenerationConfig.json` | `ChuzzleBoosterGenerationLoader` 反序列化后调用编译器；配置缺失或规则诊断会中断加载 |

## LevelConfig 合同

`LevelConfig` 的核心字段为 `LevelId`、棋盘尺寸 / `CellSizeMeters`、`MoveLimit`、`ValidCells`、初盘元素与障碍组、`SpawnEntries`、全局补充花色 `RefillCandidates`、`Objectives`。

- `SpawnEntries` 可对单个入口覆盖全局花色池，并定义 `FixedSequence`；空池表示继承全局花色。
- `RefillCandidates` 在构造时经 `LevelColorRules.ResolveGlobal` 归一化；缺省值会扩展为 A–H。
- 反序列化时若发现旧字段 `EliminateObjectives` 会明确抛错，要求迁移为 `Objectives`。
- 已读 `LevelConfig/1.json` 仅作为样例：6×6、25 步、2 个目标、7 个掉落口；不是“所有关卡”的规则结论。

## 程序化生成的静态约束

生成器使用 `levelId + seed + attempt` 派生尝试状态，候选必须通过棋盘连通、初盘无未解析 Match、目标类型存在、目标/步数比例、元素目录有效性及预检。配置类还限制：首版必须四邻连通，Normal 类型数量不超过 A–H 总数，目标类型数不超过 Normal 类型数。

## 编辑器关系与验证边界

编辑器自身的类型配置也随 `ConfigRuntimeConst.RuntimeFormat` 选择 JSON 或 Protobuf 数据；这说明编辑器界面看到的数据源、正式运行时元素目录和 authored Level JSON 不能仅凭文件扩展名混为一谈。

本审计没有启动 Unity、调用 `ResourceHub`、测试 JSON/bytes 实际选择或验证程序化关卡可玩性。上述内容是源码与样例配置的静态事实；运行时格式、热更覆盖和实际生成结果仍待 Unity 验证。
