# INBOX 收件工具

当前验收边界：本机剪贴板导入、真实文件写入和本机 Codex 读取已验证。普通 Chat 一句话自动调用尚未通过，不应以本机工具测试替代。页面提供固定 Chat 说明和成功后的完整路径、执行端读取指令。需手动启动服务；无开机自启。

此目录实现“结构化输入 → 排他新建 `00-INBOX` 任务卡”的本地核心，以及桌面端收件页。生产入口同时提供 WebMCP 快捷通道和粘贴交接包的保底通道。

## 边界

- 生产调用固定写入 `/Users/dean/LibraryG/00-INBOX`。
- 不读取、列举、更新、移动或删除任何任务卡。
- 不运行命令、不访问网络、不读取 ChatGPT 凭据。
- 测试仅在系统临时目录运行，不会写入真实 INBOX。
- MCP 对调用方只公开 `create_inbox_task`；根目录、测试目录和文件操作均不可传入。


当前生产入口不是 MCP stdio：外部私有连接、tunnel 与账号设置均未启用。旧 MCP stdio 与 WebMCP D1/D2 探针已移至 [[05-ARCHIVE/Agent/INBOX收件工具-历史验证-2026-09-18/README|历史验证归档]]，不再提供运行命令或依赖。

## 当前生产入口

```bash
npm run serve:webmcp-inbox
```

此入口只监听 `127.0.0.1:38741`，固定写入 `00-INBOX/`；它没有根目录参数、读取接口或后台自启。

页面有两种等价的建卡方式：

- ChatGPT 桌面端网站工具可用时：调用唯一 `create_inbox_task`。
- 网站工具未被发现时：在 Chat 复制 JSON 任务交接包，在页面点击“从剪贴板创建”。页面只在这次点击后读取一次剪贴板；若浏览器拒绝剪贴板权限，再手动粘贴并创建。

两条路径都受“暂停自动建卡”总开关约束，都只能新建，不会读取、修改或删除现有任务。
