# 桌面端 WebMCP 生产 INBOX 接线设计

> [!warning] 已替代
> 本文保留“每卡确认 + 跨重启收据”的设计与首次真实试用记录。用户已改选 [[方案-桌面端WebMCP自动通知模式|自动通知模式]]：明确触发后写入并通知、可暂停；不再使用跨重启收据或频率上限。

## 决策摘要

D3 不增加任何工具，也不让模型拥有任何新路径或文件能力。它只是把已验证的单一 `create_inbox_task` 从临时根目录切换到固定的 `LibraryG/00-INBOX/`，并补上**短期、跨重启的重复提交收据**。

生产链路保持：

```text
用户在 Chat 中明确要求整理进 INBOX
  → Chat 形成受限任务字段并请求 create_inbox_task
  → 本机页面展示字段，用户确认 / 取消
  → localhost helper 校验、短期去重
  → 仅原子新建 00-INBOX/<日期 - 标题>.md
```

> [!warning] 尚未授权的动作
> 本文只做生产前设计。未创建真实任务卡、未新建持久收据文件、未修改 writer 的生产根目录，也未启动新的常驻服务。

> [!info] 实现状态（2026-09-17）
> 生产组件已就绪于 `02-PROJECTS/Agent/工具/INBOX收件工具/`：`persistent-task-receipt.mjs`、`webmcp-inbox-server.mjs` 和独立 `serve:webmcp-inbox` 入口。实现完成时尚未启动；`npm test` 现为 10/10，通过跨 helper 实例的 30 分钟内重放、过期后新建及生产页文案边界测试，均只使用系统临时目录。

> [!success] D3 首次真实试用（2026-09-17）
> 用户确认后，生产入口已在本机 `127.0.0.1:38742` 启动；生产页明确标注固定 `00-INBOX/` 写入边界。用户在本机确认框确认后，成功新建 [[00-INBOX/2026-09-17 - WebMCP 生产 INBOX 首次试用|WebMCP 生产 INBOX 首次试用]]，返回 `taskId: 4ad9e27a-e913-4341-87e4-58a67c566205`、`reused: false`。已静态核对该卡的 `format_version: 1`、状态、下一步和关联字段；`.inbox-receiver/` 为 Git 忽略的私有收据状态。尚未测试真实目录下的跨重启重放，也未进入日常自动试用。

## 固定边界

| 项目 | 生产规则 |
|---|---|
| 工具 | 仅 `create_inbox_task`，schema 不增加路径、文件名、读取或任务查询。 |
| 真实写入根目录 | `/Users/dean/LibraryG/00-INBOX`，写死在生产启动入口，不从页面或工具参数读取。 |
| 卡片格式 | 保持 [[04-TEMPLATES/tp-inbox-task|INBOX 任务卡模板]] 与现有 renderer 的 `format_version: 1`；不把整段聊天、浏览器 URL 或用户身份写入卡片。 |
| 授权 | 每次调用都必须经过本机页面的用户可见确认；取消在 helper 请求前终止。 |
| 返回 | 只返回 `taskId`、相对路径、创建时间和 `reused`；不返回目录内容、已有卡正文或收据内容。 |
| 网络 | 仅 `127.0.0.1`；无局域网、公网、tunnel、MCP、Obsidian REST API 或云端凭据。 |
| 生命周期 | 本机页面关闭后工具消失；helper 由用户手动启动/停止，不设登录项或后台自启。 |

## 跨进程重复提交

### 要解决的实际问题

D2 已证明同一进程中重放不会重复建卡；但重启 helper、页面重载后可能重复提交同一工具调用。生产版需要避免“网络重试或重启后立刻重复建卡”，同时不能把未来真正相同的任务永久吞掉。

### 方案：短期私有收据

helper 内部用验证后的字段计算 SHA-256 摘要，写入一个不对工具暴露的本机收据文件：

```text
/Users/dean/LibraryG/.inbox-receiver/receipts.json
```

单条收据只保存：

```json
{
  "hash": "sha256:...",
  "task_id": "...",
  "relative_path": "2026-09-17 - 标题.md",
  "created_at": "...",
  "expires_at": "..."
}
```

不保存结论、下一步、链接、聊天内容或绝对路径。收据文件应加入根目录 `.gitignore`，避免设备私有状态进入 LG Git。

### 去重窗口与语义

默认窗口为 **30 分钟**：同一验证后字段在窗口内重放，返回原结果并标记 `reused: true`；窗口结束后，允许建立一张新的同名任务卡。这把“自动重试”与“未来重新提出相同任务”区分开来。

收据读取、过期清理和更新必须用临时文件 + 原子替换完成；损坏或不可读时，生产 helper 应**拒绝写入并显示本机错误**，而不是忽略收据后冒险创建重复卡。

> [!note] 内部读取不等于对模型开放读取
> helper 需要读取自己的私有收据才能判定重放；页面和工具仍没有任何读取、列举或搜索接口。

## 生产启动模式

生产入口与测试入口分开，避免一个参数把测试根目录误切为生产目录。

| 入口 | 根目录 | 收据 | 用途 |
|---|---|---|---|
| 历史 WebMCP 探针 | 每次新建系统临时目录 | 仅进程内 | D1/D2 验证；实现已归档，不再作为可运行后退路径。 |
| `serve:webmcp-inbox` | 固定 `00-INBOX/` | `.inbox-receiver/receipts.json` | D3 受控试用。 |

生产入口启动时应明确打印“生产模式：仅新建 `00-INBOX/`”，并要求 `00-INBOX/` 已存在。它不自动创建目录，避免路径写错时在其他位置生成新目录。

## 端到端验收矩阵

| 场景 | 预期 | 写入边界 |
|---|---|---|
| 正常确认 | `00-INBOX/` 新增一张格式正确的卡。 | 仅此卡与私有收据。 |
| 页面取消 | helper 不收到 POST，零写入。 | 无。 |
| 30 分钟内重启后重放 | 返回原 ID/路径，`reused: true`。 | 不新增卡；仅收据读取。 |
| 收据过期后同输入 | 可创建新的唯一文件。 | 仅新卡与收据更新。 |
| 非法字段 / 超长正文 | 返回错误。 | 零写入。 |
| `00-INBOX/` 缺失或收据损坏 | 启动或调用失败，显示本机错误。 | 零写入。 |
| 工具尝试传路径 / 读操作 | schema 中不存在，调用失败。 | 零写入。 |

## D3 的唯一实施顺序

1. 先为私有收据位置补 `.gitignore`，但不创建收据。
2. 新增独立生产启动入口和收据模块；生产入口不接受命令行根目录覆盖。
3. 补临时目录测试：跨 helper 实例重放、收据过期、损坏收据、原子更新失败。
4. 用户审阅 diff 与实际输出格式。
5. 用户单独确认后，启动生产入口并通过页面创建**一张明确标为试用的真实 INBOX 卡**。
6. 再进行 3–5 次日常试用，才评估是否常用。

历史探针实现已归档保留，不删除其原件；当前生产收件器出现问题时停止服务并按当前方案重新评估，不把历史探针当作可运行后退路径。

## D3 仍待实证的两点

1. 普通日常对话中，模型能否稳定在用户明确说“整理进 INBOX”时选择工具，而不是由当前助手显式决定调用。
2. `00-INBOX/` 中真实卡片对用户是否足够直观，特别是状态、下一步和关联信息是否需要调整。

这两点不通过实现推断，必须在 D3/D4 的真实小样本中观察。
