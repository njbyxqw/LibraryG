# 知识库内容归属与 MOC 路由整理任务包

> 本包只落实已确认的导航和归属规则。执行时优先增补入口与状态说明，保留历史文档、原有链接和正文；不做未经确认的迁移、删除、重命名或批量改写。

## 一、已确认的规则

### 1. 任务产出

| 类型 | 主载体 | DAILY / 其他材料 |
|---|---|---|
| 持续项目任务 | 对应项目领域下的 `任务-<主题>.md`；持续记录背景、进度、设计、讨论结论、实现与验证。 | DAILY 只记录当日摘要与入口；零碎讨论回写任务主档或其子文档。 |
| 活索引 / 快速查找 | 对应项目已有索引或专题索引，边做边补。 | 仅在形成重要条目或判断时记录 DAILY。 |
| 零碎临时任务 | 默认保留在对话。 | 只有需要跨回合保存且尚未分类时才进入 INBOX；被要求整理、可复用或关联前两类时再升级。 |

代码、配置、资源及其运行产物仍放在 MT / TS 仓库；LG 保存任务入口、设计、稳定结论和可检索导航，不复制项目源码。

### 2. INBOX

`00-INBOX/` 是可选暂存区，不是每次对话必经流程。仅用于未归属的原始材料、附件、跨回合草稿或待判断的对比材料；空置是正常状态。

### 3. MOC 层级和路由

```text
AI总MOC
├─ TileMatch 总 MOC → TileMatch 模块 MOC / 辅助索引 / 任务入口
├─ TileScape 总 MOC → TileScape 模块 MOC / 辅助索引 / 任务入口
├─ 03-KNOWLEDGE/_MOC → 可迁移知识
└─ Agent/工作流/_MOC → LG 工作流、维护与规范
```

- TileMatch、TileScape 各自有独立的总 MOC。
- 障碍、GM 等是**各项目内部**的功能模块；即便概念相似，也不能合并成跨项目的同一模块 MOC。
- 项目概览、路径索引、Docs 索引、快速定位、顺序索引是辅助索引，不替代 MOC。项目总 MOC 必须先说明“什么任务进入哪个索引或模块”，让 AI 能逐级进入。
- 不创建没有真实内容的空专题 MOC；未来某项目形成对应模块材料时，再建立该项目自己的专题入口。

### 4. `03-KNOWLEDGE` 的定位

`03-KNOWLEDGE` 是**可迁移知识层**，不是项目文档的副本。

- 可放：跨项目已验证的共同机制、跨项目方法论，以及虽源自单一项目但明显可迁移的 Unity / 编辑器 / 设计方法。
- 不放：单项目专属的类、路径、配置值、功能实现、任务进度和项目事实正文。
- 允许从一个项目提炼，但必须写清“来源项目、适用范围、验证状态”，并回链项目事实。
- 写入顺序：先沉淀项目事实；确认具有复用价值后，再提炼到 Knowledge。不得为了通用而复制项目原文。
