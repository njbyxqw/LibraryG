# INBOX 对话工作区工作流

> 当前定位：仅在整理 `00-INBOX/`、处理临时对话产物或恢复旧 inbox-organizer 流程时读取；不作为日常 TS/MT 代码逻辑读取任务的必读规范。
>
> 当前收件箱的任务状态、历史留档与未归属材料见 [[00-INBOX/_MOC|00-INBOX 收件箱索引]]；该索引只做导航和分流，不替代原始任务卡与验收记录。
>
> [!note] 落点修正（2026-09-04）
> 规范/流程文档的落点已由旧的 `03-KNOWLEDGE/工作流/` 更正为 `02-PROJECTS/Agent/工作流/`，以 [[02-PROJECTS/Agent/工作流/_MOC|Agent 工作流 MOC]] 为准。

## 定位

`00-INBOX/` 是 Chat 对话产物的统一入口，包含两种对象：

1. **原始对话材料**：按 `YYYY-MM-DD-简短主题/` 文件夹保存草稿、附件和临时比对；不要求每次对话都建。
2. **可追踪任务卡**：用户明确说“整理进 INBOX”“转成待办”“把方案留档”后，在 `00-INBOX/` 根目录创建一篇 Markdown 笔记。任务卡是后续工作的入口，不是完整聊天记录，也不是自动执行授权。

只有用户主动指定入 INBOX 的结论才创建任务卡；普通对话仍不强行分类或留档。任务卡以 `type: inbox-task` 与原始材料区分，因此不需要再建第二个任务目录。

## 历史 inbox-organizer 说明

本规范定义 INBOX 的**结构**。`inbox-organizer` 是历史流程名称，不是当前默认或可假定存在的执行器；当前整理以本规范、[[02-PROJECTS/Agent/工作流/规范-任务产出入库与维护|任务产出入库与维护规范]] 和 [[02-PROJECTS/Agent/工作流/规范-任务知识沉淀闭环与自动巡检|知识沉淀闭环与自动巡检]] 为准。

- **保存原始材料时**：直接建立 `日期-主题` 文件夹，不预先分类。
- **创建任务卡时**：仅在用户明确触发后，按任务卡模板在 `00-INBOX/` 根目录新建笔记；不覆盖已有笔记，不修改项目代码。
- **个人 Plus 收件方式**：Chat 在用户明确触发后生成固定任务包；用户交给 Codex 后，由 Codex 按同一模板新建任务卡。Chat 不直接写入本机文件；未来本机快捷方式须另行试用和授权。
- **整理 INBOX 时**（你一句话触发）：检查原始材料的最终去向，以及已完成/被替代任务卡是否已回链稳定结论；移动或删除前仍须确认。

## 对话文件夹命名规范

```
格式：YYYY-MM-DD-简短主题
示例：2026-07-01-知识库分类标准
     2026-06-28-关卡花色分析
```

## 任务卡最小约定

新建任务卡时使用 [[04-TEMPLATES/tp-inbox-task|INBOX 任务卡模板]]。初始状态为 `讨论`；若 Chat 已形成方案，创建时可改为 `方案`。只有用户明确决定推进时才改为 `待办`。

```yaml
---
type: inbox-task
state: 方案
target: LG | MT | TS | 跨项目
next_owner: Chat | Codex | 用户
next_action: <下一步>
updated: 2026-09-16
---
```

任务卡状态只使用：`讨论`、`方案`、`待办`、`进行中`、`阻塞`、`完成`。细节写在 `next_owner`、`next_action` 和正文，不增加平行状态。正文使用 `当前结论`、`已知事实 / 待核实`、`下一步`、`关联`四节。

## 完整工作流

```
┌─ 对话开始 ──────────────────────────────────────────────────┐
│                                                             │
│  INBOX/<日期-主题>/   ← 建对话文件夹                          │
│       │                                                     │
│       ├── 中间产物.md        ← 对话产生的草稿、报告、分析     │
│       ├── 比对结果.md                                         │
│       └── ...                                                 │
│       │                                                     │
│       ▼  对话中形成规范/结论                                  │
│       │                                                     │
│       ├── 规范类 → 移动到 02-PROJECTS/Agent/工作流/           │
│       ├── 项目类 → 移动到 02-PROJECTS/<项目名>/               │
│       ├── 知识类 → 移动到 03-KNOWLEDGE/<主题>/                │
│       └── 日志类 → 同步到 01-DAILY/YYYY-MM-DD.md              │
│                                                             │
│  用户说“整理进 INBOX”                                        │
│       │                                                     │
│       ▼                                                     │
│  INBOX/<任务名>.md  ← 可追踪任务卡，不等于执行授权            │
│       │                                                     │
│       ├── 方案 / 待办 → 核实或执行                           │
│       └── 完成 → 回链稳定结论、实现或验证证据                 │
│                                                             │
│       ▼  对话结束                                            │
│                                                             │
│      对话文件夹处理：                                         │
│      ├── 内容已全部移动（空文件夹） → 删除                     │
│      └── 还有残留中间产物     → 归档到 05-ARCHIVE/             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 产物分类判断

| 产物类型 | 目标目录 | 示例 |
|---------|---------|------|
| 规范/流程文档 | `02-PROJECTS/Agent/工作流/` | 分类标准、同步流程 |
| 技术知识 | `03-KNOWLEDGE/<主题>/` | Unity 技巧、编辑器原理 |
| 项目文档/报告 | `02-PROJECTS/<项目名>/` | TileMatch 功能分析 |
| 日志 | `01-DAILY/YYYY-MM-DD.md` | 每日工作记录 |
| 可追踪任务卡 | `00-INBOX/<任务名>.md` | Chat 结论、下一步与后续入口 |
| 纯中间产物 | 对话结束后删除或归档 | 临时比对表、草稿 |

## 与 DAILY 的配合

- **DAILY 记录"做了什么"**：在每日笔记中记录本次对话的关键产出和决策
- **INBOX 存放"产物本身"**：对话中产生的具体文件
- **任务卡保留"继续入口"**：稳定结论进入正式文档后，任务卡保留链接与完成结果，不复制正式正文。
- **同步时机**：对话中形成结论时，立即移动产物到目标目录并更新 DAILY 日志

## 注意事项

- 产物同步默认使用**移动**（非复制），避免冗余副本
- 规范文档产出后立刻进入正式位置；任务卡保留为索引和回溯入口
- 附件统一放 `00-INBOX/attachments/`
- 如果对话文件夹在结束后非空，说明有未处理的产物
- 已完成、被替代的任务卡和历史工作区先在 `00-INBOX/_MOC` 标明为历史留档；具体移动或删除仍须用户确认。
