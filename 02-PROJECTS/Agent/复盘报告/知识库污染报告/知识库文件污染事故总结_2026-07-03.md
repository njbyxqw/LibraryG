## 根因分析

### 直接原因
Python 脚本使用 `content += ...` 追加内容时，没有正确判断文件是否已经被污染，导致污染扩散。

### 深层原因
1. **没有备份就开始批量操作** — 应该先 `cp -r LibraryG LibraryG.backup` 再操作
2. **用 Python 脚本直接改文件** — 触发了沙箱，改用 Edit 工具更安全
3. **没有先小批量测试** — 应该先试 1-2 个文件，确认无误再批量

## 经验教训

### ✅ 以后批量操作前必须做

1. **备份**
   ```bash
   cp -r D:\LibraryG D:\LibraryG.backup.2026-07-03
   ```

2. **小批量测试**
   - 先操作 1-2 个文件
   - 人工确认结果正确
   - 再批量处理

3. **用 Obsidian 原生工具**
   - 用 Obsidian CLI 的 `move` 命令（自动更新 wikilinks）
   - 或用 Edit 工具逐个处理（安全但慢）

4. **操作日志**
   - 记录批处理了哪些文件
   - 出问题时能快速定位

### ✅ 知识库维护规范

1. **命名规范**（已有，但执行不严格）
   - 分析类：`分析-{主题}-v{版本号}.md`
   - 报告类：`报告-{功能名}.md`
   - 规范类：`规范-{规范名}.md`

2. **frontmatter 规范**
   - 所有文件必须有 `type` 字段
   - 分析类必须有 `version` 字段
   - 报告类必须有 `date` 字段

3. **交叉引用规范**
   - 所有文件必须有 `## 关联` 章节（不是 `## 关联笔记`）
   - 只链强依赖/互补/层级关系
   - 不强制全链
