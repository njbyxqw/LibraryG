# 竞品调研体系建设与持续维护

## 定位与范围

2026-10-26 用户明确将竞品调研作为长期任务：以 Royal Match / Lava Quest 为首个“安装包＋运行后存储＋代码与资源对位”的完整分析范例，后续分析任一产品、模块、功能或活动时参考其任务方法和文档维护方式。这里的“首次”指新组合方法的首次实践，不否认此前 Tile Kingdom、Match Villains、Royal Match 的静态分析积累。

任务持续维护三条主线；本页是目标、状态和待办的唯一主线，不按每次对话新建任务。具体规则和代码结论仍归各产品专题。

## 长期目标与阶段交付

| 工作线 | 阶段目标 | 持续交付与验收 |
|---|---|---|
| 采集方法 | 可重复取得包内、运行缓存、下载资源与现实时间差分 | 每种方法留执行入口、样本身份、来源清单、失败/未知边界；不把读取权限等同完整可见性 |
| 模块研究 | 沿Lava范例解释具体机制、配置、分层/AB、隐藏策略与概率消费者 | 一个模块一份持续主分析；代码事实、实测和推断分开；新证据更新原章节，待验证项明确 |
| 可运行复刻 | 把经研究的内容转成可检查页面和本地流程，反过来暴露证据缺口 | Royal Match按子任务M0—M3推进；占位、实现、浏览器检查、实机对照分别记录；每批有画面/流程/差异结果 |
| 配置与排期观察 | 依据现实时间连续采样，逐步覆盖每日换期、周窗口、个人期限与复开条件 | 表格保存实际字段与候选推测；未知不填假值，有变更则更新；不存在一次采样即可“全服排期完成”的里程碑 |
| 知识维护 | 后续会话/设备能沿MOC接续，找到当前认识、证据、下一步 | 每批检查主档、模块正文、Daily、MOC/索引和附件；工程/原始大文件同步与文档同步分开核验 |

当前执行重点、逐模块顺序、完成标准和操作注意事项，以[[02-PROJECTS/产品分析/Royal Match/本地复刻/任务-系统框架与表现复刻|Royal Match长期复刻任务]]为准；总任务不重复维护其每个界面待办。2026-10-29已明确保留同一主档，避免“再建长期任务”造成多个状态源。

## 维护与交付约定

1. 新任务先读本页、方法文档、对应产品与模块入口，确认已有结论和未决项。
2. 新发现按主题进入现有主文档：补充、替换、合并或重排；同步更新受影响结论与待验证项。
3. MOC 只维护路由、覆盖状态和缺口；过程与更正记录留 Daily，方法与原始摘录留证据目录。
4. 数据、代码、资源版本分开记录；“方法可实现”“代码静态确认”“当前账号生效”“实际体验观察”分别标明。
5. 历史材料保留并标状态，当前入口只指向持续维护正文；新增主题文档必须有上级链接与回链。
6. 原始大文件留本机资产区，按 [[02-PROJECTS/产品分析/资源目录规范|资源目录规范]] 保存；不能因文档已同步就假设另一设备也有素材。
