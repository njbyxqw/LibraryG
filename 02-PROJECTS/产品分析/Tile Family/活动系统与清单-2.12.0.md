# TF 活动系统与清单

**TF 的活动应按“玩法模板—活动实例—表现主题—运营配置”分开理解。** 本轮在 `TileMatch.Activity.LiveOps.LiveEvents.*` 下识别到 **37 个顶层、名称以 LiveEvent 结尾的具体类型**。不含 `ILiveEvent`、`SampleLiveEvent` 和目录外的 `UserSurveyLiveEvent`。这是一套可复查的代码盘点口径，不是37项线上活动、37种独立玩法或全产品功能总数。

中文名称均为内部标识的说明性译名，**尚未逐项与游戏本地化名称对齐**。同一实现可能承载多个主题；这里只按实现类计数。来源为21200 metadata 类型/字段/方法、包内 Bundle/Lua，以及同版本设备缓存文件清单；具体当前开放状态未知。配置数值已补入 [[02-PROJECTS/产品分析/Tile Family/活动解锁排期与奖励配置-2.12.0]]，按具体副本和奖励组读取。

## 一、活动共用骨架

| 层 | 作用 | TF 证据 |
|---|---|---|
| 模板与实例 | 指定逻辑、期次、主题、配置组 | TemplateName/TemplateId、DupName、Guid、LoopId、UiType |
| 资格与窗口 | 预告、解锁、起止时间 | PreviewLevel、StartLevel、StartTime、EndTime |
| 资源与入口 | 资源就绪后建图标、页面与计时 | pending / runningNoRes 集合、IconEntity、ActivityEntranceController |
| 行为输入 | 关卡胜负、收集、购买、任务更新 | GameSettleResult、OnBuyProductUpdate、ActMissionUpdateData |
| 状态推进 | 活跃/非活跃/超时/关闭与存档 | LiveEventState、LiveEventStorage、LiveEventTimer |
| 奖励与商业化 | 奖励组、商品组、已领/待补发状态 | RewardGroupId、IapGroupId；通行证/收集挑战等含 Deliver/Redeliver 入口 |
| 展示 | 开始、进度、完成、领奖及返回 | OnFlowRegister、CanShow、图标点击、首页 Flow |

此分层是产品分析归纳。已核的通用控制流详见 [[02-PROJECTS/产品分析/Tile Family/系统框架与关键流程-2.12.0]]。

## 三、跨活动联动

| 上游 | 下游/二次目标 | 证据强度 |
|---|---|---|
| 关卡结果 | LiveOps 各活动＋Toy任务 | 通用分发原生调用已核 |
| BallBlitz 收集 | MissionList | `NotifyMissionListBallBlitzCollectProgress` 方法定位，完整计数条件待核 |
| Pinata 阶段 | 卡牌揭示、赛季卡册 | 绑定字段＋EnterCardReveal 原生调用；实际发包规则待核 |
| SnowstormRescue | 关内木牌收集＋故事建造任务 | 任务标识与监听字段；真实任务数量待核 |
| 活动进度 | 通行证、礼包、卡册奖励等 | 需逐模块对位；不能把全部商业化入口都当作独立玩法 |

运营设计上可据此提出“主线行为被多个目标重复计量”的判断，但哪些活动同期开、哪些奖励能相互转化尚需配置和现场样本证明。

## 四、活动研究优先级

1. **LavaQuest / SpaceRace**：共同检验报名、连胜/计分、机器人、结算与复开；与RM比较时只复用问题，不复用数值。
2. **GoldenTreasure / TilePass**：检验主线收集→任务阈值→奖励→付费轨道；核对倍率和失败是否提交。
3. **Pinata / CardCollection**：检验连胜、阶段揭示与卡册来源，概率需要完整卡池和条件分母。
4. **MultipleMerge / StoryDup / DiceMadness**：检验主线产资源、支线消费、独立界面、剩余资源清算与资源下载。
5. **PopupBundle及礼包家族**：对齐首页Flow、用户分组、触发冷却、关闭后的补排与重复展示控制。

每个活动均需区分：包内存在、配置已缓存、逻辑已选中、现场可见、实际参加、已获奖励。已完成配置解密、前两级证据和选定原生调用核验，未声称所有活动已实机验证。
