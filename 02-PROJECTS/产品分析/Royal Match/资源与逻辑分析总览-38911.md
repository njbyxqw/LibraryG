## Android 启动与 SDK 边界

应用类是 `com.safedk.android.SafeDKApplication`，Launcher 是 `com.dreamgames.library.SplashActivity`，Unity Activity 是 `com.dreamgames.library.DreamUnityPlayerActivity`。

静态启动链如下：

1. `SplashActivity.onCreate` 进入沉浸式全屏，根据 AVC 解码能力选择 1170×2532 或 888×1920 的启动视频。
2. 启动页设有约 5 秒兜底，随后调用 `launchUnity`。
3. `launchUnity` 将原 Intent 的 action、data 和 extras 传给 Unity Activity，无转场并结束自身。
4. `DreamUnityPlayerActivity.onCreate` 调用 WebView 预热；预热仅在主进程执行，并捕获异常，避免阻断启动。

Manifest 解码后共有 66 个 Activity、21 个 Service、18 个 Receiver、8 个 Provider。随包可见 SafeDK、Firebase Analytics / Crashlytics / Messaging / App Check / Sessions、AppsFlyer、Facebook、Google Play Billing / Play Games / Mobile Ads、AppLovin MAX、Unity Ads、Moloco、MBridge、Xsolla、Helpshift，以及 Samsung / Huawei 计费相关声明。这里只证明集成随包存在，不证明每项在当前地区或运行条件下启用。

## 三消与棋盘逻辑

### 基础匹配与特殊块

`MatchType` 定义六种基础颜色：Blue、Green、Red、Yellow、Pink、Orange。`PatternType` 包含 Simple、Propeller、VerticalRocket、HorizontalRocket、TShaped、LShaped、Lightball。

`MatchManager` 负责搜索棋盘图案、生成匹配组、组织收集/特殊块数据并触发消除；匹配组需要生成特殊块时进入 `SpecialItemCreator`。后者同时覆盖匹配、Booster 和 Portal 生成来源，并记录生成、任务与 Madness 相关数据。火箭方向不是简单固定：静态代码显示其可通过 `ExplodeTargetMediator.GetScore` 比较横向与纵向格子的目标得分，选择更有利的方向。

### 步数、胜负与失败链

`MoveManager` 管理剩余步数、已使用步数和秒数，连接点击、交换与 move-completed 事件。它会从 `SlbMoveConfigHelper.GetMoveAdjustment` 接收步数调整，并接入 SuperDuke；静态存在该入口，不足以证明某局实际调整了多少步。

`WinFailManager` 以目标完成为胜利条件，并组织无步数、额外步数、失败和胜利流程。静态链显示它会等待棋盘操作空闲及目标检查，再更新活动关卡状态并结束关卡；失败前还可能接入特别优惠、LavaQuest 或 AncientAdventure。具体弹窗顺序与资格仍受运行时状态控制。

### 无解检查、洗牌、下落和多棋盘

- `ShuffleManager` 使用 `PossibleMatchFinder.CheckBoard` 检查可用移动，同时排除当前已有匹配；洗牌/改色后会再次验证“无立即匹配、无 Item 冲突”，失败时回退，并可上报无可用移动。
- `BoardManager` 支持当前 Board、最终 Board 与 Board 切换，证明玩法框架具备多棋盘关卡能力。
- `FallManager` 负责直落、交叉下落、补充及顶层 Board 场景。
- `GoalManager` 区分当前/最终目标、前置条件，以及 UI/逻辑计数，并与多 Board 状态协作。

## 难度相关随机入口

`LevelRandomManager` 同时持有普通 `random` 与 `difficultyRandom`，并包含 `DifficultyNext`、难度种子、保存/恢复，以及按难度选择洗牌、列表项和 Item 的路径。这是“客户端存在难度感知随机路由”的静态证据。

当前未观察服务端参数、实验分组、运行时随机种子和最终选择结果，因此本文不把这一入口直接定性为完整 DDA，也不推断它对特定玩家或关卡的实际影响。
