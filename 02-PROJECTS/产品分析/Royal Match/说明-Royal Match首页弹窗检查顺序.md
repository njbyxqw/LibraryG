# Royal Match 首页弹窗展示策略说明

Royal Match的首页弹窗可以理解为一套**客户端固化的展示策略：按场景和内容模块组织默认检查链，再用让位规则决定哪些后续内容本轮不检查。** 系统处理、教程、活动、礼包、提醒等内容被安排在不同位置；每个模块内部也有具体的检查顺序。

这里从产品端理解“展示策略”，关注人为安排并落实在客户端的顺序与取舍，不推断是否存在外部配置表。当前已获取39781首页编排的模块和逐项顺序，以及关键跳过规则；实际是否符合资格、是否最终显示，还要经过各模块自身判断。

打开[交互图](可视化/首页弹窗优先级-39781.html)，选择“登录”“胜利”或“失败”。上方“默认检查链”保留模块顺序，右侧“让位规则”单独说明哪些条件会让后面的内容停止检查。点开模块，点击某项的“看选中后的影响”，即可分别看到同组后续项、继续检查的模块、整组跳过的模块及具体触发项；独立项通过“查看后续关系”查看，不因此新增让位规则。需要比较多个结果时，可“加入组合假设”。规则细节和原始来源保留在“展开规则详情与证据”中。

本文说明39781首页编排，不把手动点图标、关卡内续关、活动页面内部的所有弹窗排成同一个榜。

## 默认检查链和让位优先级

**检查顺序回答“先看谁”，让位优先级回答“谁选中后，哪些后面的内容不再看”。** 只有把两者一起看，才知道产品实际采用了什么展示策略。

| 层次 | 含义 | 例子 |
|---|---|---|
| 默认检查顺序 | 未触发跳过时，按什么顺序逐项检查；先检查本身不代表独占 | 登录/失败的活动组先查Lava，再查Ancient；Lava选中后仍可继续检查Ancient |
| 同组让位优先级 | 本组首个成功后，剩余候选本轮不检查 | 普通Offer选中后，阶梯、动态、外观礼包让位 |
| 跨组让位优先级 | 前一组的指定结果成立，使后面的某些组本轮不检查 | 登录活动组有成功，常规礼包、提醒和Facebook连接候选让位 |
| 独立处理位置 | 内容有自己的检查位置，但其结果不参与指定的让位判断 | 每日奖励存在，不直接使常规礼包让位 |

**默认链表示“没有触发跳过时会怎样往下检查”，不是默认把所有内容都弹一遍。** 某项自身不符合条件，与它因为前面内容选中而被跳过，是两种情况。

三种场景可概括为以下主干；每日奖励、通知、集卡、购买重试等独立内容穿插其中，具体位置见后文：

| 场景 | 默认主干 |
|---|---|
| 登录 | 教程/周榜 → 活动与指定入口 → Starfall/Journey/Team → 常规礼包 → 活动提醒 → Facebook连接 |
| 胜利 | 整千关奖励 → 活动领奖 → 活动进度 → 联盟转换与开启介绍 → 教程/周榜 → 常规礼包（Team在首位）→ 活动提醒 → Facebook连接 |
| 失败 | 失败教程/状态提示 → 活动与指定入口 → Starfall/Journey/Team → 常规礼包 → 系统消息 → 活动提醒 → Facebook连接 |

它们共用“默认链＋跳过规则”的组织方式，但**不是所有场景共用一条完全相同的链，也不是一个总开关跳过所有后续内容**。登录和失败会进入同一套活动自动检查链；胜利有自己的领奖、进度和开启介绍编排。

模块可以按系统、活动、礼包、提醒来理解，但分类名称不能单独决定顺位。同属礼包，Starfall/Journey会随活动处理，普通Offer属于常规择一组，极难关礼包则在胜利独立尾段；同属系统消息，在胜利与失败中的位置也不同。

## 组内继续检查还是停止

| 方式 | 通俗理解 | 例子 |
|---|---|---|
| 可选多个 | 前一项符合条件，记下来；继续看下一项。组内不因前项选中而停止，但整组结果仍可能使后面的组让位 | 活动自动检查、胜利领奖、胜利活动开启介绍 |
| 首个选中即停止 | 按顺序找，找到一个符合条件的就结束这组；还可能按跨组规则跳过提醒等内容 | 常规礼包、活动提醒 |
| 独立处理 | 在自己的位置检查，结果不参与指定的让位判断 | 每日奖励、部分通知、购买重试、胜利后的极难关礼包 |

**“可选多个”不表示多个窗口同时出现在屏幕上。** 它只说明本轮检查允许安排多个内容。之后还要排队、检查当时条件，再决定是否真正显示。两个活动也可能因档期、参加资格或互斥关系，根本不能在同一账号上同时满足条件。

“独立处理”也不是一定弹。例如，登录后的周榜标签提示独立于常规礼包选择，却仍会被更早的登录教程分支跳过。

本版的No Ads自动入口虽然出现在调用顺序里，实际上不安排弹窗。表里保留它的位置，不把它算成一次可见曝光。

## 登录后怎样检查

| 默认链中的位置 | 检查内容与组内顺序 | 选中后的继续检查与让位规则 |
|---|---|---|
| 前段独立内容 | 联盟状态、邀请欢迎、回流礼包、每日奖励、每日补充、登录记录、集卡；另有No Ads入口与极难关礼包标记处理 | 这些内容的存在，不直接触发后面的教程总开关 |
| 教程与周榜 | 首页教程、集中任务按钮教程、周榜活动流程 | 可选多个；规定结果成功后，好友/任务通知、活动自动检查、常规礼包、提醒，以及周榜标签/网页奖励本轮让位。未领社交奖励仍检查 |
| 通知与活动流程 | 好友推荐、Duke's Treats、Madness、每日登录任务、射箭开始、商店新活动通知 | 到达这里就按各自条件处理；不直接计入下一组活动的让位结果 |
| 活动与指定入口 | 36项活动自动检查；再看新区域、超级光球、动态礼包、远程奖励的指定入口，然后Starfall、Journey、Team礼包 | 可选多个；组内继续检查。整个组有成功，后面的常规礼包、活动提醒、Facebook连接提示本轮让位 |
| 常规礼包 | 普通Offer → 阶梯礼包 → 动态礼包 → 世界杯外观礼包 | 首个选中即停止；后面的礼包、提醒和Facebook连接提示不检查 |
| 活动提醒 | Lava → Space → Sky → Daily Lightning → Propeller → Robot → Clash → Invite | 首个选中即停止；没有选中才检查Facebook连接提示 |
| 独立尾段 | 周榜标签、网页待到账奖励、未领社交奖励 | 普通礼包成功不会一并挡住这些内容；仍需遵守前面的教程跳转和自身条件 |

这里有个容易看错的位置：**Team礼包在活动组的总判断之前就会被检查。** 不能理解成“所有活动都没有内容，才轮到Team”。

## 胜利后怎样检查

胜利后的重点是先处理这局带来的奖励和活动变化，再决定是否继续检查常规礼包。

| 默认链中的位置 | 检查内容与组内顺序 | 选中后的继续检查与让位规则 |
|---|---|---|
| 返回与奖励表现 | 必要的League、Team Battle、Kings Cup结束请求；首页恢复、邀请欢迎、Duke's Treats、Balloon Rise、皇冠/星星/金币表现及条件商店评价 | 胜利或普通奖励动画本身，不直接让常规礼包跳过 |
| 整千关奖励 | 满足条件时的整千关完成面板 | 该分支参与后面常规礼包的让位判断 |
| 每日处理 | 每日奖励、每周任务登录记录，位于整千关奖励之后、活动领奖之前 | 独立处理，不因为每日奖励出现就挡住常规礼包 |
| 活动变化 | 35项领奖；活动进度流程；联盟转换；30项收集后的活动开启介绍 | 这些组继续检查，可累计内容；其中规定的成功结果会使后面的常规礼包和提醒让位 |
| 教程与周榜 | 首页教程、倍率道具教程、周榜活动流程 | 规定结果成功，还会使好友推荐和全部区域完成提示让位 |
| 条件提示 | 好友推荐、全部区域完成提示 | 教程与周榜未选中才检查；它们不是常规礼包的让位开关 |
| 常规礼包 | Team → 普通Offer → 阶梯 → 动态 → 世界杯外观 | 前面的指定结果没有让本组让位，才开始检查；首个选中即停止 |
| 提醒与连接 | 同样的8项提醒，然后Facebook连接提示 | 提醒择一；前面的常规礼包选中则本段让位 |
| 独立尾段 | 集卡流程与自动入口、No Ads入口、远程奖励、极难关礼包、Duke's Treats按钮教程和首次冷却提示、周榜标签、购买重试、保存进度提醒、网页奖励 | 即使常规礼包被跳过，仍按顺序走到这里，各项继续查自身资格 |

**“赢了，所以礼包不弹”不是准确规则。** 更准确的是：赢了之后，如果指定领奖、进度、开启介绍或教程结果被选中，常规礼包会让位；如果这些都没有触发让位，仍然会检查礼包。

极难关礼包属于独立尾段。普通Offer没有轮到，不等于极难关礼包也不检查。

## 失败后怎样检查

失败不会直接关闭活动自动检查。

| 默认链中的位置 | 检查内容与组内顺序 | 选中后的继续检查与让位规则 |
|---|---|---|
| 失败表现与独立内容 | 首页恢复、通知、邀请欢迎、联盟/Balloon Rise表现、登录任务、射箭倍率下降、Duke's Fortune连胜下降、Ancient图标表现；商店通知、外部支付通知、每日奖励 | 按各自条件处理，不把这些动画直接当作整条活动链的阻断信号 |
| 教程与状态提示 | 集中任务按钮、射箭状态提示、Balloon Rise与Space失败教程；Mission Pursuit、Mission Control、Weekly Mission、Team Tournament、Team Battle、Team Treasure图标教程；倍率教程与周榜流程 | 可累计；规定结果成功会让好友推荐让位，后面的活动自动检查仍继续 |
| 独立超级光球流程 | 位于团队图标教程之后、倍率教程之前 | 返回结果不计入这次失败教程标记 |
| 集卡与购买 | 集卡流程、No Ads入口、购买重试 | 失败教程选中也不直接跳过这段 |
| 活动与指定入口 | 与登录一样的36项活动、4个指定入口，以及Starfall、Journey、Team | 可选多个；组内继续，最终有成功才让常规礼包及提醒等让位 |
| 常规礼包 | 普通Offer → 阶梯 → 动态 → 世界杯外观 | 首个选中即停止 |
| 系统消息 | 常规礼包全部未选中后，检查系统消息 | 系统消息选中后，活动提醒与Facebook连接提示让位 |
| 活动提醒 | Lava → Space → Sky → Daily Lightning → Propeller → Robot → Clash → Invite | 首个选中即停止；全未选中才检查Facebook连接提示 |
| 独立尾段 | 邀请缺口提示、邀请领奖、社交关卡结束处理、Duke's Treats按钮教程、周榜标签、网页奖励 | 前面礼包或提醒选中，不等于这一段也被跳过 |

失败与胜利的系统消息位置不同：**失败放在常规礼包之后；胜利包含在前面的活动进度流程里。** 因此不能给“系统消息”一个跨场景固定名次。

## 用三个问题检验理解

**活动检查中Lava被选中，Ancient还会检查吗？**

在登录/失败的自动活动组里，外层会继续走到Ancient。它能不能也选中，要看自己的资格和活动状态。活动组允许累计，不等于现实中两者一定能共存。

**普通Offer被选中，阶梯礼包还会检查吗？**

这轮常规礼包链不会再检查阶梯礼包，也不会继续到动态、外观、活动提醒和Facebook连接候选。独立尾段仍按对应场景继续。

**这次没轮到，下次回首页一定补弹吗？**

不一定。跳过的项没有因此拿到排队资格。下次相关入口走到它时，重新判断当时的已见记录、档期、资源和会话状态；它可能再次被跳过，也可能已经不符合条件。

## 为什么选中和看见是两回事

图中的“选中”表示该入口给外层的结果满足让位判断。它通常对应准备安排内容，但不能直接当作已经弹出。

普通Offer在入队之前就可能写入已见记录，后续退出或执行失败时，玩家没看见窗口，自动入口的资格却可能已经被消耗。首页教程也有特殊返回：道具解锁子流程安排了窗口和动画，外层教程仍可能返回“不触发让位”；也存在返回成功却没有新增窗口的分支。

因此，交互图的开关写的是**“假设成功”**，而不是“假设玩家看见”。它帮助解释后面的检查为什么继续或停止。
