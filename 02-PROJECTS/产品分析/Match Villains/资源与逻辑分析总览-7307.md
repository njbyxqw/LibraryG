## 图片与视觉

静态导出物显示该版本采用高饱和、精修 3D 卡通视觉，以超级英雄/反派都市题材为主。两张启动图均使用蓝紫冷色与橙色暖光形成强烈对比，其中一张带万圣节季节化表达。活动与目标图标可见 `BombHill`、`RocketRescue`、`RouteRace`、`Snitch`、`ThunderFun`、`TNT`、`BannerRoad`、Team Duel 等命名。

这只是资源层证据；图标存在不能直接证明对应活动在当前账号、地区或时间窗启用。

## 动效链路

资源层共发现 5 个 `AnimationClip`、2 个 `Animator`、2 个 `AnimatorController`。IL2CPP 代码进一步显示：

- `PowerUpItem` 使用 Spine `SkeletonAnimation`、PrimeTween、Unity Animation 和粒子效果 ID。
- 棋盘表现与逻辑动作通过交换、匹配、合并和 PowerUp 处理链组织。
- 当前只确认“能力与控制入口存在”；尚未把每个动画资源逐项回连到 Prefab、组件和实际触发条件。

## 音频

已导出 6 条本地音乐：`GJG_Spooky_Gameplay 1` 至 `5`，以及 `GJG_Spooky_Meta`。它们均为单声道 44.1 kHz，单条约 63–92 秒，总时长 508.563 秒。命名与时长支持将其归为玩法/Meta 背景音乐。

本次 Unity 基础数据与 install-time 资源包中未观察到其他 `AudioClip`，因此音效使用位置仍需远端资源检查或运行时抓取才能闭环。

## 关卡与玩法逻辑

### 棋盘主链

`SpookyMatch.Board` 中可见以下核心入口：

- `HandleSwap`
- `CheckSurroundingsForMatch`
- `ItemMatchAction`
- `ItemMergeAction`
- `AddAction_Swap`
- `AddAction_Match`
- `AddAction_Merge`

它们共同构成交换、匹配、合并与级联处理的静态主链。PowerUp 类型可见 Bomb、Rocket、Disco、Snitch 与 RocketBomb。棋盘元素类还包括 Crate、Chain、IceWall、BrickWall、Locker、FlyTrap、Mole、Octopus、Pipe、Safe、Shifter、PufferFish、EgyptianTemple、DragonCage、Water 等；这里只说明代码类型存在，不等同于当前线上关卡均使用。

### 关卡分类与规模

`LevelManager` 定义的集合包括 Default、Master、Debug、MiniGame board、spawning board、snake、police chase；`LevelType` 包括 `DEFAULT`、`HARD`、`SUPER_HARD`、`HEIST`。

共导出 5,966 个 TextAsset，其中 5,834 个为 JSON、91 个为 CSV。名称分析发现 5,587 条 `N - Level` 条目，编号覆盖 1–5200；这是资源条目数而非唯一关卡数，同一编号可能属于不同集合或变体。抽样的关卡 JSON 使用 Tiled 风格的 `layers` / `tilesets` 结构；三个同名 `1 - Level` 样本具有不同棋盘尺寸或配置，其中一个为 30 步并带 `Crate` 教学弹窗。

### 活动与卡牌配置

本地配置名称可见 BombHill、RocketRescue、SnitchChase、ThunderFun、BannerRoad、VillainRoyale，以及 `museum_break_config`、`pinata_config`、`power_cards_config` 等。

进一步按 `GameEventType` 与具体 `*EventManager` 交叉盘点，共确认 49 个具体活动管理器，分为关卡内收集杯、连胜能力、竞速榜单、长期收集、限时副玩法、任务聚合和 Pass 七类。完整活动清单、计分、阶段与奖励逻辑见 [[02-PROJECTS/产品分析/Match Villains/活动系统总览-7307|活动系统总览]]。

- `power_cards_config` 包含加步数、免费锤子、预置 Rocket/Bomb/Thunder、四向 Rocket、双倍 Booster、最后一步全盘打击、Ghost Snitch、Shuriken、Mjolnir、UFO、Double Thunder 等效果定义。
- `superthunder_config` 的本地默认值为启用、302 级开放、分数阈值 10、`server controlled = false`。
- `pinata_config` 可见 5 类 Pinata、升级概率、3/8/15 连胜阈值、金卡概率 0.3、可收集物概率 0.4。
- `museum_break_config` 可见分阶段时长和目标配置；由于当前只做静态抽样，不推断线上完整活动节奏。

## DDA 与动态关卡边界

`DefaultTetrisLevelConfig` 包含阈值 `[301, 501, 1001]`、多组带权配置、压力/缓解阈值，以及重试次数阈值 5，构成明确的本地动态难度配置证据。

代码侧 `Board.RequestDynamicTetris` 会读取 `SpooqModule.GetDdaTargetMovesRemaining`，并通过 `GetLevelDataRequest` 发送关卡 key、应用版本、平台与 replay 数据。可确认客户端存在 DDA 目标步数和动态关卡请求边界；未观察到服务器实际返回、实验分组或运行时最终选中的关卡版本，因此不能据此还原完整线上 DDA 策略。

## SDK、安全与加载边界

包内可见 Firebase Analytics / Crashlytics / Messaging / Remote Config、Adjust、Facebook、Google Play Games / Billing / Ads、AppLovin MAX、Helpshift 等集成。这里只表示随包存在，不代表每项在本次运行条件下均启用。

应用入口类为 `com.pairip.application.Application`。静态反编译显示 `attachBaseContext` 调用 `VMRunner.setContext`、`SignatureCheck.verifyIntegrity` 和 `LicenseClient.checkLicense`，随后调用父类实现。该结论用于说明包体保护边界；本次未尝试绕过完整性或授权校验。
