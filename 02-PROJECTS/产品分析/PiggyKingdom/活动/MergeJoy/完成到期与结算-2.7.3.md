# Merge Joy 完成、到期与结算

**Joy将普通关闭、领取最终大奖和最终退出分开处理。领终奖后仍留在棋盘；最终退出时补领符合条件的普通奖励，活动资源与暂存物有单独限制，不能概括为“所有剩余物品兑换”。**

本文依据Android 2.7.3／203同构建配置、托管IL和原生常量算法。已复用资源拆解任务的生命周期证据，并复核BP资格、资源过滤、空清单、暂存处理与固定补偿。属于静态消费者结论，未进行自然到期、支付或中断恢复实测。

## 1 状态及入口

| 场景 | 代码可确认的行为 | 不能据此推导的说法 |
|---|---|---|
| 活动未到期、终奖未领、当前场景仍有效时关闭 | 关闭视图，保存本期状态；没有执行整期退出结算 | 关闭面板即清盘或重新开局 |
| 首次获得终奖 | 发终奖、记录已领，展示后仍留盘并隐藏Play | 获得终奖立即强退、换盘或开始下一条主链 |
| 最后机会判定 | 活动数据仍开放，且“主链进度已达上限但终奖未领”或“基础投放余额大于0” | 任意暂存物、低阶奖励物或BP待领都会触发同一个判定 |
| 结束弹出分流 | 最后机会成立，或所属BP开放且有可领／未购买状态时，打开棋盘页收尾；否则显示结束页 | 所有结束路径都先显示BP补领奖励页 |
| 结束态按关闭 | 可先提示BP；有基础投放余额时弹Quit／Stay，无余额时继续最终退出流程 | 暂存件数也计入此处余额提示；“未购买BP”意味着可补付费奖 |
| 最终退出完成 | 记录场景完成；默认Joy没有本期下一场景，确认完成并关闭轮次；本期盘面不再继续使用 | 退出后还能重新打开同一棋盘继续处理，或残留物进入下期 |

`HasUnclaimedRewards`在此模块特指“主链到顶且终奖未领”，不能仅按方法名翻译成全部未领奖励。`IsMergePassOwned`表示BP归属当前活动；是否购买另查`IsPurchased`。

## 2 最终退出顺序

正常棋盘退出分支按条件依次处理：

1. 展示所属BP提醒；每个视图实例只拦截一次，提醒条件包含未购买。
2. 基础投放余额大于0时展示退出确认，可选择留场。
3. 确认退出后关闭棋盘，收集有资格的BP未领奖励，过滤本活动投放资源；有普通奖励才展示列表。
4. 结算棋盘可兑现奖励物；有奖励才展示列表。
5. 满足“终奖已领且退出前基础余额大于0”时，展示固定资源补偿结果。
6. 本场结束，后续一期重新建立棋盘和进度。

步骤不是每次全部出现。全资源BP方案的补领清单过滤后为空，不出现空奖励列表，也不会退回棋盘让玩家使用被过滤的资源。结束页的关闭按钮和其名为Play的按钮均调用Close，随后直接执行ExitMatches；不能将其描述为重新进入主线关卡。

### 2.1 到期后能做什么，1800秒代表什么

已经进入的Joy棋盘，投放、拖动合成与点击物品路径没有额外的时间／终奖门禁，仍受交互锁、动画锁、空格和物品条件限制。倒计时初始化未绑定完成后强退的回调。因此静态代码支持在收尾棋盘处理剩余物品；是否能再次进入需单独满足上节入口分支，不能概括为无限期开放。

模板`preserveSec=1800`由`BaseActivity.IsActivityCanOpen @0x314964c`读取，与保护时间取最大值后交给`ActivityHelper.ToActivityStatus @0x31467dc`；后者使用`end_DateTime - 秒数`进行判断。字段偏移对应`ActivityTemplate.preserveSec +0x44`及`M3SystemOpenItem.end_DateTime +0x30`。这是提前截止可开启资格的时间参数，**不是到期后延长30分钟**。活动剩余时间方法没有使用该preserveSec字段。

本次没有用上述输入路径推导主线通关产出的全部上游时间门禁。TS需求中的“到期停止新增主线资源”作为本版规则写明，不冒充本次已完整实测的Piggy行为。

## 3 各类剩余内容如何处理

| 内容 | 最终退出时的规则 |
|---|---|
| 免费BP普通奖励 | 仅补已达成、未领取的档位 |
| 付费BP普通奖励 | 同上，且必须已购买；尚未购买只可能触发提醒 |
| BP中的Joy投放资源 | 自动补领时剔除，不增加基础投放余额；对应档位仍记录已领取。退出前的常规手动领取不走此过滤 |
| 露出且可兑现的奖励物 | 只扫描棋盘可视范围内每格顶层，跳过主链；物品有直接奖励配置才发放。默认金币／道具奖励链为末级可兑现 |
| 低阶奖励物 | 不自动合成到末级，不补末级奖励，不按比例兑换 |
| 覆盖内棋子 | 不在顶层奖励扫描中，不穿透覆盖补奖 |
| 主链棋子 | 不补发未达到的进度礼包，不重复发已领礼包 |
| 暂存物 | 不参与退出奖励扫描；最终退出后不能继续使用，不跨期保留。没有证据表明CloseRound当场逐项删除存档中的暂存列表 |
| 基础投放余额，终奖未领 | 不触发拳套补偿；最终确认完成时余额归零 |
| 基础投放余额，终奖已领 | 余额大于0时固定补偿1个拳套，然后余额归零；与剩余1份或100份无关，不逐份兑换 |

固定补偿的奖励类型为`GameItemType.fist=6`，数量为`1.0`。数量采用同构建`EncryptorBase.Decrypt(float)`算法复算，不能套用整数解密算法。补偿发奖结果没有混入棋盘奖励返回列表，由后续转换提示单独表现。

## 4 解锁统计对完成判定的影响

首次解锁并非只检查“玩家合成”这一种来源：初始化格顶物品、合成产物、生成／投放物品、移除顶层后新露出的物品都可能进入解锁检查；只有配置为可拖动的物品且尚未记录时才追加记录。

- 全覆盖揭开后格顶仍为11000限制层，不会因为看见高阶图案就登记其下主链物。
- 向受限棋子拖入同级物品时，先移除限制层，检查原棋子解锁，再合成并检查新产物解锁；两个等级分别防重。
- 暂存中的物品尚未落盘，不因“存在于暂存”登记解锁；成功投放经SpawnItem检查。
- 主链进度取已登记等级的最大值。高阶物品登记不等于自动把所有低阶物品ID补进已解锁集合；BP仍按指定ID判断。

这些规则解释了预置高阶棋子、礼包与BP之间的关系，TS定稿时应明确沿用或有意调整，不能只写“所有进度一致”。
