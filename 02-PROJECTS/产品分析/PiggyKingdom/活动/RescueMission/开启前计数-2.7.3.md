# Rescue Mission开启前计数

**活动整体未开启时，通关等任务事件不计入该期，活动开启后也不会把此前通关补进来。** 活动已在后台开启、只是玩家未打开入口时，可正常累计。依据为Piggy Kingdom 2.7.3／203原包ARMv7的原生控制流；未做实机前后差分。

## 场景区分

正式开启关卡配置为 **57关**：2026-11-18及11-24保存的AutoP中，`rescue_start={"level":57,"day":1,"task_mode":1}`，`rescue_on=true`，选表`RescueConfig_3`。`RescueDM.GetUnlockLevel`（ARMv7 `0x348b268`）实际读取`AutoPRescueInfo.ReadBasicInfo.level`（字段+0x10），`GetUnlockActivityDay`读取day（+0x14）；并非从活动模板推测等级。首轮实拍入口也提示57关，与配置一致。11-24五份快照的最小字段与SHA256保存在`rescue/unlock-config-evidence.json`；未于11-25重采，day与排期等条件仍需同时满足。

| 场景 | 计数结论 | 条件与边界 |
|---|---|---|
| 本期尚未OpenRound／roundStatus≤0 | 不更新任务 | `IsOpen()`返回false，事件入口退出 |
| 活动已开启、未完成、LeftSecs>0 | 接收匹配的任务增量 | 三项同时满足才分派到Daily或普通任务实现 |
| 活动已开启但未点击入口／未看开场 | 可累计 | 事件入口不检查isViewed、IsPopup或是否正在显示救援页 |
| 整个活动已开启，后续某天或阶段未解锁 | 已生成且匹配的任务可以累计 | Daily遍历全部tasks，普通模式也遍历任务数组；当前解锁阶段用于普通模式目标完成提示，未在每个计数写入前筛掉后续任务 |
| 已完成或LeftSecs≤0 | 不更新 | 活动门禁退出 |

例：目标为完成10关，整期未开启时先打10关，不会在新一期直接变成10/10。新一期开启后，从该期新建任务与归零的本轮通关统计开始。

## 原生证据链

本机根：`D:\LibraryG\06-PRODUCT-ASSETS\PiggyKingdom\2.7.3\`。下表是原包ARMv7地址，不能用于当前安装的ARM64库。

| 环节 | 方法／地址 | 实际控制流 |
|---|---|---|
| 统一任务入口 | `RescueDM.OnChangeTask` `0x3487f6c` | 依次要求IsOpen为true、IsCompleted为false、LeftSecs≥1；之后按taskMode分派 |
| 活动开启判定 | `RescueDM.IsOpen` `0x348b2fc` | `UserInfo.roundStatus>0`，不是“用户是否打开过页面” |
| 虚调用精确核对 | metadata的RescueDM vtable | class偏移0x190→slot26→IsOpen；0x198→slot27→IsCompleted；0x160→slot20→get_LeftSecs。已按EncodedMethodIndex低位移位解码，避免仅凭调用顺序猜方法 |
| Daily模式计数 | `RescueDailyTask.OnChangeTask` `0x2cd3b30` | 遍历已生成任务；任务type匹配后用事件count增加TaskInfo.count；不以当天stage解锁状态限制写入 |
| 普通模式计数 | `RescueTask.OnChangeTask` `0x2cd7c5c` | 要有可用解锁阶段；遍历全部tasks，type匹配即count+=事件count，再按当前解锁阶段判目标跨越提示 |
| 新一期初始化 | `RescueDM.OpenRound` `0x348b514` | 新轮分支设置roundStatus=1，清零matchStartLevel和match3Levels、星星等本轮字段，选择taskMode后调用InitTasks |
| 清零指令 | `0x348b71c–0x348b72c` | 将UserInfo+0x30的matchStartLevel、+0x34的match3Levels写0 |
| 新建任务集合 | `RescueDM.InitTasks` `0x3489fe4` | 新建Task对象并生成Daily／普通任务，再写回UserInfo.task；普通GenTasks为新TaskInfo初始化，不读玩家历史通关数 |
| 单独本轮通关统计 | `RescueDM.TryReceiveLevelReward` `0x3488d74` | 有未完成任务时增加match3Levels；新一期仍由OpenRound归零，不能把跨期旧统计当新任务进度 |

开场保留分支：同一轮已开启且未完成时，`OpenRound`可走修复／保留路径，不强制重建。它是同一期恢复，不是为未开启阶段补记通关。上表“新一期清零”仅指新轮初始化分支。

## 原始材料与边界

- 原始证据：`04-ReverseEngineering/rescue/native-*.txt`、`native_evidence_index.json`、`virtual-slots.json`；提取入口为上一层`rescue-extract.py`，vtable复核脚本为`rescue/verify_slots.py`。
- 原包ARMv7 `01-Decoded/arm/libil2cpp.so` SHA256：`f2d03e18384b94369cefcc79d78a276d5e1035248308c5cd59158d83a606780d`，本次重新计算；方法定位来自同包Cpp2IL与raw metadata。
- 本次没有读取／修改设备，没有实际打10关，没有调整时钟、活动开关或账户。当前设备为同版本ARM64，不能把本次ARMv7地址写作设备地址。
- 已核任务状态门禁、数组增量与开场初始化；没有穷尽每种任务触发源、任务替换、历史兼容和服务端配置。普通通关的结论不自动覆盖其他模块自带的进度同步行为。
