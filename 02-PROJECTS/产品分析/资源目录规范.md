# 产品分析资源目录规范

> [!important] 双层结构
> 产品分析的报告、逻辑、框架、证据结论、路径索引及报告选用的配套资源保存在 `02-PROJECTS/产品分析/`。原始 XAPK/APK、批量解包/导出、下载 Bundle、反编译产物和运行时原始采集保存在当前设备 LG 的 `06-PRODUCT-ASSETS/`，属于本机原始材料区，Git 忽略、不随知识库提交。不能仅按图片/音频扩展名分类：报告选用的附件需随报告在项目目录维护，原始批量素材仍不入库。

## 固定目录

资源路径以当前设备 LG 根目录为准：Windows `D:\LibraryG`，Mac `/Users/dean/LibraryG`。下列相对结构一致，但不假设样本/工具/导出物已跨设备同步。

```text
06-PRODUCT-ASSETS/
└── <ProductName>/
    └── <Version>/
        ├── 00-Package/               原始 APK、XAPK、IPA 或安装包
        ├── 01-Decoded/               解包、反编译资源与引擎原始数据
        ├── 02-Art/                   图片、图集、动效、Prefab 等导出物
        ├── 03-Audio/                 音效、音乐及导出报告
        ├── 04-ReverseEngineering/    类结构、IL2CPP、调用和指令证据
        └── 05-Runtime/               授权范围内的运行时截图、日志和抓取结果
```

## 命名规则

- 产品目录使用稳定英文产品名，不带版本，例如 `TileKingdom`。
- 版本单独成层，例如 `1.58`；同一产品的新版本不得覆盖旧版本。
- 原始包保留产品、版本和来源标识；其他目录按内容类型命名，不重复产品名。
- 工具和跨产品复用脚本不放进单个产品资源目录，继续维护在其共享工具位置。
- 每个产品版本必须在 `02-PROJECTS/产品分析/<产品>/` 保留资源路径索引，并注明本地、远端、静态和运行时证据边界。
- `05-Runtime/` 按采集批次隔离配置、状态、下载资源与运行记录；标明设备/安装版本、时间、来源路径、查询范围及是否原子快照。原始包版本与运行版本不一致时保留各自身份和对应关系，不覆盖混装。
- 配置/状态采用必要字段白名单；不把账号凭据或无关个人资料写入稳定文档。原件与解码结果分开保留，重名资源按 Bundle＋对象 ID 区分。
- 执行流程与证据判断见 [[02-PROJECTS/产品分析/方法-竞品模块分析与持续维护|竞品模块分析方法]]；本规范负责存放规则，不重复维护工具操作教程。

## 报告随附资源（2026-10-26 用户明确）

- 选入报告用于呈现或支撑结论的配图、图表、必要音频/动效示例等，放在对应 `02-PROJECTS/产品分析/<产品>/<专题>/` 下的配套资源子目录（例如 `assets/`），由报告使用相对路径或 vault 路径引用；两端使用同一规则，不建立设备专属附件规范。
- 报告或已有资源索引记录附件用途、来源批次/版本、原始证据路径和项目内路径。Daily 只记报告与资源入口，不搬入附件正文或原始数据。
- 维护范围包括报告及配套资源的链接、文件存在性、来源对应关系、Git 跟踪/忽略状态；尚未提交或无法核验状态时明确说明，不把目录存在等同跨设备已同步。
- 只有不共享的原始材料引用在本机确实缺失时，才记“本机不可核验”。报告附件缺失、仍放在原始区或被忽略时属于具体维护缺口，不作为本机原始材料统一豁免，也不自动删链接。
- 不因本规则自动迁移历史大批素材；先列报告实际使用的附件及目标路径，保留原始材料，后续按授权处理必要附件。不改变原始区 Git 忽略，不自动 commit/push。
