# 工作内容日志同步规范

## 核心原则

DAILY 日志记录**"做了什么 + 结论是什么"**，不存放具体产物文件。
产物文件走 INBOX → 对应目标目录的流程。

## 同步时机

以下情况应立即更新当日 DAILY（`01-DAILY/YYYY-MM-DD.md`）：

| 触发事件 | 记录内容 |
|---------|---------|
| 对话产出规范文档 | 规范名称 + 存放位置 |
| 对话产出项目文档 | 文档名称 + 存放位置 |
| 关键技术决策 | 决策内容 + 理由（一句话） |
| 修复了某问题 | 问题简述 + 修复方式 |
| 对话结束 | 本次对话的主要产出摘要 |

## 日志格式

### 单项目格式

在当日 DAILY 文件中，各项目以 `## 项目名` 为一级节，节内先写一段总结再展开详情：

```markdown
## TileMatch

<一段话总结今天该项目做了什么>

### <子任务 1>
...详细记录...

### <子任务 2>
...详细记录...

---

## TileScape

<一段话总结今天该项目做了什么>

### <子任务 1>
...详细记录...
```

### 规则

- `## 项目名` 固定为二级标题，项目内三级标题自由组织
- 每节**开头必须有一段总结性文字**（做了什么 + 结论）
- 日志要**尽可能详细**，保留源码路径、参数值、决策理由、踩坑记录等
- 同项目下多个子任务用 `###` 标题区分，时间标注可选
- 如果有待办事项，在节末用 `### ⚠️ 待办` 或 `- [ ]` 注明

### 旧格式（对话维度，已废弃）

## 与 INBOX 的衔接

```
对话进行中：
  INBOX/<日期-主题>/  ← 中间产物

对话结束时：
  1. 产物移动 → 03-KNOWLEDGE / 02-PROJECTS 等
  2. 更新 DAILY 日志 ← 记录"做了什么"
  3. 清理 INBOX 对话文件夹
```

## 多项目覆盖

本规范覆盖以下项目的日志同步：

| 项目 | 源路径 | 知识库路径 |
|------|--------|-----------|
| TileMatch | `D:\meatloaf_client01\.workbuddy\memory\` | `02-PROJECTS/TileMatch/` |
| TileScape | `D:\TileScape\.workbuddy\memory\` | `02-PROJECTS/TileScape/` |

同步时，同一天不同项目的日志**合并到同一 `01-DAILY/YYYY-MM-DD.md`** 文件，按项目分节。

## 注意事项

- DAILY 不存放具体文件内容，只记录摘要和路径引用（但细节可以很详细）
- 同一天多次对话，在同一 DAILY 文件中分别追加
- DAILY 日志里的路径用相对路径（如 `03-KNOWLEDGE/工作流/xxx.md`）
- 整理 INBOX 后，Skill 自动在此追加整理记录
- 自动化同步时不修改 vault 已有内容，瓶颈修复例外（需在任务 prompt 中显式授权）

## 与 inbox-organizer Skill 的关系

本规范定义**记录什么**，`inbox-organizer` Skill 在整理完成后自动按此格式更新 DAILY。
