# TS 道具购买缺货跳商店与支付回流核对

用途：为[[02-PROJECTS/TileScape/游戏逻辑/方案-强需求道具礼包功能与美术设计|强需求道具礼包设计]]提供当前本机事实，不把方案描述当作已经实现。源码根为`D:/TileScape_fresh/`；以下路径相对该根。当前项目AGENTS指向`.cursor/rules`，旧Docs/Knowledge入口本机缺失，改沿LG代码框架索引进入实际文件。本次未取得Git版本身份，依据文件SHA-256和方法定位；不代表线上或另一设备分支。

## 已核调用链

`TileGamePanelPropController.OnPropClicked`先看`_inventory.CanConsume`；不足时进入`OnPurchaseClicked`。本机此方法打开`UIPropBuyPanel`，传ItemId和购买成功刷新回调；不是直接在局内按钮上扣款。弹窗`OnClickBuy → TryPurchaseAndClose → TileGamePanelPropBuyService.TryPurchase`。扣费失败时`RouteCurrencyShortage`只处理DIAMOND，并以null参数路由`ShopPanel`。

`RouteActionShopPanel.Execute`仅根据当前是否局内生成OpenSource；`ShopOpenContext`目前只有OpenSource。因此商店知道Home/Match，尚不知道目标道具或具体货币不足原因。单独以Match判定会把其他局内进店入口误算为本礼包场景。

库存适配`ItemSystemTileGamePanelInventory.CanConsume`使用`IItemSystem.CanUse(itemId,1)`。`ItemSystem.CanUse`先维护请求物品状态，再调用`ConsumePlanner.TryBuild`；后者先检查有效Unlimited效果，再从数量堆栈凑足需求。因此缺货不是简单的普通数量=0，尚有效的限时无限和限时数量都应纳入。礼包接入也应复用同一判定。购买弹窗的确认按钮未在自身再次检查目标库存，新增定向跳转应补点击时重查，防状态变化。

## Banner与回流

| 位置 | 静态事实 | 对设计的影响 |
|---|---|---|
| `ShopModule.CollectBannerOffers` / `CompareOfferPriority` | 收集Banner Provider，再按Priority降序 | 可复用扩展点；新礼包要成为本次明确首项，不能与其他项同优先级后依赖不稳定顺序 |
| `ShopCardBanner.Bind` | 当前索引归0，ReloadData定位0；默认3秒轮播、0.45秒切换 | 首位能力已有；强需求停留策略需新增或配置化 |
| `ShopPanelPresenter.ShowPage` | 刷新并将纵向位置设为1（顶部） | 与横向首项一并保证首次可见 |
| `ShopOpenContext` | 只有OpenSource | 缺货目标、进入原因及本次回流绑定仍需补齐 |
| `UIShopPanel.OnPurchaseSucceeded` | 仅标记本次打开期间已购买 | 不能将这个函数本身说成关闭商城的实现 |
| `ShopPanelPresenter.OnPurchaseClicked` | 经Trade购买，成功刷新，处理中/待恢复区分 | 新礼包要实际接上统一交易，不能仅拼一个购买按钮 |
| `ShopPanelPresenter.ApplyRewardPresentation` | 局内且独立商城存在时，`OnRewardPresentationCompleted=CloseOverlayShop`；阻塞飞行动画期间输入 | 已有“奖励展示结束后关商城”能力；区别于SDK支付回调立即关页 |
| `TradeRewardFulfillment` | 奖励入账与展示分离；TryShowRewards把完成回调交给奖励表现系统 | UI不重复发奖励；入账和展示失败/恢复边界继续走既有系统 |
| `TileGamePanelPropController` | AddChanged订阅四种道具，库存变化时RefreshUI | 可复用刷新，回到关卡仍应核对最终可见状态 |
| `UIPropBuyPanel.TryPurchaseAndClose` | TryPurchase为false时直接返回，不主动关购买弹窗 | 余额不足跳商城后可能仍留着这一层；成功回流必须处理 |

局内四种默认道具为撤回11、手套14、磁铁13、风车12；DIAMOND=1。ADD_SLOT=7常量存在，但默认局内四按钮定义不含它，不能仅凭常量就将第五种礼包当成可直接接入。
