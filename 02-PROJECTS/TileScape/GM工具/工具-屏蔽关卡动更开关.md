# GM 工具：屏蔽关卡动更开关

## 目的

在 `Tile` GM Tab 内切换本机动态关卡总闸门，用于在**不修改正式 FeatureSettings 配置**的情况下，验证本地关卡 JSON 与动态关卡的加载差异。

## 当前入口与调用链

```text
TileMatch.GM.cs
  -> DynamicLevelConfigManager.ToggleDynamicLevelConfigForDebug()
  -> DynamicLevelConfigUtils.SetDynamicLevelConfigDisabledForDebug()
  -> PlayerPrefs: TileV2.DisableDynamicLevelConfig
  -> DynamicLevelConfigUtils.UseDynamicLevelConfig()
  -> DynamicLevelConfigManager.GetLevelConfigJson()
  -> LevelConfigLoader.LoadLevelById()
  -> 动态内容为空时读取本地 Config/LevelConfig/<level>.json
```

| 项目 | 位置 / 事实 |
|---|---|
| GM 注册 | `Assets/Game/TileV2/Scripts/Entry/TileMatch.GM.cs`，`Tile` Tab，按钮名为“屏蔽关卡动更”，无参数；每次点击翻转一次本机屏蔽状态。 |
| 业务门面 | `Assets/Game/TileV2/Scripts/DynamicLevelConfig/DynamicLevelConfigManager.cs`；避免 Tile 入口程序集直接访问 `internal` 的 Utils。 |
| 覆盖存储 | `Assets/Game/TileV2/Scripts/DynamicLevelConfig/DynamicLevelConfigUtils.cs`，仅 `MODULE_GM` 编译下读取 `PlayerPrefs` 键 `TileV2.DisableDynamicLevelConfig`。 |
| 本地回退 | `Assets/Game/TileV2/Scripts/Config/Level/LevelConfigLoader.cs`；动态 JSON 为空后经 `TileResourceHub` 加载 `Assets/Game/TileV2/Config/LevelConfig/<level>.json`。 |
| 动态缓存 | `Application.persistentDataPath/LevelConfigCache`，与项目内本地 JSON 分离，动更不会覆盖本地文件。 |

## 已确认行为

- 关闭后，下一次新建关卡配置加载时 `UseDynamicLevelConfig()` 返回 `false`，加载器会回退本地 JSON；**不需要为了该加载分支专门重启**。
- 已进入的当前局已有内存中的 `LevelConfig`，不会被切换中途替换；应以“下次进关生效”描述。
- 开关是持久化本机状态；再次点击恢复后，后续加载重新按正式动态配置决定是否使用动更。
- 非 `MODULE_GM` 构建不读取该本机覆盖，仍由 `dynamiclevelcfg.bytes` 的正式配置控制。
- 执行后由 `DynamicLv` 日志输出最终“关卡动更开启/关闭”状态和本机屏蔽状态；不以按钮名称推断当前状态。

## 当前风险与待改进

| 状态 | 项目 | 说明 |
|---|---|---|
| 待修正 | 已请求的异步动更 | 当前点击关闭只改变总闸门，未调用 `ClearLocalCache()`；已在途 manifest 回调可能继续排入下载，旧动态缓存也会保留。建议关闭时取消请求并清理动态缓存。 |
| 已处理 | GM 文案与状态 | 命令标题为“屏蔽关卡动更”；`DynamicLv` 日志输出最终动更状态、本机屏蔽状态，以及“当前局不变、下次进关生效”。 |
| 待确认 | 构建可见性 | Android、Standalone、iPhone Player Settings 当前都有 `MODULE_GM`；若仅供测试包使用，应确认是否追加 `DEBUG || DEVELOPMENT_BUILD` 门控。 |
| 待验证 | Unity 运行 | 待确认面板命令出现、关闭后的本地加载、恢复后的动更恢复，以及请求中切换时的缓存隔离。 |

## 推荐使用与恢复

1. 在 `Tile` Tab 点击屏蔽开关。
2. 保持当前局不变，退出并重新进入目标关卡，观察本地 JSON 行为。
3. 完成后再次点击恢复，避免本机持续屏蔽动更。

> 在“关闭即清缓存”的修正完成前，不应用该工具判断在途下载是否被停止；它只能保证后续读取优先回退本地。

## 最小验证

- 命令可见：带目标构建符号的包中能打开 `Tile` Tab 并执行该命令。
- 本地回退：关闭后不重启，退出当前局再进入同一关，确认读取本地 JSON。
- 在途隔离：开始 manifest/文件请求后立刻关闭，确认缓存文件与元数据不再提交（依赖“关闭即清缓存”修正）。
- 恢复：再次开启后，确认后续关卡加载恢复正式动更逻辑。
