# TileScape GM 工具新增与使用规则

## 一句话原则

GM 只提供调试入口；业务逻辑、状态存储、校验与清理仍留在业务 owner 内。新增命令应小、可说明副作用、可定位、可验证。

## 现有机制

| 项目 | 当前规则 |
|---|---|
| 编译门控 | GM 主体受 `MODULE_GM` 控制；仅限本地测试的命令可额外使用 `(DEBUG || DEVELOPMENT_BUILD)`。最终渠道是否保留符号须按构建验证。 |
| 初始化顺序 | `GameMain.CreateModules` 先创建 `GMTools`，业务模块随后通过 `IGMSystem` 注册命令。 |
| 注册契约 | `IGMSystem.RegisterGM` 当前仅支持 0、1、2 参数。 |
| 命令归属 | 内置通用工具放 `GMTools.*.cs`；业务工具放所属模块或领域的 `*.GM.cs` / 注册方法中。禁止让 `GMTools` 反向依赖业务模块。 |
| 命令身份 | 运行时以 `Tab + Title` 去重，同名会静默替换。因此标题应稳定且同 Tab 内唯一。 |
| 面板行为 | `UIGMPanel` 打开时读取当前命令表；打开后新增的命令不会自动显示。 |

## 新增步骤

1. **确定 owner 与 Tab**：优先复用领域 Tab，例如关卡工具放 `Tile`；不要为单个命令无必要新增 Tab。
2. **先实现业务动作**：把状态改变、输入校验、缓存清理或异步取消收敛到 owner 的公开/内部业务方法，GM 回调只负责调用和输出结果。
3. **在 owner 注册命令**：安全取得 `IGMSystem`，或沿用该模块已有注入式注册方式；注册时写清标题、参数说明、默认值与是否自动关闭面板。
4. **说明副作用**：涉及 Profile、配置、缓存、下载、购买、SDK 或重启时，在命令标题、参数描述或日志中写明影响和生效时机。
5. **补专题记录**：在本目录新增“工具-<名称>.md”，写明代码路径、调用链、持久化位置、运行影响、恢复方式和验证状态，并从 `_MOC.md` 挂入口。

## 编码与使用约束

- 不要直接跨程序集访问 `internal` 工具类；应由拥有程序集暴露最小业务门面。
- 不要从 Tile 等游戏程序集调用 AOT/Module 专属能力；例如重启应经已有公共应用接口或在有依赖权的 Module owner 内处理。
- 0–2 个基础参数可直接注册。复杂/多字段输入在业务命令中以单个字符串明确解析、校验并给出错误日志；不要扩展泛型重载来绕过当前公共契约。
- 解析错误不应悄然按 `0` 继续执行；当前 GM 框架存在该限制，新增危险命令应在业务层二次校验。
- 不以标题作为长期逻辑 ID。现有框架尚无 ID 字段；若未来命令数量/自动化调用增加，再兼容性演进 `GMCommandDefinition + TryInvoke`。
- 调试状态若写入 `PlayerPrefs`，必须写清是否跨重启保留、如何恢复默认，以及其编译门控范围。

## 审核清单

- [ ] owner、Tab 与编译门控正确，且不会暴露到不应使用的渠道。
- [ ] 命令标题唯一，参数/默认值/自动关闭行为明确。
- [ ] 状态改变有输入校验、失败日志和恢复方式。
- [ ] 异步请求、缓存或文件写入具备关闭后的隔离/清理策略。
- [ ] 当前局、下次进入、重启后三种生效边界写清。
- [ ] 已补本专题文档、`_MOC.md` 和当日 Daily；Unity/真机结果与静态审计分别标注。

## 已知框架限制

- 参数上限是两个；`uint` / `ulong` 输入解析失败可能因装箱类型不匹配引发调用异常。
- 没有统一的执行结果、异常隔离、权限、命令注销或动态 UI 刷新协议。
- `Tab + Title` 的静默覆盖会掩盖重复注册；新增命令时须人工避免重名。
