# TS二合活动修改需求：Merge Joy

## 1 背景与交付范围

基于从MT迁入TS的二合活动，参考Piggy Kingdom的Merge Joy调整玩法与界面；复用现有能力，具体技术实现由程序评估。本版为圣诞主题、一周活动、Joy式弹窗、6列×8行同盘成长、待投放气泡和主链进度条，不开放独立图鉴及复杂障碍。

Joy与Merge Fantasy是后续轮换的两个独立活动。本次只交付Joy；Fantasy完整玩法与轮换排期后续单独整理。

本需求按功能拆成9份模块文档，用于分别评审、配内容、安排开发和验收。总览维护模块边界及交付进度，具体规则在对应模块中维护，不再在总览重复整套细则。本稿为功能细化稿，待产品／程序评审；正式数值、商品、排期仍需配齐。

## 4 共用口径与模块衔接

| 名称 | 定义 | 规则所在模块 |
|---|---|---|
| 主链解锁 | 主链物品首次按规定成为可操作物品；记录不随物品升级消失 | 03 |
| 主链进度 | 展示已解锁等级与后续目标，不是BP领取进度 | 04 |
| 进度礼包 | 指定等级首次解锁时自动发一次的奖励 | 04 |
| BP目标与领奖 | 目标由解锁完成，免费／付费奖励各自判断领取与权益 | 06 |
| 基础投放数量 | 可生成主链一级物品的剩余次数，每次成功投放消耗1次 | 05 |
| 暂存物 | 已产生但尚未落盘的具体物品，后进先出 | 05 |
| 待投放数量 | 基础投放数量＋暂存物件数，显示在气泡角标 | 05 |
| 奖励物 | 可继续合成并按自身条件兑现的棋盘物品，不等于奖励已到账 | 07 |
| 最终退出 | 结束本期使用资格并执行补领；不同于普通关闭 | 08 |

模块联动按以下结果对齐，不限定代码组织：

1. 通关或BP发活动资源 → 模块05数量增加 → 底部显示更新。
2. 合成成功 → 模块02检查四邻揭盖；模块03检查解锁；模块07检查本次附带产物。
3. 首次解锁 → 模块04更新对应节点并检查首次礼包；模块06更新相应BP目标，不混用领取记录。
4. 终奖已领／活动到期 → 模块08改变参与状态 → 模块01入口、模块05底部及模块06销售／领奖按各自资格更新。
5. 最终退出 → BP普通奖励补领 → 棋盘可兑现奖励 → 符合条件的固定余量补偿 → 失去本期使用资格。

## 5 本版不纳入的功能

| 类别 | 本版范围 |
|---|---|
| 独立图鉴 | 不开放页面、入口、单物品／整链收藏奖、红点及相关教学 |
| 阶段换盘／主链切换 | 不沿用六阶段领箱换盘，不增加满级后切换下一条主链 |
| 复杂生产与障碍 | 不加入农场采集、产能升级、动物喂养、冰冻计数、火焰收集、云目标及移盘 |
| 额外资源功能 | 不开放倍率投放、自然恢复、货币兑换、独立现金资源商店及独立仓库管理 |
| 其他活动外围 | 排行、点赞返奖、限时体力Buff、Pinata、饼干礼包联动不纳入 |
| 其他附加产物 | 主Merge专用奖励气泡链、普通克隆气泡及其购买、幸运产物不列入本版交付；与本版金币／道具奖励链区分 |
| 旧内容全量搬用 | 只配置本版所需主题、地图、页面与教学，不要求所有旧内容同时开放 |

“不纳入”限定本版玩家可见功能与交付范围，不要求直接删除通用底层能力。Fantasy的具体采用范围在其独立需求中确定。

## 7 整体交付验收

模块先按自身用例验收，再联调以下完整路径：

- 首页进入 → 教学投放 → 合成与揭盖 → 解锁目标 → 首次礼包和BP目标各自更新。
- 重复合成 → 奖励物落盘／满盘暂存 → 暂存优先投放 → 奖励物兑现，不重复发首次奖。
- 免费领奖／购买后补领 → 资源到账 → 关闭重进，权益、盘面及各领奖记录一致。
- 终奖留盘 → 剩余物处理 → 最终确认 → BP／盘面补领和固定补偿 → 本期不可重入。
- 自然到期 → 按资格处理或结束 → 中断恢复不重复发奖 → 下一期不继承旧盘与余量。
- 目标设备完成布局、文案、图标和点击范围验收，排除功能不出现入口或教学。

## 8 实现顺序建议

1. **Step 1：逐模块评审。** 按01～09评审范围、状态和验收点；重点分别确认04进度条与06 BP，补齐每项配置／资源输入。
2. **Step 2：完成盘面循环。** 先对齐02棋盘、03主链、05投放、07奖励物，验证一张盘可持续推进及满盘处理。
3. **Step 3：完成目标与奖励。** 接入04首次礼包与06 BP，商品配置并行准备；分别验证自动奖励、手动领取及权益。
4. **Step 4：串起入口与结束。** 联调01和08，完成终奖留盘、到期、补领、固定补偿、中断与跨期。
5. **Step 5：教学、主题与完整验收。** 09资源／文案可并行准备，最终按模块及本节完整路径验收，再回填进度表。Fantasy另立需求推进。
