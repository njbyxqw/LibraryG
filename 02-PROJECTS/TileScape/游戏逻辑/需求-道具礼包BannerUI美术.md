# TS 道具礼包 Banner UI 美术需求

图文阅读入口：[[02-PROJECTS/TileScape/游戏逻辑/TS_Prop_Banner_Art.html|UI美术需求网页]]。网页包含参考图在线入口、TS现有道具的四版本布局示意、分区标注及完整交付要求；此Markdown保留为可维护正文。

**制作一套用于商城顶部的道具礼包 Banner，包含撤回、手套、磁铁、风车四个内容版本。奖励分区沿用Prop Favor的主次关系，外观以用户最新提供的TS商城Banner为准：上方展示奖励，下方左侧礼包名称、右侧价格按钮。** 本文为V2美术提案；数量、价格和文案未定稿，均需支持动态替换。

使用场景：玩家缺少道具且货币购买不足，点击进入商城后，第一位显示对应道具礼包。玩家应先认出“这就是我需要的道具”，再看清获得数量和购买价格。功能依据：[[02-PROJECTS/TileScape/游戏逻辑/方案-强需求道具礼包功能与美术设计|强需求道具礼包设计]]。

## 1. TS样式与竞品参考的分工

**美术样式以TS截图为准。** 本版主稿参考STARTER PACK／VALUE PACK的奶油色圆润外缘、浅米灰凹陷分组、红色底栏和鲜绿按钮。顶部MEGA DISCOUNT PACK的蓝框＋橙底栏作为同一商城里的另一套样式，在网页可切换对照；两者均保留本次目标道具布局。采用哪套落版仍待评审，不能把本版默认选择当成用户已确认。顶部Banner的老鼠、礼盒和90%OFF属于特定促销主题，本礼包暂不新增。

| 参考 | 重点借鉴 | 在TS中的处理 |
|---|---|---|
| TS商城截图：本次主参考 | 现有普通礼包奶油圆框、米灰分组、红底栏、绿按钮；顶部促销蓝框、橙底栏 | 复用TS现有材质、文字描边、按钮厚度和圆角；网页提供两套现有风格对照 |
| 图1：Booster Pack | 奖励区与名称/价格底栏分开，主次清楚 | 只保留信息层级参考；其金色外框和绿色底栏不作为TS新资源制作标准 |
| 图2：Prop Favor | 左侧主推道具、中间货币、右侧混合道具；主图标明显大于其他奖励 | 只借鉴奖励分区；颜色、边框、按钮、字体均回到TS体系。目标数量建议合并到左侧，右侧只放其他三种 |

只参考两张图里的**横向礼包卡片本体**。图2上方蓝色道具购买弹窗、两图的棋盘遮罩与关闭按钮不在本次制作范围。轮播点由商城组件提供，不画进Banner底图。截图中的欧元价格、金币数量和Popular标签不作为TS已定配置。

## 2. 构图与尺寸

以现有商城容器 **1080×550 UI单位，约1.96∶1** 作为设计基准；该尺寸来自11月18日本机Prefab静态核对，最终落版需对齐接入时的商城容器。以下比例为设计起点，允许为视觉平衡微调。

| 区域 | 参考占比/位置 | 内容与要求 |
|---|---|---|
| 外框 | 四周包裹，边缘厚度约卡片宽度的2%–3% | 沿用TS普通礼包奶油色厚圆角，内沿白色高光、外沿暖米色和柔和投影；红底栏自然收口，不再整圈套亮黄色金框 |
| 奖励区 | 上部约70%高度 | 奶油浅黄底，承载目标道具、货币、其他道具三组信息 |
| 目标道具区 | 奖励区可用宽度约30%，左侧 | 大图标＋合计数量；背后少量柔光/放射光。主道具不再套一层厚重小框 |
| 货币区 | 约27%，中部 | 浅米灰圆角凹陷分组底，TS现有金币形象或货币堆，下方显示数量 |
| 附带道具区 | 约43%，右侧 | 同材质圆角分组底，三种附带道具采用“上二、下一居中”排布，各有独立数量；不为凑四格复制目标道具 |
| 底栏 | 下部约30%高度 | 沿用TS红色底栏，上沿细分隔，底部暗红体积；左侧礼包名，右侧绿色购买按钮。蓝框方案则复用现有橙底栏 |
| 购买按钮 | 底栏右侧，约占卡片宽度33%–36% | 与边框保持留白；按钮文字、边缘高光和触达范围完整，不能靠截图边缘裁切 |

视觉尺寸以图标实际可见轮廓衡量，而非PNG画布。主道具约为附带道具的1.6–1.8倍；数量不能挡住道具关键识别部位。货币堆的高度和亮度需低于主道具，避免中间重新成为唯一焦点。

## 3. 美术表现

**整体为TS现有欧卡休闲风格：圆润、明亮、有轻体积感。** 本版主稿采用TS普通礼包的“奶油圆框＋浅米灰分组＋红色底栏＋鲜绿按钮”，网页同时提供现有蓝框／橙底栏的顶部促销样式对照。两套都沿用TS现有组件，不混入竞品金边。颜色与截图中的深灰蓝商城背景同屏检查。

| 部件 | 具体要求 |
|---|---|
| 外框 | 普通样式为奶油色圆边，顶部及左侧白色柔高光；促销对照样式为TS蓝色外沿。最终直接复用对应TS资源和九宫格，不另造一套厚金框 |
| 奖励底 | 明亮但低于文字高光，允许极淡星点或几何纹理；不得覆盖数字或干扰图标轮廓 |
| 分组小底 | 浅米灰、低对比、圆角，上部内阴影＋底部浅色边缘，表现轻凹陷；分组底不能比外框更厚重 |
| 主道具 | 直接复用TS道具原图，保持造型、颜色、透视。轮廓周围轻柔光即可，不统一染金、不加稀有度材质 |
| 礼包名称 | 使用TS现有粗圆字体，奶油白字配深棕色描边及向下投影；一行优先，不挤压价格按钮 |
| 奖励数量 | 主数量最明显，附带数量沿用截图奶油白字＋深青绿色描边；统一“×N”。主数量按合计显示，不使用暗示额外赠送的“＋N” |
| 价格按钮 | 鲜绿主体、浅绿上沿高光、深绿底部厚度；正常态即有明确可点击感。价格使用截图中的奶油白粗体和深绿色描边 |
| 促销角标 | 默认不展示。暂不制作Popular、折扣百分比、原价划线或倒计时；后续若确定标签，再增加独立可隐藏组件 |

## 4. 四个内容版本与文字

四个版本仅替换标题、主图标、奖励图标顺序和数值，底板与购买按钮共用。图标来源沿用TS现有资产，正式图标映射由接入数据提供。

| 版本 | 左侧主道具 | 右侧其他道具 | 暂定名称 |
|---|---|---|---|
| 撤回 | 撤回，Item 11 | 手套、磁铁、风车 | 撤回补给 |
| 手套 | 手套，Item 14 | 撤回、磁铁、风车 | 手套补给 |
| 磁铁 | 磁铁，Item 13 | 撤回、手套、风车 | 磁铁补给 |
| 风车 | 风车，Item 12 | 撤回、手套、磁铁 | 风车补给 |

中间统一为TS当前购买货币，**视觉按用户本次TS截图中的星形金币／金币堆表现**。11月18日静态代码记录为DIAMOND、ID=1，这是代码命名与道具ID，不能据此要求美术画成蓝钻。正式接入需核对该ID的实际资源映射，直接复用截图对应的TS货币资源。本页金币图形仅为结构占位。Banner不加长段功能解释；标题、数量和价格已足够表达内容。

工作稿数量用“×N”、货币用“N”、按钮用“价格”占位。验收时另用三位道具数量、五位货币数量和较长本地化价格字符串测试空间，但这些测试值不得作为正式礼包配置。标题、图标数量、货币数量、价格均为独立可编辑元素，不烘焙进底图。

沿用功能稿的**合并数量建议**：例如主道具总计5个，则左侧只显示×5，右侧不再出现同一种道具。此项是本版排版提案，尚不代表正式奖励配置已确认；若后续采用TF分开显示的方式，需要同步调整奖励展示规则。

## 5. 交互状态与表现范围

| 状态 | 视觉处理 |
|---|---|
| 正常可买 | 所有奖励、标题、本地化价格完整可见；购买按钮最明确 |
| 按下 | 沿用TS现有按钮轻缩放/回弹与明暗反馈，文字和图标随按钮整体变化 |
| 支付处理中 | 按钮展示现有加载状态并禁止重复点击；卡片不切换目标、不换奖励 |
| 暂不可购买 | 按钮使用现有不可用状态；不显示误导性的可点击假价 |
| 购买成功 | 复用现有奖励反馈；商城关闭后局内数量刷新。本次不新增礼包开箱动画、道具施放动画 |

卡片本身不新增关闭按钮。卡片整体是否可点击沿用商城既有规范，本版明确的付费操作点为价格按钮。首次展示可有轻量柔光，但不以循环跳动或粒子遮挡数量。

## 6. 交付与验收

**美术交付：** 1套共用Banner底板、1套奖励分组底、复用或适配的购买按钮及状态、4张完整内容版本效果稿；附分层源文件和需要新增的透明PNG切图。道具、货币、字体、加载状态优先复用，交付清单区分“新增”和“复用”。

| 图层/资源 | 交付要求 |
|---|---|
| 外框与主背景 | 背景、边框按适配需要分层；可拉伸部分注明九宫格边界，四角不变形 |
| 奖励分组底 | 共用可拉伸资源；尺寸变化不造成圆角拉长 |
| 底栏 | 与上方奖励区分开，保证高度适配和按钮定位 |
| 主道具柔光 | 如新增则单独透明层，不能连同道具烘焙 |
| 图标与文本 | 单独图层；四类图标保持相同视觉基准，标题/价格/数量不能合成在PNG中 |
| 效果稿 | 同时给单卡与放入商城首屏的同屏稿；至少检查实际显示尺寸，不仅看放大稿 |

验收重点：①进店第一眼能认出目标道具；②目标总数、货币、附带道具和价格不会读混；③绿按钮与TS红色或橙色底栏保持现有对比关系；④四版本切换不跳位；⑤长文本与大数量不溢出；⑥图片中的奖励与最终配置一致。尺寸占比、颜色和文字都是本版建议，效果稿评审后再定版。

## 实现顺序建议

1. **Step1：先出手套版。** 用TS现有手套、货币及其他三种道具，完成单卡与商城首屏同屏稿；先评审构图、主次和颜色。
2. **Step2：扩展其余三版。** 保持共用底板，检查不同图标轮廓与数量排版；确认合并数量展示是否采用。
3. **Step3：切图与接入。** 输出分层、九宫格和文本/图标节点说明，复用TS购买按钮状态；正式数值和价格由配置填入。
