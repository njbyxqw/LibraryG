# 新增障碍元素开发流程

> 障碍元素（Blocker）= 不能直接匹配、需 ECA 触发销毁/变形的特殊 Tile。
> 范围：放在关卡编辑器右侧「Element / 障碍」分类、可由策划手动放置的 Tile。
> 参考样本：磁铁牌（Magnet=5210）、糖果瓶（CandyBottle=5170）、行李箱（SuitCaseHorizontal/Vertical=5130/5131）。
> 本文是「如何新增一个障碍元素」的完整三段式流程（逻辑 / 资源 / 落地），是 [[03-KNOWLEDGE/Game-Logic/任务-元素牌开发|元素牌开发任务]] 的执行手册。

---

## 0. 前置检查

| 项 | 检查方式 |
|---|---|
| `TileType` 数值未占用 | `Assets/Game/TileV2/Scripts/Config/Tile/TileType.cs` 末尾枚举区，Blocker 段从 5000 起 |
| 设计文档/数值 | `LibraryG/.workbuddy/knowledge-closure/queue/ready/KC-*.md` 或 `LibraryG/03-KNOWLEDGE/Game-Logic/` |
| 美术资源 | 占位先用现成 sprite，命名规范见 §2.2 |
| 不是「TileTypes（关卡花色）」 | 关卡花色走左侧 TypeControlView，**不在本流程** |

## 1. 逻辑层（Logic）

### 1.1 添加 `TileType` 枚举

文件：`Assets/Game/TileV2/Scripts/Config/Tile/TileType.cs`

```csharp
// 在 "障碍" 段（5000+）末尾追加
Magnet = 5210,        // 示例
NewObstacle = 5xxx,   // 新增
```

> 枚举值是 add-only，不复用、不改旧值，否则序列化/反序列化错位。

### 1.2 编写 TileConfig JSON（ECA 行为）

文件：`Assets/Game/TileV2/Config/TileConfig/<Name>.json`

```json
{
  "Name": "NewObstacle",
  "TileType": 5xxx,
  "Group": "Blocker",
  "Tags": ["Blocker"],
  "Image": "",
  "FixedSize": true,
  "MinSize": { "x": 1, "y": 1 },
  "MaxSize": { "x": 1, "y": 1 },
  "MatchCount": 0,
  "Life": { "0": 1 },
  "Behaviours": [ ... ]
}
```

`Behaviours` 常用事件/条件/动作：

| 类型 | 常用枚举 | 何时用 |
|---|---|---|
| 事件 | `TileClicked` | 玩家点击（如磁铁牌：吸牌） |
| 事件 | `TileDestroyed` | 销毁时清理（`Once:true` + `DestroyTile`） |
| 事件 | `Attack` | 受攻击时（如糖果瓶：扣血/破碎） |
| 事件 | `BarChanged` | 手牌区变化时（如磁铁牌：触发 BarMatch） |
| 条件 | `LivesAtLeast/Most` | 生命值门槛 |
| 条件 | `BarHasSpace` | 手牌区是否有空位 |
| 条件 | `VisibilityStateEquals` | 可见性过滤 |
| 动作 | 自定义 Action（如 `MagnetPull`） | 在 Action 工厂注册 |
| 动作 | `DestroyTile` | 销毁自身 |
| 动作 | `BarMatch` | 触发手牌三消 |

参考样本：`Config/TileConfig/Magnet.json`（点击触发）、`CandyBottle.json`（受击触发，含保底）、`Butterfly.json`（多变体）。

### 1.3 实现自定义 Action / Condition（必要时）

- Action 路径：`Scripts/GameCore/Logic/GameLogic/Behaviours/Action/Implementation/`；接口 `IAction.Execute`；工厂 `ActionFactory.cs`；枚举 `Config/Behaviours/Action/ActionType.cs`；标 `[Preserve]`。
- Condition 路径：`Behaviours/Condition/Implementation/`；工厂 `ConditionFactory.cs`；枚举 `Config/Behaviours/Condition/ConditionType.cs`。
- ECA 优先，规则层不依赖具体 View。

### 1.4 开局改牌 / 特殊初始化（可选）

若障碍需在 Board 初始化时动态生成（如磁铁牌 `MagnetGroupCount`），新建 `Scripts/GameCore/Logic/GameLogic/Module/Level<Name>/Level<Name>TilesInit.cs`，在 `Board.InitializeFromLevelConfig` 接入 `InvokeStrategy`；数据字段加在 `Config/Level/LevelConfig.cs`（`[JsonProperty("XxxCount")]`），编辑器面板绑定在 `Editor/LevelEditor/Script/Views/LevelConfigView/LevelConfigView.cs`。

> 注意：这条与「编辑器手动放置」是两套机制，按设计文档决定走哪条。

### 1.5 可选：Bot/Headless 模拟器 + 回放/DDA

- 模拟器：`Scripts/GameCore/Logic/GameLogic/Bot/Simulation/Simulators/<Name>MatchSimulator.cs`，仅 Bot/无头测试需要。
- 回放/DDA：受影响的 tile 修改操作若要精确复现，在 `Scripts/GameRecord/` 加操作类型，DDA 调整时调用 `Board.InvokeLevelDDA`。

## 2. 资源层（Resources）

### 2.1 准备 Prefab

路径：`Assets/Game/TileV2/Res/Game/GameCore/Prefab/TileView/<Name>/Prefab/Tile<Name>.prefab`

- 从同源基类 prefab（Rocket / Butterfly）复制，保留 transform / Collider / Animator / SpriteRenderer 骨架。
- 必备：至少一个 `SpriteRenderer`（icon）、`BoxCollider`（点击）、`Animator`；绑定到 MonoBehaviour（如 BaseTileView）的 icon / background / plainBackground 字段。

### 2.2 准备 Sprite

- 单 sprite 贴图（推荐）：`Editor/LevelEditor/Res/Texture/Tile/block_<TileType>.png`，meta `spriteMode:1`。
- 切片 spritesheet：meta `spriteMode:2` + `spriteSheet.sprites` 列表；引用**必须**用 `path.png[sprite_name]`（`AssetDatabase.LoadAssetAtPath<Sprite>` 才拿得到子 sprite）。例：`block_joker.png[block_joker_0]`。

### 2.3 注册到 `TileBlockerCfg`

文件：`Assets/Game/TileV2/Config/TileBlockerCfg/tileblockercfg.json~`（运行期对应 `.bytes`）

| 字段 | 含义 | 示例 |
|---|---|---|
| `id` | = TileType 数值 | 5210 |
| `type` | 1=Tile 障碍，2=Effect 障碍，0=暗牌 | 1 |
| `effectName` / `effectPrefabPath` | 破裂特效（无则空串） | "" |
| `prefabPath` | 自身 prefab 路径 | `Assets/.../TileMagnet.prefab` |

- 运行时 `TileAssetConfigProvider.cs` 读本表（protobuf-net），按 `id` 映射到 `TileType` 找 prefab。
- **坑**：`prefabPath` 不允许末尾空格（Excel 导出极易粘上），代码已 `?.Trim()` 兜底，但 Excel 源要去空格。
- **不需要** `TileBreakEffectCfg`（糖果瓶 5170 也无），除非显式需要破裂特效。

### 2.4 Editor 显示表：`effecttypeconfig`

源文件：`Editor/LevelEditor/Res/ExcelConfig/LevelEditorConfig.xlsx`（EffectTypeConfig sheet）

| 字段 | 取值 | 说明 |
|---|---|---|
| `Id` | 3201 起空闲号 | 与 TileSelectionGroupConfig 的 GroupTypes 关联 |
| `BlockType` | 同 TileType 数值 | 与 TileType 双向约束 |
| `Type` | 1=Tile→障碍，2=Effect | 决定生成 TileSelectionObstacle 还是 TileSelectionEffect |
| `Name` | 中文名 | "磁铁" |
| `ImagePath` | 编辑器面板图标 | 切片 sprite 用 `path.png[name]` |
| `BindTileType` | -2 | 无特殊绑定 |
| `Theme` / `Color` | 0 | 通用占位 |
| `FirstLevel` | 0 | 首次出现关卡（0=不限） |
| `Version` | 同批新增障碍版本 | 如 "1.9.1" |

**运行时产物（必须同步改）**：`Res/Config/LevelEditorConfig/effecttypeconfig.json~`（审阅源）+ `.bytes`（protobuf-net，实际读取）。

### 2.5 Editor 分组表：`tileselectiongroupconfig`

源文件：`LevelEditorConfig.xlsx`（TileSelectionGroupConfig sheet）：`GroupName`（分类标签）+ `GroupTypes`（逗号分隔的 Id 列表，引用 effecttypeconfig 的 Id）。把新障碍 Id 追加到目标分组 GroupTypes 末尾。

**同步产物**：`tileselectiongroupconfig.json~` + `.bytes`。

## 3. 落地层（Implementation）

1. **Unity 重新 import**：重生成 `.bytes` 后必须切到 Editor 焦点触发 import，否则下次 ConfigFetcher 导表读旧缓存；确认新增 prefab/sprite 的 `.meta` 已生成。
2. **编辑器验证**：打开 LevelEditor 场景 → 右侧分组出现新障碍 → 点选后棋盘可放置 → 保存后 `Level_<id>.json` 的 `Tiles` 列表出现 `TileType: 5xxx`。
3. **运行时验证**：Trial 模式进入，看 prefab 是否正确加载（LogUtil 无「未找到 prefabPath」）、ECA 触发是否符合预期、销毁/入栏动效。
4. **编辑器面板额外 UI（非必需）**：若设计要求「每关可配置 X」，在 `LevelConfigView.cs` 加 UI 字段绑到 `LevelConfig`。

## 4. 验证清单

**必做**：
- [ ] 配表 round-trip：原 `.bytes` 解码→重编码字节完全一致（证明编解码器与 protobuf-net 兼容）
- [ ] 写入后 round-trip：新 `.bytes` 再次 decode→encode 一致
- [ ] `prefabPath` 无末尾空格（`python -c "data.find(b'TileMagnet.prefab ')"` 自检）
- [ ] `ImagePath` 单 sprite 写裸路径；切片 sprite 写 `path.png[name]`
- [ ] Unity 重新 import，`.bytes` 内存里是新的
- [ ] 编辑器面板能看到、点选能放置；Trial 模式进入无 prefab 加载错误

**可选**：Bot 模拟器跑关、回放、教程（若障碍出现在引导关）。

## 5. 常见坑

| 坑 | 现象 | 规避 |
|---|---|---|
| 改 `json~` 不改 `bytes` | 运行时读旧值，编辑器不显示新条目 | `RuntimeFormat=ProtobufNet` 时两者必须同步 |
| 改 `xlsx` 不改 `json~/bytes` | 下次 ConfigFetcher 导表覆盖运行时产物 | 三份一起改 |
| `prefabPath` 末尾空格 | 找不到 prefab | Excel 检查 + 代码 `?.Trim()` 兜底 |
| 切片 sprite 写裸路径 | `LoadAssetAtPath<Sprite>` 返回空 | 写 `path.png[sprite_name]` |
| 并行多次 `Edit` 同一文件 | 后写覆盖前写 | 对同文件的 Edit 必须串行 |
| 枚举值复用/修改旧值 | 序列化错位 | 永远 add-only |
| 资源 GUID 改写 | 引用断链 | meta 文件不手改 GUID |
| 没写 `Once:true` 销毁 | 重复触发销毁行为 | `TileDestroyed→DestroyTile` 必须 `Once:true` |
