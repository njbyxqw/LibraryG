## 1. 视觉方向
以用户最新确认的“欧卡、参考 Royal Match；沿用现有画廊棕褐色书壳；背景与通用部件不绑定主题”为准。明亮饱满的休闲游戏色彩、圆润厚实的轮廓、上亮下暗的柔和体积、清晰的按钮层级。照片承担风景叙事，书壳承担收藏感。使用原创 TileScape 场景，不使用 Royal Match 的人物、商标或原始控件。

awesome-design-md 是 DESIGN.md 规范资料库，非可安装的 SKILL.md 技能。本稿采用其视觉主题、色彩角色、字体、组件、布局、层级、约束、适配的组织方法；风格以欧卡游戏 UI 为准。

## 3. 布局与字体
- 竖屏设计，单页半本书；窄左书脊，右侧仅三枚无字装饰页签。
- 主题名在页头左侧，代币在右侧，关闭热区独立，不挤压余额。
- 四图固定 2×2，单图 4:3，顺序 01/02、03/04；四图等权。
- 页脚只有上一章、下一章；无页码、无 x/4、无完成进度、无 NEW 标签。
- 标题采用粗圆体视觉，正文采用清晰黑体；白字使用轻描边与下投影保证可读性。
- 实装字体需选已授权中文粗圆体及对应多语言字体。图中标题、条件、余额均为视觉排版，不作为合图资产使用。

## 4. 图片与组件状态
| 场景 | 视觉设计 |
|---|---|
| 已解锁 | 完整彩色插画＋奶油相框＋独立题名 |
| 未解锁 | 同一原画置灰＋小锁＋条件文案；不为每张制作独立灰图 |
| 照片详情 | 单张完整横向 4:3 图，标题/短说明/左右切图/关闭 |
| 关卡条件 | 图形提示＋条件文案＋返回旅程操作 |
| 代币条件 | 代币图标、所需数量与余额分层，主次操作清晰 |
| 资源异常 | 空相框、简洁缺图图形与重试；不能用未解锁状态代替加载失败 |

详情的左右切图只对应已解锁图片。条件提示稿只提供“知道了”，不新增购买、获取代币或扣费确认规则。正式切图时须将文字、状态层、图像与背景分开。

## 6. 适配与交付边界
- 主稿为竖屏视觉设计，未做 Unity、目标机或交互验证。
- 短屏先压缩背景和书外留白，不压扁图片，不把 2×2 改为滚动长列表。
- 长屏增加上下留白；关闭、余额与底部翻章留在安全区。
- 以 390 逻辑像素宽为例，独立按钮热区至少 44×44；图内条件字建议不小于 14。
- 文案变长时换行或扩展文字区，保持 4:3 图像完整。
- 240、120、80、Level 21–30 均为草图示例，不是正式经济或关卡配置。
- PNG 是 UI 效果稿，不是可编辑 PSD/Figma，也不是可直接使用的 Unity 切图。
- 场景合图是 UI 概念样张，不等于已完成 24 张 2048×1536 分层原画。

## 7. 实现顺序建议
Step1：评审主界面及跨章节对照，确认画廊棕褐色书壳、通用蓝灰背景、照片占比与按钮层级。
Step2：确认照片详情与解锁弹窗的布局，策划补全条件及代币是否消耗。
Step3：美术按确认稿制作分层源文件；拆分书壳、纸页、相框、角贴、页签、代币、关闭、翻章和状态层。
Step4：核实六章实际地图后绘制正式逐章四图；统一命名与本地化文案配对。
Step5：未来接入阶段再验收短/长屏、安全区、资源异常和重进回看；本次仅交付视觉设计。
