## 一、关卡替换对照表工具

### V1 — 初始构建

**功能**

- 操作列三态：待处理(替换/跳过按钮) → 已替换(绿色标签) → 已跳过(黄色标签)

**阈值默认值数据校订**

## 二、关卡数据对比工具

> 存档：`02-PROJECTS/TileMatch/工具/数据对比/报告-关卡数据对比工具.md`

### V2 — 对比框架搭建

**架构设计**
- 从 V1 框架派生，去掉候选匹配和替换操作
- 两组数据独立 6 维评分 → 按 Level ID 匹配 → 逐关双列对比
- 数据流：`scoreDataset(datasets[0])` + `scoreDataset(datasets[1])` → `map0 / map1` → `levels[]`
- 三工具不合并：V3 分析→V1 替换是串行流程，V2 对比是独立验证场景，语义不兼容

**对比列设计**
- Level / 质量分V1 / 质量分V2 / Δ / 流失V1→V2 / 难度V1→V2 / 变异V1→V2 / 改善指标
- 5 种排序：Δ绝对值降序 / 改善最大在前 / 质量分V1降序 / 质量分V2降序 / Level 升序
- 筛选：改善(Δ≥15) / 恶化(Δ≤-15) / 全部

**标签体系重构**
- 恢复基础标准+进阶标准 6 项阈值面板（最初误删，经讨论后恢复）
- 标注列改为双版本显示：`V1:⚠流失 ⚠偏难 → V2:—`
- 分类从 Δ 驱动改为标签驱动：已修复(V1有标签→V2无) / 改善未修复(V1V2均有) / 新问题(V2新增标签)
- 去掉"改善指标"列，被标注列取代

**六个对比指标评估**
- 流失率：标签最可靠，无歧义
- 难度/变异：阈值外两个都标，需看 Δ 辅助判断
- 人均消耗：方向反转——替换工具"低=问题"，对比里消耗↑是改善
- 复活转化：弱信号——转化低可能是关太简单不需要复活
- 失败剩余率(首次)：越小越好，改用 `首次失败剩余率` 列

### V3 — 自定义指标 + 持久化

**自定义对比指标**
- 参考 V3 分析工具的 `toggleMetricDropdown` 模式
- 上传后 `scanColumns()` 扫描 Excel 列名，过滤 `_r_` 前缀（解析时产生的原始值副本）
- `autoDir()` 自动方向判断：含"流失/变异/难度/死局/退出/剩余"关键词 → ↓越低越好
- 权重面板下方 `＋ 添加对比指标` → 点击弹出下拉列表 → 选中添加
- 问题 1：下拉点击无反应 → `addCustom()` 里调用了不存在的 `renderWeightConfig()`，ReferenceError 静默吞掉
  修复：去掉调用，改为直接关下拉
- 问题 2：添加后数据显示为 — → `getVal()` 从评分对象查 `_cm_` 前缀的 key，但评分对象只含 6 个内置字段
  修复：改为从原始 `datasets` 按 Level ID 查找自定义列的值
  最终方案：分析时把自定义列值嵌入 `level` 对象的 `_cm0/_cm1` 字段，渲染和 CSV 直接从 level 读取
- 问题 3：恢复后下拉显示"所有指标已添加" → `availCols` 未存入 localStorage
  修复：`saveState()` 加 `ac:availCols`
- 按钮 UI：从权重面板移到关卡列表筛选栏独立一行，下拉栏 `min-width:220px`

**localStorage 持久化**
- `saveState()`：分析完成后存 levels / weights / thresholds / customMetrics / availCols / filenames
- `restoreState()`：页面加载时自动恢复，若 levels 有数据直接渲染表格
- 性能优化：不存原始 datasets（57 列 × 500 行 × 2 ≈ 几 MB JSON），只存分析结果 ~50KB
- 清除缓存按钮：`localStorage.removeItem + location.reload()`
- 阈值 6 项全部持久化

**列宽优化**
- `table-layout:fixed`：Level 56px / 质量分 64px / Δ 40px / 标注 150px(可换行) / 其余列自适应
- 对比指标 checkbox 独立一行，按钮不挤

**运行时错误修复**
- `bs.forEach` ReferenceError：`bs` 数组声明在 381 行但 372 行就用了，var 提升后值为 undefined
  修复：挪声明到使用前
- `r0/r1` ReferenceError：summary 面板用了 map 回调内部的局部变量

## 四、命名规范与迭代教训

**命名规范（最终）**
```
工具名.html          ← 活跃版，不加版本号
工具名_vN.html       ← 版本快照，大改动前保存
工具/XX/报告-工具名.md ← Obsidian 笔记，单文件记录所有版本
```

**本次迭代教训**
1. 桌面同步是最大的混乱源头——只维护工作区原文件
2. 文件名/title/顶栏/CSV下载名必须四层一致，改一处就要改所有
3. 涉及文件操作时每次回复开头报文件名，避免用户打开错误文件
4. 大改动前先 cp 版本快照，删文件前三思
5. JS 变量声明在使用前，var 提升是隐形坑
6. 单 HTML 文件内函数重名静默报错很难排查，加 try/catch 兜底
7. localStorage 不要存原始数据集，只存分析结果

## 六、关卡数据集成工具 V1（三工具合并）

> 本地文件：`local_py_script/关卡数据集成工具.html`（1552 行 / 67KB）
> 分析文档：`02-PROJECTS/TileMatch/工具/分析-三工具功能梳理与集成建议.md`

### 架构

单文件三模式：上传文件 + 选择功能（独立两步）→ 加载确认 → 结果

```
📂 上传 [A集*] [B集可选]     ← 始终可见
🎛️ 选择 [🔍分析] [📊对比] [🔄替换]  ← 始终可见，独立于上传
[🔍 加载并分析]              ← 确认按钮（文件+模式都选好才启用）
─────────────────────────────
⚙️ 设置面板（加载后出现）
📋 结果区（加载后出现）
```

### 三模式功能

| 模式 | 核心功能 |
|------|------|
| 🔍 分析诊断 | 总览卡片 + 洞察卡片 + 排名表 + CSV + 关卡号复制 + 双文件时可切数据源 |
| 📊 版本对比 | 四分类汇总（已修复/改善未修复/新问题/正常）+ 双列diff + 筛选排序搜索 + CSV |
| 🔄 替换对照 | A/B概览 + 候选匹配Top5 + 三态操作 + 重复检测 + CSV |

### 共享模块
- 评分引擎（scoreDataset）统一，权重/阈值三模式共享
- SheetJS 上传引擎（双文件拖拽）
- localStorage 持久化（权重/阈值/替换状态/模式）
- CSV 导出统一（BOM + UTF-8）

### 流程优化
- 初版流程错误：上传→加载→设置+模式 同时出现
- 修正后：上传+选模式独立 → 加载确认 → 设置面板+结果
- 加载后模式切换直接 `selectMode()` 重渲染，不重新解析文件
- 加载前模式切换 `pickMode()` 仅选中，不触发分析

### MCP search_vault 踩坑
- `search_vault` 使用精确连续子串匹配，不是分词搜索
- 多词空格分隔查询返回空 → 已记入 `workbuddy-obsidian-workflow` skill
