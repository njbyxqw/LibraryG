## 本地编辑器扩展工具包搭建

### 目的
- 创建本地专属的编辑器扩展目录，包含花色加载等定制化小功能
- 不修改游戏/编辑器核心代码，只做拓展
- 不上传 git，仅本地使用

### 实施
1. **还原 TileSelectionView.cs**：将之前直接写入的花色加载代码全部移除，恢复原始状态
2. **创建 `client/Assets/Editor/LocalExtensions/`**：
   - `LocalExtensions.asmdef` — 引用 TileMatch.Editor 程序集
   - `TileSelectionViewFlowerPatch.cs` — 通过反射访问 TileSelectionView 私有字段，实现相同的花色动态加载功能
3. **.gitignore**：新增 `client/Assets/Editor/LocalExtensions/` 和 `.meta` 的忽略规则

### 技术实现
- `[InitializeOnLoad]` + `EditorApplication.delayCall` 注册 SelectLevel 事件监听
- 反射访问 `_categoryData`、`_categoryGoDict`、`_categoryObject` 私有字段
- 反射调用 `CloseItemList`、`OnCategoryButtonClicked` 私有方法刷新 UI
- 数据源：`LevelDataManager.Instance.CurrentLevelConfig.TileTypes`

### 输出
- 生成 `本地扩展开发规范.md`（归档文档）
- 生成 `TileSelectionView_花色加载方案.md`（归档文档，实施记录版）
- 生成 `workbuddy_archives/花色加载V1.cs`（归档文档）
- 生成本地扩展目录 `client/Assets/Editor/LocalExtensions/`
  - `LocalExtensions.asmdef`
  - `TileSelectionViewFlowerPatch.cs`（花色加载反射实现）
  - `README.md`（规范速查）
- 后续定制化小功能可直接在 `LocalExtensions/` 中添加

### 踩坑记录与规范补充
1. **asmdef 引用不传递**：Unity 的 asmdef 不传递依赖，需显式声明每个用到的程序集。最终引用：`TileMatch.Editor` + `TileMatch.Config` + `BettaSDK` + `TileShared.Logic.DomainEvent`
2. **DomainEventBus 正确用法**：不在 `Betta.Framework` 而在 `Game.TileShared.Scripts.GameCore.DomainEvent`，`RegisterForEnumKey` 需 `IEnumKeyEventHandler<T>` 接口（不是裸 delegate），用嵌套类桥接
3. **config 文件损坏**：`tiletypegroupconfig.bytes` 反复损坏（与本地扩展无关），最终从 `.json~` 手写 protobuf 编码器重建
4. 以上全部补充到规范文档的第五、六节

### 规范修复与 Skill 创建
- 修复规范文档：章节编号重复（2.3 模板 → 2.4 文件命名）、DomainEventBus API 错误（`.Instance` → 静态调用）、模板 using 补充

## 关卡编辑器快捷键本地化（ShortcutBindingManager）

### 背景
- 源码 `ShortcutBindingManager.cs`（311 行）已设计完成但未集成到 client 目录
- 功能：数字键 4~7 动态绑定当前关卡的障碍牌/特效，一键选中编辑工具
- 需要改造为本地扩展，不修改源码

### 评估结论
- 所有依赖（LevelDataManager、TileType、EffectType、OptionState 等）均通过现有 asmdef 引用可访问，零新增依赖
- 3 个关键改造：命名空间 → LocalExtensions、Singleton → 静态类 + EditorApplication.update 按键轮询、关卡切换检测用引用对比
- 项目内容变更零影响：新增/删除障碍牌或特效无需任何配置调整，运行时动态从 LevelConfig 读取

### 实施
- 创建 `client/Assets/Editor/LocalExtensions/LevelEditor_ShortcutBindingPatch.cs`（约 280 行）
- 核心改造：
  - 丢掉 Singleton，改为 `EditorApplication.update` 主循环轮询 4~7 键
  - 关卡切换自动检测：`oldConfig != newConfig` 引用对比 → RefreshFromBoard
  - 输入框聚焦安全检测：`EventSystem.current.currentSelectedGameObject.GetComponent<InputField>()`
  - 双注册防护：`_isRegistered` 标记防止 domain reload 重复注册
- 保留原三步映射算法：扫描队列 → 检查保留/清空 → 填补空位
- 移除 TileChildTile/TileChildPile 类型（1~3 键由 Controller 原生处理）

### 输出
- 生成 `client/Assets/Editor/LocalExtensions/LevelEditor_ShortcutBindingPatch.cs`（本地扩展文件）

### 调试增强
- 添加完整诊断日志链，覆盖从初始化到按键触发的全链路：
  - 静态构造函数 → 确认 `EditorApplication.update` 已注册
  - `LevelDataManager.Instance` 就绪检测（含 null 告警）
  - `CurrentLevelConfig` 内容输出（LevelName / Tiles.Count / Effects.Count）
  - 关卡切换 → RefreshFromBoard 触发节点
  - 每 600 帧（≈10s）输出一次绑定状态快照（4 个槽位内容 + 关卡信息）
  - 输入框聚焦 → 日志提示快捷键禁用
  - 按键检测 → 输出按键、槽位索引、绑定内容
  - RefreshFromBoard 完成 → 输出队列长度 + 填充后非空槽位数

## 项目资料库索引建立

### 目的
- 11 份归档分析文档分散在项目根目录和 `workbuddy_archives/`，后续会话无法自动感知
- 需要一套机制让每次新会话都能知道有哪些已有资料可复用

### 决策
- **方案**：MEMORY.md 内建资料库索引表（不选 Skill，分析报告是参考资料不是工作流）
- **规则**：存档/同步/归档触发词 → 同时更新 MEMORY.md 资料库索引 + 日志标记 → 自动化同步 Notion
- **索引结构**：按标签分组（编辑器/purple、打点/red、游戏逻辑/gray、Rocket/pink），每行含文件路径 + 内容摘要

### 索引内容（11 份）
| 标签 | 文件数 | 典型文件 |
|------|--------|----------|
| 编辑器 (purple) | 4 | 关卡编辑器梳理、本地扩展规范、花色加载方案、快捷键系统 |
| 打点 (red) | 3 | 打点梳理报告、Tile打点解析、SQL参考 |
| 游戏逻辑 (gray) | 3 | 跑关机器人、障碍Tile序列、死局改进方案 |
| Rocket (pink) | 6 | 完整逻辑分析V1、V2完整逻辑、PRD、架构设计、QA报告、V2定稿 |

### 输出
- 更新 `MEMORY.md`：新增「文档存档规则 → 资料库索引联动」规则 + 「项目资料库索引」表
- 补充 Rocket 标签 `.workbuddy/reports/` 下 5 份结论性报告到索引表
