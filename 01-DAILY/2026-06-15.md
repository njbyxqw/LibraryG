# 2026年06月15日 星期日

## 关卡 QA 工具：Diff 对比改为 MD5 + Comment 剥离

> **状态**：已回退（程序已内置此功能），以下为存档记录

### 背景
之前在 LevelFileMigrationWindow 的 Diff 模式下，使用 JObject 深度解析 JSON 并逐字段比较，按 BoardSize/Tiles 等字段分级为 critical/moderate/minor。用户反馈：

1. **实际已在用 MD5 校验** — 这是现有流程，简单可靠
2. **不需要字段级分级** — 对比工具只需告诉"哪些文件变了"，人工去 Fork 审具体 diff
3. **Comment 字段应排除** — Comment 是纯标注，对游戏逻辑零影响，但 MD5 会跟着变造成误报

### 改动记录

**文件**: `LevelFileMigrationWindow.cs`

**① Diff 改为 MD5 对比**
- 删除了 `DiffFileEntry` struct 和 JSON 深解析逻辑
- `_diffModifiedFiles` 从 `List<DiffFileEntry>` 简化为 `List<string>`（只存文件名）
- `ExecuteDiffCompare()` 中同名文件用 MD5 对比替代 JSON 解析
- 结果展示去掉严重程度分级，三种状态统一用文件名网格

**② MD5 计算时剥离 Comment**
```
// ComputeMD5 内部逻辑:
// 1. 读 JSON 文本
// 2. JObject.Parse → .Remove("Comment")
// 3. ToString(Formatting.None) 重序列化
// 4. 对结果算 MD5
// 5. 解析失败时退回到原始内容
```
Comment 在内存中移除后才算哈希 → Comment 变更不会误报为"修改"。

### 方案选择记录

| 方案 | 是否采用 | 原因 |
|------|---------|------|
| JSON 结构解析 + 字段分级 | ❌ | 冗余：Fork 已做 diff 展示；关卡 JSON 格式稳定无格式差异 |
| MD5 + Comment 剥离 | ✅ | 快、准、职责对：只回答"哪个文件变了" |
