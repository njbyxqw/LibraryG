# 2026-07-15 工作日志

## 牌局生成深度分池 BUG 诊断

### 问题
用户怀疑"深度前25%不打乱"规则有问题，经代码审查确认存在 BUG。

### 根因
`AssignTileTypeByDepthStrategy.cs` 中 `InitializeTypeIndexByDepth()` 方法：
- **设计意图**：按深度排名排序所有牌，最深的 75% 进 shufflePool（Fisher-Yates 打乱），最浅的 25% 进 tailPool（不打乱）
- **实际代码**：`AssignPoolByDepthRank(0, n1, ...)` 和 `AssignPoolByDepthRank(n1, targetCount, ...)` 按 **slot 索引区间**切分，不是按深度排名切分
- slot 索引遵循 JSON tile 顺序（`randomAssignmentIndices` 按 JSON 先普通牌后序列子牌构建），与深度无关
- 导致：深牌若在 JSON 里靠后 → 落入 tailPool → 拿到不打乱花色；浅牌若靠前 → 落入 shufflePool → 拿到打乱花色

### 附加问题（6月23日 `3f6a2f31f2` 引入）
- 三池（shuffle/deterministic/sequence）改为两池（shuffle/tail）
- sequencePool 原来会被 Shuffle，合并进 tailPool 后不再 Shuffle
- tailPool 使用 `BuildSpreadPoolByCounts` 生成确定性交替排列

### 涉及文件
- `AssignTileTypeByDepthStrategy.cs` — L122-159 (InitializeTypeIndexByDepth), L155-156 (切分行), L430-448 (AssignPoolByDepthRank), L284-331 (Trap 路径同样的切分问题)
- `TileDepthComputer.cs` — L219-321 (BuildExpandedList, randomAssignmentIndices 构建顺序)

### 正确修复方向
1. 收集所有普通牌 slot [0, count1)
2. 按深度排名排序
3. 深前 n1 个 → shufflePool
4. 浅后 (count1 - n1) 个 → tailPool
5. 序列子牌单独处理（是否 Shuffle 需确认产品意图）
