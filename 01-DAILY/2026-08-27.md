# 2026-08-27 工作日志

## TileMatch

把 20_TE 专用可视化扩展成通用关卡预览工具，并持续迭代目录扫描、侧边列表布局与自然排序。

### TileV2 关卡可视化预览器（通用工具）

- 新增两个文件（均在 `local_py_script/`）：
  - `level_viz.html`：前端页面，支持下拉选择/路径输入/本地 JSON 三种加载方式，X/Y 平移滑杆（-3~+3，纯预览），原版对比（git HEAD），棋盘尺寸与层数自适应，碾压关系交互
  - `level_viz_server.py`：本地 http 服务器（默认端口 8790），提供 `/api/list`（运行时 Config/LevelConfig 9406 个 + 编辑器 Editor/Levels 13625 个）和 `/api/load?path=&base=1`（base=git HEAD 版本对比）

#### 关键踩坑

1. **git 仓库根在 `client` 上一级**：`git show HEAD:<path>` 需带 `client/` 前缀
2. **多进程绑定同一端口**：Windows 上重复启动服务器会导致旧进程仍占端口、请求被旧代码处理；重启前必须按端口杀净（`Get-NetTCPConnection -LocalPort 8790` 找 PID 后 `Stop-Process`）
3. **resolve 目录歧义**：`TE复刻/20.json` 拼到 runtime 目录时 commonpath 也能通过（路径合法但文件不存在），必须同时 `os.path.isfile` 才返回，否则永远命中第一个 root

#### 使用方式

`python local_py_script/level_viz_server.py 8790` 后访问 http://127.0.0.1:8790/

#### 复用价值

后续做关卡 QA、批量预览、对比改动（改前/改后）直接复用该工具；旧的 `gen_20te_viz.py` 保留为一次性生成脚本。

### 扩展：目录扫描功能

- 服务器新增 `/api/scan?dir=&recursive=1`：输入相对 ROOTS 路径或本地绝对路径，扫描目录下所有 .json，返回 `{dir, files:[{name,path}]}`；空路径默认扫描运行时根；支持绝对路径（`resolve` 也同步支持）；防目录穿越
- 文件按数字前缀自然排序（1.json < 2.json < 10.json）
- 前端 pathInput 旁新增"扫描目录"按钮：输入目录（如 `TE复刻`）→ 扫描结果填充到下拉"扫描结果"组 → 自动加载第一个，之后可直接下拉切换，不用每次重输路径；pathInput 支持回车加载

### 布局改版：侧边关卡列表 + 点击加载

- 关卡列表从顶部下拉移到**棋盘左侧面板**（`.filepanel`，270px），高度与棋盘区域拉伸一致（`.wrap align-items:stretch`）
- 列表结构：`运行时配置(9406)` / `编辑器关卡(13625)` 两个组头懒加载展开；editor 按顶层子目录分组（📂 子目录节点点击再展开），避免一次渲染上万 DOM；根目录平铺文件
- **去掉自动加载**：初始化不加载任何关卡，点击左侧文件项才 `loadByPath` 并高亮激活项
- 扫描结果作为独立"📂 扫描结果"组置顶并默认展开；顶部下拉 `#fileSel` 已移除

### 排序修复：统一数字自然排序

- 之前 `/api/list` 的运行时/编辑器列表是**纯字典序**（`10.json` 排在 `2.json` 前）；`_nat_key` 只认文件名开头数字
- 后端 `_nat_key(s)` 改为通用自然排序：按 `re.split(r'(\d+)', s)` 拆段，数字段比数值、字母段忽略大小写；`_file_key(f)` 按完整 `path` 排序（同 path 回退 name）
- `/api/list` 的 runtime/editor 文件列表、`/api/scan` 结果全部走 `_file_key`
- 前端 `buildGrpBody` 的子目录名排序改用 JS 自然比较器 `natCmp`（`\d+|\D+` 拆段）
- 效果：`1_TE < 2_TE < ... < 12_TE`，`TE复刻/1.json < ... < TE复刻/12.json`
