## 关卡文件追踪工具 - 分支逻辑修复 (20:50-21:00)

### 问题
- 之前用 `git branch --contains` 查的是"commit 在哪些分支"，导致一条 commit 后面跟着 3 个分支
- 用户需求：**只看在哪个分支上创建的**（merge 后的不算）

### 修复方案
- **去掉 `commit_branches` 表**（不需要记录多个分支）
- **`commits` 表加 `source_branch` 字段**（只存一个分支名）
- **`update_database()` 按 `TRACK_BRANCHES` 顺序处理**：
  - 先处理 `tile/tile_dev_level`，再处理 `dev`
  - 如果 commit 已存在，不更新 `source_branch`（保持首次出现时的分支）
- **效果**：
  - commit `abc123` 在 `tile/tile_dev_level` 上创建 → `source_branch = tile/tile_dev_level`
  - 后来 merge 到 `dev` → DB 里还是 `tile/tile_dev_level`，不更新

### 代码改动
1. `TRACK_BRANCHES = ["tile/tile_dev_level", "dev"]`
2. `update_database()` 重写：遍历分支，调用 `parse_git_log(branch, ...)`
3. `parse_git_log()` 接受 `branch` 参数（去掉 `--all`）
4. `save_commit_and_changes()` 参数从 `branches: list` 改为 `source_branch: str`
5. `query_database()` SELECT 用 `c.source_branch`
6. HTML 模板显示 `source_branch` badge

### 测试结果
- 数据库重建成功：53 条 commit
- `source_branch` 分布：`tile/tile_dev_level: 53 条`
- `dev` 分支的 9 条 commit 都是重复的（已在 `tile/tile_dev_level` 里），正确跳过
- HTML 报告生成成功：`report_final.html`

### 用户反馈
- 待确认：HTML 报告中 `source_branch` 显示是否正确
