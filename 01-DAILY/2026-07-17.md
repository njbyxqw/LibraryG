# 2026-07-17 工作日志

## 关卡难度 SQL (lv_name) 版：修复空行 / Level_ID 为空
- 文件：`02-PROJECTS/TileMatch/打点/关卡数据报表_难度指标拓展版(lv_name).sql`
- **现象**：结果出现大量空行，Level_ID 列为空，仅 Level 列（lv_name）有文件名。
- **根因**：`ta.v_event_48.lv_id` 在部分事件上为 NULL，而 lv_name 有值。上一轮用的复合键 `GROUP BY (lv_id, lv_name)` 把同一关卡拆成「lv_id 有值」和「lv_id 为空」两行 → 空行；空行因 `NULL = NULL` 不成立，最终 LEFT JOIN 的 ua 扩展列也不匹配而全空。
- **修复**：以 `lv_name` 为唯一聚合/JOIN 键，所有 CTE 的 `GROUP BY` 去掉 lv_id；`lv_id` 仅作展示列，用 `MAX(lv_id)` 取该关唯一非空值。最终 JOIN 改为 `ON ls.lv_name = ua.lv_name`。排序：默认 `ORDER BY ls.lv_name`，备选 `ORDER BY ls.lv_id`（已非空）。
- **踩坑经验（重要）**：vault 中 `ta.v_event_48` 的 `lv_id` 并非全量非空，不能拿它当唯一分组键。凡涉及 lv_id/lv_name 聚合，统一用 lv_name 作键，lv_id 用聚合函数取展示值。
- 原版 `关卡数据报表_难度指标拓展版.sql`（lv_id 序）存在同样潜在 NULL 组风险，本次未改（用户未要求）。

## 二次修复：lv_name 为 NULL 导致仍有空行
- **现象**：lv_name 唯一键修复后，仍有空行（Level 列为空 + 拓展列全空）。
- **根因**：`ta.v_event_48.lv_name` 也存在 NULL 值。GROUP BY e.lv_name 把 lv_name=NULL 的事件聚成 NULL 组 → Level 列空；NULL 组进入 user_lv_base/user_lv_agg 后，因 `NULL = NULL` 不成立，LEFT JOIN 时 ua 全空。
- **修复**：在 `base_events` WHERE 中新增 `AND e.lv_name IS NOT NULL`，过滤所有 lv_name 为空的无效事件（无文件名，无分析意义）。NULL 组彻底消除。
- 数据模型确认：lv_name 唯一、lv_name→lv_id 唯一、lv_id→lv_name 多对一（一个 lv_id 可对应多个 lv_name）。

## 三次修复：lv_id 从 lv_name 解析（不可信原始字段）
- **现象**：部分 lv_name 对应的 Level_ID 错误（如 lv_name="2" 显示 lv_id=59）。
- **根因**：`ta.v_event_48` 的 `e.lv_id` 字段不可信，与 lv_name 并非一一对应（属于埋点数据质量问题）。lv_name 本身才是可靠标识——纯数字=基础关卡，带后缀=测试关卡，数字前缀相同=同一 lv_id。
- **修复**：不再读取 `e.lv_id`，改为从 lv_name 提取数字前缀：`CAST(regexp_extract(e.lv_name, '^(\d+)', 1) AS INTEGER) AS lv_id`。下游 `MAX(lv_id)` 不变。
- **关键教训**：事件表中的 ID 字段（e.lv_id）不可作为业务 ID，优先从 lv_name（文件名）解析——lv_name 是关卡在编辑器的唯一标识，数据更可靠。

## 根因查明与四修：e.lv_id 语义（玩家序号 ≠ 关卡 ID）
- **追问**：为什么 lv_name="2" 对应 lv_id=59？
- **代码查证**（TaDataManager.cs）：
  - `lv_id` = `DataCenter.Instance.LevelCommonData.Level`（玩家的最远关卡序号，全用户生命周期递增）
  - `lv_name` = `LevelGroupInfoInGame.levelPath`（实际在玩的关卡配置文件名）
  - → 打到第 59 关的玩家重玩第 2 关时，事件携带 lv_id=59、lv_name="2"。e.lv_id 语义是"玩家序号"而非"关卡配置 ID"。
- **修正**：同步修改原版 `关卡数据报表_难度指标拓展版.sql`（lv_id 序）：
  - base_events SELECT 加上 `e.lv_name`，lv_id 改为 `CAST(regexp_extract(e.lv_name, '^(\d+)', 1) AS INTEGER) AS lv_id`
  - WHERE 加 `lv_name IS NOT NULL`
  - 该版保持 `GROUP BY lv_id`（合并同 lv_id 的不同 lv_name，如 "2"+"2_test"→lv_id=2 只一行）
- **两版对比**：lv_name 版=每文件一行（不合并）；lv_id 版=同 lv_id 合并一行（聚合测试关+基础关）。
