### LastTile 歪角度 bug — 三波排查收敛

**现象**：最后一张牌进 Bar 飞行旋转结束后角度歪（随机角度），蓄力段也歪，砸落才被 SetPositionAndRotation 硬转正（太晚）。

#### 第一波：初诊起点残留角（12:05）
根因：`PlayLastTileAddToBarAnim`（TileView.cs:555）旋转用 `RotateMode.LocalAxisAdd`（增量累加）：
- 飞行段在**当前角 θ 基础上**累加 720°（整数圈不消除 θ）
- 蓄力段 remainingAngle=0 不转
- slam 段无旋转
- → 动画结束角 = 起点角 θ
- θ 非固定来源：prefab 角度全 0、棋盘不设角度 → θ 是历史动画残留（进 Bar 动画中途被 CancelBarAnim 打断 / 其他系统旋转未恢复）→ 偶现+随机

修复方向（待用户确认）：旋转改**绝对目标 + `RotateMode.FastBeyond360`**，不依赖起点角：
- 飞行段 DORotate 到 `targetRotation.z + 360*rotationCount`；蓄力段 DORotate 到 `targetRotation.z + remainingAngle`；slam 保留兜底
- 备选（改动最小但飞行/蓄力仍歪）：slam 段加 DORotate 归正

#### 第二波：误诊 DOPath 冲突论（12:15）
⚠️ **推翻第一波"起点残留角"论**。Trea 提出：`DOLerpMoveTopDown`（`Assets/Game/TileShared/Scripts/Util/GameExtend.cs:122`）= `DOPath(..., PathType.Linear, PathMode.TopDown2D)`。`PathMode.TopDown2D` **每帧把 transform.rotation 设为路径切线角**（随牌起点位置变化 → "随机歪"来源）。

LastTile 飞行段（TileView.cs:575）并行 `DORotate(720°, LocalAxisAdd)`（TileView.cs:582-588）→ **两个 tween 每帧同写 rotation 互相覆盖**；LocalAxisAdd 的 startValue 在 tween 启动瞬间缓存，此时 DOPath 已注入切线角 → 720° 累加基于切线角 → 结束 = 切线角（歪）；最后写者定格（切线角 or 切线角+720 ≡ 切线角）→ 偶现。

对照组：普通进 Bar（520 行）同用 DOPath 但无并行 DORotate + 525 行立即修正 → 不歪；Headless 用 UnityMock（TransformDoTweenExtensions.cs:95）只动 position → 不冲突。

修复方案（用户选 A）：**飞行段去掉 DORotate（消除并行写 rotation）→ 飞行结束强制归正 `transform.rotation = Quaternion.Euler(targetRotation)` → 蓄力段 DORotate(LocalAxisAdd, 360×rotationCount) 完整转圈 → 砸落笔直**。注意 `lastTilePreRotAngle`/`lastTilePreRotLeadTime` 参数语义将废弃。

#### 中间：方案 C 兜底（12:21，用户拍板）
最终方案（用户否决 A/B 的较大改动）：**飞行段完全不动，只在蓄力段归正角度**。参数一个不改、蓄力时长保持 lastTilePowerUpDuration(0.14s)。

改动：`TileView.cs`（GameView 版）`PlayLastTileAddToBarAnim` 蓄力段 powerUpRotation：
- 原：`DORotate(remainingAngle, LocalAxisAdd, Linear)`（默认 remainingAngle=0 → 不转，歪角被保持）
- 新：`remainingAngle>0` 时 `DORotate(new Vector3(0,0, targetRotation.z+remainingAngle), FastBeyond360)`；否则 `DORotate(targetRotation, Fast)`（最短路径归正）→ 无论飞行段被 DOPath 切线角带歪多少，蓄力 0.14s 内摆正到 Bar 目标角，砸落必正。Ease 改 OutQuad。

验证建议：真机/编辑器多次跑"最后一张牌"进 Bar，观察砸落瞬间角度；重点关注路径切线角大的牌。

#### 证伪 DOPath 理论（14:24 补充 + 14:52 正式证伪）
**DOPath 每帧写切线角"理论被证伪**（DOTween 官方 XML 文档证据链）：
- `DOPath` 文档原文："Tweens a Transform's **position** through the given path waypoints"——只动 position
- 旋转朝向需显式 `.SetLookAt()`（"Additional LookAt options... Orients the target"），`DOLerpMoveTopDown`（GameExtend.cs:122-125）**未链式调用 SetLookAt** → DOPath 不写 rotation
- `PathMode.TopDown2D` 只是路径插值平面（忽略 Z 差异），与 rotation 无关
- 反证：普通进 Bar（520 行）同用 DOLerpMoveTopDown，若 DOPath 写切线角，牌飞行中会侧向翻转，美术早炸了

**真根因（回归 12:05 最初诊断）**：飞行段 `DORotate(720°, RotateMode.LocalAxisAdd)` 累加模式——从当前角 θ 累加整数圈，结束角 ≡ θ（模 360）；θ 非 0（历史残留）时歪角保留到砸落前。

θ 来源排查：MoveUp 只有 DOScale（✗ 排除）、TileView 无池化（✗）、ShiftByBar L655 归零（✗）；剩余嫌疑 AddToBoard/AddToOverBar/洗牌/撤销道具路径——**修复不依赖找齐 θ 来源，方案对 θ 免疫即可**。

教训：DOTween 行为以官方 XML 文档为准（DOPath≠旋转、DORotate=world、DOLocalRotate=local），勿凭方法名臆测；"已验证"的结论也要追问验证方法。

#### 方案 D 落地：飞行段绝对目标（14:52 提出 → 15:45 实施）
**飞行段 preRotation 改绝对目标 + FastBeyond360**：
- 原：`DORotate((0,0,preRotAngle), LocalAxisAdd)`
- 新：`DORotate((0,0,targetRotation.z + preRotAngle), FastBeyond360)`

数学保证：start=θ∈[0,360)，end=targetRotation.z+720∈[720,1080)，end>start 恒成立→**永远正方向不反转**；结束角 ≡ targetRotation.z → **精确正角，与 θ 无关**。蓄力段（方案 C 现状）起始已正，Fast 差值=0 不动 ✓ 天然满足。视觉：飞行段正方向转 1~2 圈（720-θ），与原设计"转两圈"一致。

确认 Headless 版 TileView 无 LastTile 动画逻辑（Grep 无匹配），只改 GameView 版。

**改动 1（核心）**：TileView.cs `PlayLastTileAddToBarAnim` 飞行段 preRotation（L587-591，含注释说明）

**改动 2（注释）**：蓄力段注释更新——删除已证伪的"DOPath 切线角"表述，改为"飞行段已保证结束角精确，此处保底摆正；默认配置差值 0 不动；rotationCount>2 时从正角补转剩余圈数"。蓄力段代码逻辑不动（方案 C 分支保留作兜底）。
